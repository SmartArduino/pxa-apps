# DOM 投影：候选实现与逐堆验证

当前产品仍为 P38。P57 候选只改 Guest 桥接资源中的通用 HTML 转义，没有更改网页、Host、SDK、JS 引擎、应用预算或默认缓存。它在 pai-touch 上降低了投影耗时，但 P59 有两项 SRAM 读数高于配对旧样本，**暂不合入**；不会用较低的 PSRAM 抵消 SRAM 增长。

## 改动原因

原实现用全局正则查找，再为每个匹配调用 JS 回调。密集转义会产生大量临时匹配对象，长图片地址的扫描也在解释执行路径上。候选改用五次原生字符串替换，先处理 `&`，最后处理空字符，保持原有实体及 UTF-16 语义：

```js
const escape = s => String(s).replaceAll('&', '&amp;').replaceAll('<', '&lt;')
    .replaceAll('>', '&gt;').replaceAll('"', '&quot;').replaceAll('\0', '&#xfffd;');
```

桥接字节码 16,931→16,813 B，正常 S3 包 1,443,740→1,443,618 B。正常模拟器/S3 的 UI AOT 和引擎 Wasm 均与 P38 逐字节相同；模块输入、加载及实例请求量也相同。这些不能代替物理堆测量。[构建指纹、请求量和测试范围](original-page-scripts-20261017/dom-escape-candidate.json)。

## 正确性及有界内存

同一原生 Page/引擎二进制，按旧、新、新、旧顺序测试纯文本、密集转义、中文/非 BMP 字符及稀疏转义，各 31/257/4096 字符；12 组的 JS 稳定占用和本次峰值都未增长。密集 4096 字符的 JS 峰值为 1,331,294→241,358 B，稀疏 4096 字符为 179,586→178,279 B。[全部原值](original-page-scripts-20261017/dom-escape-native-candidate.json)。

这是原生探针的 JS 堆，不是整机收益。为保留密集文本及独立旧正则参考，测试单独使用 2 MiB/2 s；应用预算没有提高。原生 ASan/UBSan/泄漏检查包含正文、属性、内联图片地址、NUL、已有实体、有效及孤立 UTF-16 代理项；签名库、812 个编译取消恢复点及数组取消恢复通过。

实际 AOT UI＋WAMR 模拟器在 296×240/160 DPI 圆角屏、480×480/240 DPI 圆屏通过完整检查，包括约 2.9/4.0 KiB JSON 中的非扫码 180×180 图片、连续 DOM 更新、图片不重复解码、GIF、超时/内存保护、导航、拖动优先和空闲。原始 HTML/四段脚本加合成 API 的两档载荷也在正常发布构建通过，不能作为真实认证证据。

## P62 分段候选：字符边界及真机 P63

仅限制每回合的节点数量仍无法限制单个长属性。P62 在现有遍历栈中表示待转义的字符串及偏移，每次处理至多 512 个 UTF-16 码元，沿用原生累积缓冲，完整快照完成后才一起提交画面与点击映射。边界遇到一对有效代理项时向前避让，避免每批转成 UTF-8 后损坏中文扩展字或表情。同步 `innerHTML/outerHTML` 保持原语义；没有默认缓存、Host/SDK 改动或预算提高。

桥接资源变为 17,490 B（相对 P38 多 559 B）；正常模拟器/S3 的 UI AOT 与引擎 Wasm仍逐字节相同。原生旧/新/新/旧的 12 组中，JS 稳定占用下降 224–656 B，各组峰值没有增长；这不是整机峰值。新增测试实际抓到了未避让代理项的早期候选错误，修正后长正文、后续属性、生成 style、半途修改取消均通过。真实 AOT UI＋Wasm 的原始四脚本/合成 API、两档载荷、小屏/高 DPI 圆屏、GIF、拖动、图片预览中的回调与延后提交通过。[构建和本地结果](original-page-scripts-20261017/dom-chunks-candidate.json)。

P63 在同一 d878 Host/字体上预先固定 8 次正常包 ABBA，每版两次软件冷启动、两次重开，全部保留。候选 4/4 完整二维码，旧版 3/4；旧版一次在 READY 后超时。旧版失败不进入完整路径的耗时/内存差值，不能成为低内存收益。候选冷启动观察 24.604/24.129 s、重开 23.489/23.381 s；旧版冷启动 25.445/24.841 s、唯一完整重开 24.039 s。输入图片字节数和系统状态会变化，不将这些少量网络时钟换算成 CPU 加速、FPS 或触摸延迟。

**P62 仍未通过本轮逐堆不增长门槛，暂不合入。** 冷启动 SRAM 稳定最大值多 32 B；最后旧块在应用启动前的 SRAM 已少占 2,412 B，不能确定来源，也不通过减去基线来强行通过验收。原值和相对启动前增量都保留。受控资源快照的当前图片/音频/元数据占用相同，但这不证明整机或全部 Guest 内存相同。可用 WAMR 日志仍不足以证明完整会话线性峰值；代码映射与帧缓冲不能用请求量或历史计数冒充本轮峰值。

另一次独立诊断不混入正常包内存门槛：部分长属性片段约 10 ms，但全部投影的最大观测仍为 79,394 µs；不能宣称所有投影都小于 50 ms。原始脚本编译仍有约 1.4 s 回合。额外阶段内存查询显示，该诊断的 SRAM 窗口峰值在初始化结束时已经出现，因此不能把那一回峰值直接归因于稍后的内联 PNG 临时文件；查询本身会扰动运行，也不能据此给正常包归因。

[全部 8 次正常记录、独立诊断、资源口径及精确恢复](original-page-scripts-20261017/device-dom-chunks-candidate.json)。29 个安装文件与最新 3 个私有文件集合及 SHA 均恢复原字节，Host/字体/其他应用/真实会话未改，浏览器恢复原有归档状态。真实用户扫码、书架和阅读仍待验证。

本地后续 P65 进一步区分节点与字符串片段的工作权重：解释执行时每回合最多处理一个 DOM 节点或两个字符串片段，保留同步序列化原有上限和语义。原生 ASan/UBSan 的正文/属性/样式/代理项/取消检查及 12 组 JS 堆检查通过；原始四脚本加约 4 KiB 合成响应也通过。该桌面诊断有 168 个投影片段，最大观察 1,021 µs；不能把它换算成真机时间。P65 尚未真机验证，仍是隔离候选，没有合入或提高任何预算。

补充的正常构建协议检查使用原始四脚本和虚构凭据，验证登录 POST 字段、`Secure; HttpOnly` 响应 Cookie、书架请求携带 Cookie，以及脚本写入的指纹 Cookie。全部通过，只能说明合成协议链路正确；不能代替真实扫码或证明真实书架、正文可读。
