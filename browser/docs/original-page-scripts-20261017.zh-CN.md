# 原始页面脚本执行与回归（2026-10-17）

后续 P26 的签名源码匹配资源已让真机显示原始页面二维码；真实登录仍未验收，长回合仍待优化，见 [后续测量](signed-script-libraries-20261017.zh-CN.md)。下文 P20 表格和失败记录保留为阶段基线。

本轮保留网站原始 HTML、脚本和链接，只改浏览器 Guest。界面仍为 AOT，脚本仍按需加载为 Wasm 解释组件；没有增加 Host JS 接口，也没有重新引入微信读书或漫画的替换页面。原始微信读书登录页及四个脚本通过模拟器的**合成协议回归**，真实账号登录、书架与阅读仍须单独验收，不能用独立微信读书应用的结果代替。

## 实现与取舍

| 改动及原因 | 收益 | 内存与限制 |
| --- | --- | --- |
| 编译、执行分为相邻的空闲回合；旧代码将二者合在一个回合 | 执行前释放网络源码和 NUL 副本；执行、事件处理继续使用 50 ms 预算 | 复用初始化 factory 的 JS 根，复用响应队列的元数据，无新增缓存/队列；节约运行峰值尚未量化 |
| 大 VM 的冷门 opcode 分为独立内核 | 保留帧由 1184 B 降至 632 B，为正常页面调用留下空间 | 桌面 FAST 的单帧数据，不等于整栈峰值；准备后的模块占用有所增加，见下表 |
| 解析器拆分保留工作；括号前瞻只处理可能的箭头参数，数字前瞻只验证语法 | 不再反复转换随后丢弃的 Number/BigInt；避免无关分支占用递归栈 | 保留数字、分隔符、后缀与箭头语法；有界解析和 VM 调用仍会拒绝过深程序 |
| 字节码、原生回调、访问器、构造器、转发及 eval 按保留工作计费 | 字节码上限由早期保守版本的 6 层提高到 12 层；混合重入在耗尽操作数栈前返回 JS 错误 | 计数放在原有结构填充中；16 KiB 操作数栈、48 KiB 线性 C 栈不扩大 |
| DOM 属性使用共享描述符，固定属性 getter 直接读取属性表 | 减少多余 JS 包装调用，原始页面状态更新不再因这些包装耗尽调用预算 | 签名桥接字节码 16,960 → 16,931 B；不增加默认缓存 |
| 普通稀疏数组只复制可能存在索引的范围 | 跳过长串空洞；十万元素 splice 的模拟器交替对照降到毫秒时钟分辨率附近 | 不分配缓存；索引访问器、原型索引、Proxy、非数组及越界范围保留原路径和可观察操作 |
| 注册标准 Proxy，并保护十一种属性/原型回调入口 | 缺失 API 不再被误当成递归保护；递归或透明原型循环返回 JS 错误并恢复 | 复用原深度计数，不扩大栈；新增代码/模块请求量见下表 |
| 编译在词法读取和各处理阶段前检查取消 | 到期后主动退栈并释放部分编译结果；前瞻解析不能吞掉一次性取消 | 复用现有中断计数及递归保护字段；本项正常 Wasm +264 B，输入＋实例请求量 +1,469 B |

编译使用独立的 2 s 期限：词法读取约每 157 个 token 检查一次，在变量解析、标签优化和栈分析前检查，并保留完成后检查；不延长执行/事件回调预算。当前解析器不是增量编译器，单次字符/数字转换、正则编译和正在进行的优化阶段仍同步完成；源码容量、语法深度和堆预算仍分别受限。这不能被描述为严格的 2 s 抢占式保证。

执行/事件的 50 ms 也只是中断回调的目标期限，并非严格上界。优化稀疏数组前的私有探针在同一固定模拟器中分开测得：25,442 B 兼容脚本的解析约 402 ms、字节码生成约 187 ms、执行约 823 ms；脚本在这段执行中没有及时再次检查中断期限。其他四段程序的执行均小于 3 ms。这是共享工作站负载下的一次带日志测量，包含调度与探针开销，不能当作 CPU 时间、设备数据或前后性能对比。[阶段原值](original-page-scripts-20261017/phase-probe.json)保留这些口径。原始 HTML/四个外部脚本未改，API、二维码和登录终点仍是合成 fixture。

也按 [Binaryen 的 Guest 内部控制方式](https://github.com/WebAssembly/binaryen/blob/main/src/passes/Asyncify.cpp)验证了暂停/恢复编译的可能性：最小 C 原型可分 28 次调用完成相同递归运算，但完整 QuickJS 的 Asyncify 原型没有通过现有 16 KiB WAMR 操作数栈，并显著增加模块请求量，因此**没有合入或部署**。同一独立探针剔除调试自定义段后，文件由 525,271 B 增至 930,848 B，加载模块请求由 1,591,801 B 增至 4,347,955 B；两者的 C/保存栈合计预算均为 48 KiB。这是引擎探针，不是完整浏览器的内存或 FPS 对比；它也仍有长阶段，不能视为流畅性解决方案。

## 稀疏数组与 Proxy 后续修复

函数剖析进一步定位到兼容库中的 `Array(100000)`＋单个索引＋`splice(1,1)`：旧实现对接近十万个空洞重复执行属性查询、删除和释放。新路径先证明自身为普通数组、索引均为数据属性、普通原型链没有索引或 exotic 行为，再缩短不会发生可观察操作的空洞范围；仍通过原有 Set/Delete 路径处理保留部分。命名 getter、索引 getter、继承索引、Proxy、不可扩展/不可配置、重叠方向和 uint32 边界均有语义回归。原型深度 32 只是优化退出阈值，超出后走原路径，不限制 JS 原型深度。通用循环每 128 项、密集循环每 256 项主动检查取消，不能由此推导其他原生函数也已限时。

同一 UI AOT、五组交替新实例、结果校验的最终 P20 模拟器对照：旧版 936 / 924 / 1046 / 889 / 1014 ms，新版 0 / 1 / 1 / 1 / 1 ms。`0` 表示低于 `Date.now` 的 1 ms 分辨率。较早低负载的 P18 对照是旧版 107–142 ms、新版 0–1 ms；两组不是同一负载，不合并计算倍数。它们是共享工作站中的用例墙钟，**不是设备 FPS、输入延迟或整站加速比**，见[原始样本](original-page-scripts-20261017/sparse-benchmark.json)。

本次也发现旧 60 项矩阵中的四项 Proxy 测试存在误判：Page 未注册 Proxy，ReferenceError 也满足「出现一个错误」。现已注册标准 Proxy，递归用例须明确捕获 InternalError/stack overflow，Proxy 用例还须证明回调实际多次进入；间接 eval 保持全局作用域。十一种属性/原型回调保护、透明原型循环、正常/撤销/不变量及数组 getter 重入均通过。旧结果不能视为有效的 Proxy 覆盖。

`JSRuntime` 在锁定的 Wasm32 构建中仍为 768 B，`Page::Impl` 仍为 520 B。源码缓冲提前释放属于生命周期改进，不能仅凭这一点宣称整机稳定内存或运行峰值下降。

## 真机没有通过原站登录验收

最新 P20 保持 2 s 编译期限，在 pai-touch 的已验证 PNG Host `d8789493…` 上复测：JS 初始化总计 774,785 µs，最大初始化步 253,175 µs，随后仍返回「脚本编译超时」，没有 Guest trap。唯一完成图片是站点静态 logo，不能当作二维码证据。约 4.708 s 手势窗口记录 15 个 present 间隔，页面编译已经失败，不能作为滚动通过或帧率优化结论。记录见 [P20 真机结果](original-page-scripts-20261017/device-p20.json)。该 Host 不同于以下历史长时限实验，不能直接据两者比较内存或性能。

以下为此前 P16 的长时限诊断历史：

pai-touch（MAC a4:cb:8f:d5:d4:f0；Host `host-tools-v0.1.0-25-g75673a9-d`）保持原固件、字体和 Wi-Fi。本轮正常包首次打开原始页面时返回「脚本编译超时」。解释执行专用的 12 s 编译期限候选随后跑完原始登录脚本，报告 `errors=0`，下载了 180×180 的真实二维码图片，但也出现系统 **「应用无响应」** 提示，因此不能视为兼容性或流畅性通过。没有进行扫码或账号登录。

这次长时限候选：从点击入口至采样结束约 44.2 s（含真实网络和约 4.11 s 的手势窗口）；页面报告最长回合 **16.29 s**。该统计包括整个调度回合，不能称为单次编译 CPU 时间；12 s 检查只覆盖编译函数内的完成后检查，更不能承诺整个回合不超过 12 s。手势窗口仅记录到 11 个 present 间隔且出现 ANR，不将此计为滚动性能通过。

源码已撤回长时限，保留 2 s 期限并增加上述取消检查；P20 的设备复测已如上记录：取消能够结束编译，但原站仍编译超时。**当前原始微信读书页面仍不能作为真机可用功能交付。** 后续须继续解决长工作不能及时交还执行权的问题；继续增加期限不是解决方案。[原始设备测量](original-page-scripts-20261017/device-long-turn.json) 保留窗口、稳态和历史口径，峰值不能跨不同工作负载与旧版直接比较。

![长回合触发系统无响应，候选没有通过验收](original-page-scripts-20261017/device-anr.png)

借用前设备上没有安装浏览器。为测试临时归档的商店与小说阅读器均从精确签名快照恢复，全部原安装文件及原私有文件 SHA 逐项一致，包括独立微信读书的真实会话。浏览器测试代码恢复为归档状态；没有清除用户数据。MEMORY/PERF 停止清理，系统文件锁恢复，无应用运行，设备已释放。

## 已验证与边界

- 固定 Host 二进制 `eee492d3cacb13853a8db6c4256758f579c514f948864b8ca1526effac61e720`，真实 AOT UI＋Wasm 解释组件的 [88 项矩阵](original-page-scripts-20261017/matrix.json)全部通过。每项新进程，解析异常用例须返回普通 JS 错误；递归回调须捕获明确的栈溢出错误，下一段脚本的独立网络回执确认恢复；不能只检查 READY 或 native 测试。
- 正式候选的 ASan/UBSan、WASI 深度模型及解释分派回归通过，涵盖动态脚本先于 parser 脚本完成、最后一个 inline 脚本恰好位于 EOF、编译过期不执行。锁定上游 `test_language.js`、`test_closure.js`、`test_loop.js` 的普通 native 引擎检查通过，不将其当作 Wasm 栈证明。
- 七类源码的全部 406 个检查位置，各用持续取消、一次性取消测试，共 **812 次取消/恢复**，通过原生 ASan/UBSan/泄漏检查和独立 WAMR 16 KiB 操作数栈检查。涵盖括号、箭头前瞻、解构、多函数、switch、捕获变量、部分完成的闭包和 direct eval；每次取消后，同一引擎继续计算 `1+2`。它是 C API 回归，不代替完整浏览器或设备时延证明。测试源码见 `tests/compile_interrupt_test.c`，已接入 `tests/test_script.sh`。
- 三条原生数组复制取消/同引擎恢复用例通过 ASan/UBSan/泄漏检查和独立 16 KiB WAMR；覆盖密集向前、密集向后与普通 array-like 对象的同步循环，源码 `tests/array_interrupt_test.c` 已接入测试脚本。
- 综合浏览器检查通过：DOM/事件、异步网络、脚本失败恢复、超时与堆上限、图片/GIF、重复图片不重载、拖动期间不提交脚本重绘、空闲不重绘。
- 未改动的官方登录 HTML 和四个 JS，配合明确标记的合成 API、不可扫描的棋盘格图片及终点书架 fixture，完成 getuid → 图片 → 轮询 → weblogin → 跳转。网站内部 `/clog` 也无脚本异常。此结果**不是实际扫码、认证或阅读成功**，见 [协议结果](original-page-scripts-20261017/original-protocol-fixture.json)。不分发站点私有脚本或真实凭据；后续收录的 MIT es5-shim 源码与许可证见上述签名库报告。

中间候选曾出现混合运算符、构造器/箭头混合解析、getter＋eval 的 Guest trap；现均加入永久回归并通过。单类递归通过不能代替混合场景验证。仍不宣称任意网页/未来工具链均无栈问题，也不依据脚本提交速度宣称显示 FPS 或输入延迟提高。

复现使用 `tests/test_script.sh`、`tests/parser_smoke.py --runtime` 和 `tests/script_smoke.py`，参数及前置 fixture 启动见各自 `--help` 与[前阶段报告](script-scheduling-20261017.zh-CN.md)。`tests/language_cases.js` 包含数字前瞻及箭头参数语义用例。变更引擎时先运行 `tools/compile_runtime.sh`，再校验 `runtime/compiled.sha256`，防止签名桥接字节码与源码不一致。
