# Pixel Dungeon C++ 真机验收（2026-10-10）

pai-touch 的同场景实际显示帧率与 C 版持平，稳定内存与本轮最大峰值更低。没有删减音轨、地图或画质来获得这个结果。普通发布包保持 O3、按时间生成地图；固定种子只在显式启用 `PD_BENCHMARK_SEED` 的测试包中生效。

## 固定工作负载

同一固件、同一次开机、296×240、160 DPI、圆角 58、安全边距 8/10/8/10、内部目标 296×240、中文、战士、第一层，种子 `0x51ed270b`。两版各重新启动三次，每次重新建立测试存档，从标题→空槽→职业进入新游戏；标题和游戏分别预热 5 秒。4 秒采集期间，每 240 ms 注入一次搜索，共 12 次，按下保持 80 ms 后松开。原版地区音乐全程启用。

使用明确分开的按下/松开跨过实际触控采样周期。最初的快捷 TAP 重放出现过少执行一次搜索；这些只有 22 回合的失败运行被排除，未用于比较收益。搜索位置按真实安全边距布局计算，在按钮内部；没有通过改变核心操作或增加搜索次数补齐存档。

采集完成后通过返回/后台操作触发保存，读取真实私有 KV 文件，校验 CRC、世代、地图种子、楼层、职业与回合。六个运行全部为 **24 回合**，最终存档 SHA-256 均为 `b04fa0e8a0e925ea55cabfc7c0e4b9a6d2734bad9610ed613a5c579876a7354c`。这与本次桌面“加载既有存档”场景的进入方式不同，不能把桌面和设备数字拼接成一个对比。

原始汇总：[C](device-C-gameplay.json)、[C++](device-CPP-gameplay.json)。截图：[C](screenshots/device-C-gameplay.jpg)、[C++](screenshots/device-CPP-gameplay.jpg)。两版采集命令范围均为 3,072–3,968 B、像素覆盖均为 101,059–102,385，场景没有降档。探针未溢出。

## 实际显示性能

| 三轮中位数 | C | C++ |
|---|---:|---:|
| 实际显示 FPS | 18.77 | 18.80 |
| 每轮整帧 Host 光栅平均 | 29.079 ms | 28.855 ms |

两版 FPS 范围分别为 18.59–19.08 和 18.23–18.83，波动明显大于中位数差值。因此结论是 **持平**，未证明显著加速。呈现间隔完整保留在 JSON 中，按设备实际显示通知计算，未用提交 FPS 代替。

原生比较已验证命令和像素等价；桌面 AOT 则单独记录 Guest/Host/LVGL CPU 与输入 CPU。本次真机探针测的是 Host 光栅和显示间隔，不具备逐函数 Guest 时间，不能把帧间隔减去光栅就当成 Guest 时间，排队、音频与调度也在其中。

## 内存

每次启动前与预热结束后分别重置 ESP-IDF 最低剩余堆计数，记录本轮启动/初始化与稳态窗口真实峰值。下表整机数包括 OS、音频、游戏与采样探针；稳定值为三轮中位数，峰值为三轮中的最大值。

| 整机计量 | C | C++ |
|---|---:|---:|
| 稳定 SRAM | 286,876 B | 286,788 B |
| 稳定 PSRAM | 3,909,440 B | 3,318,720 B |
| 从本轮空闲状态增加的稳定 PSRAM | 2,489,324 B | 1,897,004 B |
| 初始化最大 SRAM | 295,628 B | 295,540 B |
| 初始化最大 PSRAM | 4,259,068 B | 3,640,860 B |
| 稳态最大 SRAM | 291,272 B | 291,184 B |
| 稳态最大 PSRAM | 3,914,848 B | 3,324,100 B |

整机稳定 PSRAM 减少 590,720 B（约 577 KiB），初始化最大值减少 618,208 B。两批空闲 PSRAM 基线相差约 1.6 KiB，远小于运行内存差值；原始数据同时保留绝对值和相对值。

| 分项稳定值 | C | C++ |
|---|---:|---:|
| Guest 线性内存 | 663,552 B | 262,144 B |
| WAMR 动态分配 | 423,477 B | 48,543 B |
| WAMR 本实例峰值 | 424,872 B | 66,317 B |
| ESP AOT 映射 | 327,680 B | 655,360 B |
| Host 外部资源预算 | 479,185 B | 476,743 B |
| 三帧缓冲 | 426,240 B | 426,240 B |
| 深度缓冲 | 142,080 B | 0 B |
| 命令队列 | 147,456 B | 147,456 B |
| 采样探针 | 2,112 B | 2,112 B |

AOT 映射增加已计入整机内存，不以 Guest 减少掩盖代码占用。Asset 缓存与音效缓存包含在资源预算内，不重复相加。资源预算的历史 peak、历史 allocation_failures 和 surface 的累计 peak 在 JSON 中仍会出现：它们不是此次 C++ 启动峰值。此处使用逐窗口重置的堆计量；例如 C++ 的历史 surface peak 继承了之前 C 版的深度分配，实际活动 surface 的深度为 0。

退出后线性内存、帧缓冲、深度、队列和探针均释放。游戏热路径仍用固定容量绘制、对象和存档暂存，未增加大型默认缓存。

音效与六首音乐保留原版资源哈希和调度规则。设备游戏基准期间启用真实音乐；没有做定量听感或声音延迟测量。esp-mosaico 的真机安装尚未验收，305 DPI 的模拟器交互验证已经通过。设备空间紧张时按授权轮换测试包，保留阅读器，不擦除分区或改变分区表。

## 复现

在 workspace 根目录运行。`--pixel-search` 会清空指定测试应用的私有数据，不能直接用于有个人存档的安装。

```sh
python3 local/pxa-apps/common/cpp/tests/reference/prepare_pixel_device.py local/pxa-apps local/cpp-game-ports-20261010/pixel-device-reference-source
PXA_APP_DEFINES=PD_BENCHMARK_SEED=1374496523 bash tools/app.sh build pixel-dungeon --target esp32s3 --aot-only --source-root local/cpp-game-ports-20261010/pixel-device-reference-source --output local/cpp-game-ports-20261010/pixel-c-device-fixed
PXA_APP_DEFINES=PD_BENCHMARK_SEED=1374496523 bash tools/app.sh build pixel-dungeon-cpp --target esp32s3 --aot-only --source-root local/pxa-apps --output local/cpp-game-ports-20261010/pixel-cpp-device-fixed
python3 tools/measure-device-voxel.py --port /dev/ttyACM0 --app pxa-pixel-dungeon-cpp --output local/cpp-game-ports-20261010/device-pixel-CPP-pointer --warmup 5 --seconds 4 --repeat 3 --local-heap --wake-home --pixel-search --package local/cpp-game-ports-20261010/pixel-cpp-device-fixed/pxa-pixel-dungeon-cpp.pxa
bash tools/app.sh build pixel-dungeon-cpp --target esp32s3 --aot-only --source-root local/pxa-apps --output local/cpp-game-ports-20261010/pixel-device-final
python3 local/pxa-apps/common/cpp/tests/reference/device_pixel_lifecycle.py --port /dev/ttyACM0 --output local/cpp-game-ports-20261010/device-pixel-normal-lifecycle
```

分别安装对应的完整签名包，音频授权后先退出再进入正式采样。两版须使用同一固件并保持同一显示配置；普通包不定义测试种子宏。C 参考源目录只用于构建隔离的诊断拷贝，本仓库原 C 游戏没有改动。
