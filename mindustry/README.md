# Mindustry · PXA

非官方 PXA 独立应用，用 C++ 从零实现基础工厂与波次塔防，复用 Mindustry v154 原版贴图、界面图标、应用图标、17 组音效及完整的 16 首音乐。应用及 Mindustry 素材按 GPL-3.0 分发，字体保留其 OFL-1.1；保留上游声明。通过 PXA Guest 接口运行，无 Java、Arc 或对系统、固件的修改。

## 运行与操作

在固件工作区根目录构建：

```sh
tools/app.sh build mindustry --source-root local/pxa-apps --target simulator --aot-only
```

商城发布按架构分别构建，每个安装包只包含该架构的 AOT。以下命令在固件工作区运行，输出目录使用本次发布的本地产物目录：

```sh
release_dir="local/artifacts/mindustry/$(date +%Y%m%d-%H%M%S)/release"
for target in esp32s3 esp32s31 esp32p4 simulator; do
  tools/app.sh build mindustry --source-root local/pxa-apps \
    --target "$target" --aot-only --output "$release_dir/$target"
done
```

`store/cover.png` 是像素工业风的商城宣传插画，沿用原版素材的 GPL-3.0 许可；商城截图单独使用真实 PXA 模拟器原始画面。

在真实模拟器中运行构建后的签名展开目录：

```sh
tools/simulator.sh product --profile pai-touch \
  --package local/app-output/pai-touch/pxa-mindustry \
  --publisher-key deps/pxa-system/apps/pxa/.dev-signing/publisher-public.der
```

触屏操作：常驻界面只保留顶部暂停、波次与资源摘要，以及底部“建造、核心、地图、工具”。点“建造”展开七个分类；选中建筑后列表自动收起，底栏变为更换建筑、旋转、确认和取消。点地图预览后点勾确认；传送带、导管或铜墙可拖动预览直线，再确认整条计划，占地、计划队列和建筑槽位整体检查；缺料也可排队。建筑成本显示在操作栏上方。

0.4 支持在地图上双指张开放大、合拢缩小，范围为 50%–250%（每格 8–40 像素）。缩放围绕两指中点，两指一起移动可平移地图；抬起一指后，剩余手指可继续平移，全部松开后恢复普通点击。建造模式也可双指移动地图，单指仍用于拖动铺线。手势开始会取消未确认的铺线预览，保留建筑类型；Alpha 在游戏更新中持续跟随视角中心；释放手指后保留选中的建筑类型。触点落在界面按钮或展开的面板时，按界面操作处理。单点设备可用工具面板的缩放按钮。

长按已有建筑约半秒，可选择同类型与朝向，随后选址、确认建造。选中或预览双管炮、电弧、修复器、电力节点时显示范围轮廓；节点同时保留供电连线。拖动铺线时，成本栏显示整条数量和总成本，材料不足标红。

拖动地图平移，点“核心”回基地。“地图”按需展开小地图，点击目标即跳转并收起；建造或查看建筑时，右侧也提供地图入口。工具面板包含科技研究、部队指挥、缩放、拆除模式和声音。点顶部资源摘要查看全部库存、电力和单位数，点面板外收起。左上暂停，右上系统菜单退出。平移视角或点小地图后，Alpha 自动跟随视角；点范围内的可采矿石开始持续采集，再点同矿点或空地停止；选中建筑后才显示供料、拆除和取消，水量或工厂进度显示在上方。按钮布局避开 Host 提供的安全边距。

手柄方向键平移，A 选择/预览/建造，B 取消，X 旋转，Y 开波，L/R 切分类，START 打开系统暂停菜单。

起始钻头已连接核心。建设第二条钻头—传送带生产线、分路向炮塔运送铜弹；核心必须实际收到材料才能支付建造。科技研究消耗库存，石墨用于解锁冶炼与电弧。冶炼厂需要煤、沙和电；发电机需要煤，电力节点连接网络。“部队”面板可切换守卫、集结与进攻；选择集结后点击地图设定目标。建筑与战斗状态每五秒自动保存，返回主菜单或正常退出时提交最新存档。

## 生产链

0.10 的传送带使用原版五种连接贴图和每种四帧动画，按相邻传送带的输出方向及相邻机器选择直线、转弯和汇入，镜像规则与原版 Autotiler 相同；建造预览及队列也使用相同连接选择。所有建筑阴影先绘制，再绘制主体，运输物品放在主体之上，避免建造顺序改变时阴影切断竖向或反向传送带。图集仍为 256×256，钻头原始图层保留在源码，运行时只上传预合成帧。传送带动画按原版 speed=0.03 的节奏同步，堵塞约半秒后停止。

移动端操作按 v154 MobileInput 的视角吸引方式：Alpha 飞向视角中心，接近到 15 世界单位（1.875 格）内停下；最大平移速度恢复为每原版帧 3 世界单位。暂停时停止移动，读取存档后从机器人所在位置查看世界。普通生存模式必须由 Alpha 在 220 世界单位（27.5 格）的范围内施工，按建材和原版 buildSpeed=0.5 逐步推进、扣料，未完工设施不运行；采矿或实际施工期间停止自动开火。主菜单“沙盒”保留原版全局无限资源规则：不扣建材、不限建造距离且可瞬间完工，不把这些规则带入普通生存。

0.9 的 Alpha 自动射击选择射程内最近的单个敌人，双枪交替射击，单发 11 伤害、合计每 17 帧一发（各侧实际装填 34 帧），使用原版 150 世界单位（18.75 格）的弹道射程。20 Hz 逻辑按原版帧数累计，保留平均装填速度；仍按本应用现有方式即时结算伤害。

音乐使用 v154 原版曲目：菜单循环 `menu`；平静曲目 `game1/game3/game6/game8/game9/fine`，紧张曲目 `game2/game5/game7/game4`。核心血量不足 85% 时，下一首从紧张曲目选择。默认“音乐：原版”采用间歇播放：每三分钟以 80% 概率选择一首，波次开始 8–15 秒后以 46% 概率尝试播放，已有曲目不会被波次打断。设置中可切换“连续”（对应原版 alwaysmusic）或关闭，音效开关独立保存；菜单与游戏之间按两秒淡出切换，进入后台暂停、回到前台续播。boss、land、launch、editor 曲目随包保留，等待对应玩法接入。

音效区分按钮、波次、完成建造、完成拆除、单位产出、研究、修复、Alpha、电弧和其他枪械。Alpha 实际施工/采矿时播放对应循环，钻头、冶炼厂和工厂实际工作时播放机器声；六个 Host 音效通道中使用五个通道，机器环境声优先播放视野附近较响的一组。相同近距离事件合并，波次与爆炸不会被密集射击覆盖。音效转为 16 kHz 单声道 PCM；原曲在打包前转成 16 kHz 单声道 Vorbis（quality 5），匹配 PXA 输出格式，避免设备实时解码 44.1 kHz 双声道后再次重采样；Host 仍流式解码，不整体读入 Guest 内存，也不再发送空白 PCM 块。未经修改的原始音乐保存在源码的 `audio-source/music/`，原始文件和转换结果的 SHA-256 记录在 `audio-upstream.json`，可运行 `python3 local/pxa-apps/mindustry/tools/import_audio.py` 重新获取及转换。设备输出仍受 PXA 单声道混音、通道数和硬件扬声器影响。

0.8 将 Alpha 采矿改为持续作业：点击铜、铅或沙开始采集，再点同一矿点或空地停止；先将视角移向远矿点，等 Alpha 进入 8.75 格采矿范围后点击采集。Alpha 按原版 mineTier=1，不能手采煤和钛。每秒按三次 60 Hz 子步合并到 20 Hz 逻辑中，采矿速度 6.5，计入矿物硬度：铜/铅稳定每秒 6 个，沙每秒 7.5 个。反复点击不再直接增加物资，Alpha 实际施工期间暂停采矿。

距离核心中心 27.5 格以内时，采得物料直接入库；核心已满或距离更远时进入 Alpha 的单一物品背包，上限 30 个，满载或装有其他物品时停止采集。机体旁显示物品与数量，采矿时显示光束和矿格轮廓。查看核心后点“存入”可存放背包；查看建筑后点“交付”优先交出携带物品。空背包时保留就近核心的“供料”快捷操作，但机器人必须同时处于核心和目标建筑的转交范围内；这一快捷操作仍是触控便利功能，并非完整原版背包交互界面。

地面单位共享寻路场，在目标格或建筑通行关系改变时更新；只有飞行单位时跳过地面搜索。敌方到核心的地形寻路场在有敌人且需要更新时构建，空闲期不再固定反复搜索。寻路缓存和诊断计数不写入存档，载入后按需重建。

0.7 修正加工与供电：石墨压缩机、硅冶炼厂和窑炉按完整加工周期产出，在完成时扣除配方原料；缺料、产物库存满或断电时保留进度。冶炼厂、窑炉、石墨压缩机的每项原料分别可存 10 个，避免某种原料占满后另一种无法进入；陆军工厂分别可存 20 铅、20 硅，空军工厂可存 30 硅。石墨周期 1.5 秒、硅周期 2/3 秒、玻璃周期 0.5 秒；以原版 60 Hz 帧的 Q4 定点累计，保留不足一周期的工作量和供电小数，避免把硅固定舍入成 0.7 秒。

电力不足时按网络供给/需求比例降低生产效率，电池先补差额；缺料或产物已满的加工设备不计用电负载。电池以 0.1 电力单位保存能量，避免小缺口被每步向上取整，多块电池按存量或剩余容量比例分担放电/充电。电网按建筑实际占地边缘接触，普通用电设备不能互相充当导线；节点沿用范围自动连接。连接拓扑仅在建筑结构变化时重算，稳定帧只更新发电、负载、蓄电和供电比例。查看加工厂可见加工进度、供电百分比，以及缺料、产物已满、供电不足或等待出兵状态。

0.6 的玩家建造操作提交给 Alpha，不再直接生成成品。Alpha 默认可在 27.5 格范围内按队列建造，速度为原版 0.5；施工时间由建材数量 × 物品成本及传送带/路由器/交叉器的原版倍率计算，模拟每 50 ms 合并三次原版帧的工作量。材料从核心逐步扣除，缺料暂停，并尝试其他可执行计划。未完工建筑不生产、不发电、不运输；施工显示轮廓、进度和机器人光束。超出范围时移动 Alpha 靠近后继续，查看工地可看到缺料、距离或排队状态。最多 48 项待执行计划，连续铺设也是逐项施工。

拆除同样进入 Alpha 队列，逐步完成并返还约一半建材（完整建筑按原版四舍五入）；未开工的计划可直接取消，已开工的计划进入拆除。开始拆除后设备停机，库存物品和液体不回收。沙盒沿用原版无限资源规则：不扣材料、不受建造距离限制，机器人处理计划时迅速完成。初始化基地和测试夹具使用底层直接生成接口；普通玩家输入全部走建造队列。

0.5 的机械/气动钻头按 v154 的底座、各自转子、顶盖组合完整图标；八个转动阶段在构建时合成，运行时每个钻头只绘制一张主体精灵，仍用 256×256 图集。选矿按非沙矿物优先、覆盖数量、原版物品 ID 决定；开采时间计入硬度，基础 600/400 帧加硬度 × 50，使用原版 60 Hz 帧单位换算到 20 Hz 模拟。预热渐变到 1.0/供水时 1.6，供水稳定产量约为 2.56 倍；总库存达到 10 后停止开采和耗水，转子随预热停转。点击钻头可看实际矿种、当前产速和水量。远景隐藏非选中建筑的水量和加工进度细条；铺线预览时也收起无关加工进度，避免高密度场景挤满绘制命令。

- 基础：铜/铅/煤/沙 → 钻头与传送带 → 核心、双管炮、石墨。
- 玻璃：窑炉消耗 1 铅 + 1 沙，在供电时每 0.5 秒产出 1 玻璃；机械泵和导管使用玻璃，储液罐还需要钛。
- 供水：机械泵仅可放在水面，7 单位水/秒。定向导管、液体路由器和储液罐把水送到钻头。机械钻头每秒消耗 3 单位水、气动钻头每秒消耗 3.5 单位水，加速约 2.56 倍；堵料时停止耗水。水量、背压和管道方向实际参与计算。
- 钛：气动钻头可以开采钛，机械钻头及 Alpha 手采无法开采钛，Alpha 也不能手采煤。新地图在基地西北方向提供钛矿，基地西侧提供小水塘。
- 军工：陆军工厂每 15 秒消耗 10 铅 + 10 硅制造尖刀；空军工厂每 15 秒消耗 15 硅制造星辉。每座工厂消耗 72 电力/秒，单台火力发电机的 60 电力/秒可让一座工厂以约 83% 速度运转，完整周期约 18 秒；足额供电时为 15 秒。
- 部队：最多 8 个友方单位。地面部队绕开水面、岩壁和实体建筑，飞行单位越障；尖刀自动射击，星辉发射三连发。敌人也会攻击友军。达到上限、无材料、无电或工厂出口堵塞时，不会凭空扣料出兵。

科技页分页显示成本和解锁状态；新增科技有前置要求。占领区域和已研究科技会保留到下一次部署。声音开关随游戏存档保存。

0.7 同时恢复单位的原版世界比例：Alpha、尖刀、爬虫、星辉的原始贴图均为 48×48 像素，一格按原版 32×32 贴图像素换算，机体画布占 1.5×1.5 格；Alpha 的原版碰撞尺寸仍是 8 世界单位，即一格，不能拿碰撞框代替贴图大小。单位图集缩图分辨率提高到 24×24，保留原始透明边距和长宽比例，地图缩放时按同一比例绘制。血条放在机体画布上方。

## 当前内容和边界

22 种建筑、8 种物品、48×48 程序地图，三个生存目标（10、15、20 波）与沙盒。包含原版美术、17 组原版音效、16 首原版音乐、中文/英文预生成字模、横竖屏适配、触控和手柄。每局最多 160 栋建筑、40 敌人、8 友军、64 条射击效果，线性内存上限 3 MiB。

这仍是基础内容的非官方重制。三个区域是重新生成的小地图及不同生存目标，冰冻森林采用雪地外观，并非原版战役地图。科技成本、部分单位移动速度和波次编组有小地图适配；单位上限是总计 8 个。仅实现水这一种液体，水量按 0.1 单位离散；运输离散为单物品格，交叉器按进入方向直通。供电按网络比例及离散蓄电计算；节点目前按范围自动连接，尚未提供原版手动连线与全部连接规则。射击即时结算伤害，尚无完整逐弹碰撞、单位升级/完整飞行运动、完整科技树、逻辑处理器、蓝图、地图编辑器、联机或原版存档兼容；Alpha 暂无死亡/重生。

### 存档兼容

0.2 起自动读取 0.1 的 MND2 存档，保留库存、建筑、敌人、波次和旧地图布局，随后写成 MND3。0.3、0.4 沿用 MND3；0.5 使用 MND4；0.6 写入 MND5，继续读取 MND2/MND3/MND4，将旧钻头冷却转换为对应进度。0.7 写入 MND6，继续读取 MND2–MND5；保留旧施工队列，转换原有工厂进度和电池能量，旧加工冷却不重复发放已产出的物品。0.8 写入 MND7，继续读取 MND2–MND6，补充保存背包、采矿目标与进度、移动目标。0.9 写入 MND8，继续读取 MND2–MND7，补充独立的三态音乐设置，旧存档默认使用原版播放调度。MND8 同时保存施工状态、已投入建材、拆除进度及计划顺序，并同时保存钻头预热、开采进度、水量、工厂进度、部队、集结点、研究、占领记录和声音开关，并校验长度、字段范围、占地及校验和。错误存档不会覆盖当前世界。旧地图保留原水域；新的基地旁水塘只在新地图生成。

### 当前渲染方式

0.3 起默认通过 GameRender 批量提交世界、精灵、按钮与文字，HUD 合入同一帧；不再在 Guest 逐像素绘制完整 RGB565 帧，也不使用 UI Canvas 绘制文字。已知界面文字随包预生成字模，首次绘制直接解压到 256 项 LRU、四页 A8 纹理，首帧无需等待系统逐字回复。数字、标点和中英文固定文案均收录。未收录字符才通过 UI 接口请求 Host 系统字模并缓存；UI 接口仍提供输入根节点。Host 字体服务可使用其自身的 LVGL 实现，这不等于移除系统中的 LVGL。

字号收敛为 12、16、24，减少重复字模。需要回退时，当前可见文字先于后台请求，每次收到回复就补发请求，容量背压后不额外固定等 20 ms，并合并重复重绘。主循环将绘制耗时计入等待周期，避免每帧绘制后再固定休眠 20 ms。不要求升级系统固件或改动消息协议。

`font-source/` 保留工厂 PXA Sans SC 的原始 TTF、来源和两份 OFL 许可。`tools/build_font.py` 使用 Pillow 从 `main.cpp`、`core.cpp`、`runtime.cpp` 的字符及可打印 ASCII 生成三个字号的 PackBits 字模和指标，输出 `font.hpp`、`font-upstream.json`。新增或修改文案后运行此生成器；普通构建直接使用已生成字模，不加载整份 TTF。字体只用于应用，不改系统字体。

原版贴图打包为保留 RGB565 颜色的索引图集，静态地形分块缓存，小地图只在地形或建筑变化时上传。暂停和静态菜单按输入、字模完成等事件重绘；游戏画面目标 30 Hz，模拟逻辑保持 20 Hz。选中电力节点时显示连接范围内的供电线路。

GameRender 请求 `PREFER_DIRECT_SCANOUT` 和借用命令缓冲区模式，是否实际直刷取决于 Host、屏幕与系统覆盖层；系统弹窗仍由 Host 接管。桌面模拟器不能确认 ESP 的物理直刷路径，也不能据其耗时推算 ESP 实机帧率。对比时应分别看 Guest 指令生成、同步提交和 Host 光栅化耗时。

`MINDUSTRY_LEGACY_RENDERER` 保留原 RGB565 自绘与 Canvas 文字的参考实现。`MINDUSTRY_PROFILE` 向日志输出绘制耗时与缓存计数；开启后菜单也持续重绘以便相同场景对比，不显示性能浮层。例如：

```sh
PXA_APP_DEFINES=MINDUSTRY_PROFILE tools/app.sh build mindustry --target simulator --output <本地产物目录>/gamerender
PXA_APP_DEFINES=MINDUSTRY_LEGACY_RENDERER,MINDUSTRY_PROFILE tools/app.sh build mindustry --target simulator --output <本地产物目录>/legacy
```

## 素材与许可

0.11 将全部 22 种建筑的静态图标与原版 v154 的 `icons()` 和绘制器合成顺序逐项对应。`tools/building_art.py` 集中定义图层：两种工厂为主体 + 共用出入口 + 共用顶盖；炮塔为底座 + 炮身；电池补顶盖；导管、液体路由器及储液罐补底层。核心按原版 Team.sharded 的三色调色板合成队伍图层。机械、气动钻头继续使用底座、转子和顶盖。炉火、发电预热、维修闪光和泵内液体属于运行状态，静态图标保留原版默认外观。

工厂四个朝向在导入时预合成，仅旋转出入口；建造预览、施工图及场景主体使用对应朝向，底座和顶盖的光照方向保持原版。建筑及单位精灵仍放在一张 256×256 索引图集中，图层在构建阶段合并，单栋建筑的主体绘制次数不增加。修改图层时先核对上游源码，再更新生成头文件及图像参考；原始 PNG 和来源哈希保存在 `assets/upstream/`、`upstream.json`。

`tests/building_art_test.py --output <本地产物目录>` 检查全部建筑和工厂朝向的固定图像参考，以及图集边界、重叠、透明度和颜色；`tests/building_frame_test.cpp` 检查真实绘制命令中的图标、工厂主体、施工图和预览朝向。参考文件为 `tests/fixtures/building-icons-v154.json`，仅在对照原版图层并完成视觉检查后更新。

`upstream.json` 固定上游版本、文件来源和 SHA-256。`tools/import_assets.py` 仅下载清单中的原版文件，再用 Pillow 缩小贴图、生成 RGB565 头文件，用 FFmpeg 转换四段音效；应用图标直接复制原版 PNG。`tools/build_render_assets.py` 从头文件生成索引图集、调色板和区域表，修改或重新导入贴图后应再次运行。需要 Python 3、Pillow、FFmpeg 和联网；普通构建无需重新导入。`assets/NOTICE.txt` 与应用内“关于”包含归属及非官方说明。分发二进制时须同时提供本应用对应源码及许可；应用包不纳入 PXA 系统链接依赖。

## 开发检查

```sh
g++ -std=c++17 -O1 -g -fsanitize=address,undefined \
  local/pxa-apps/mindustry/{core.cpp,systems.cpp,construction.cpp,production.cpp,power.cpp,player.cpp,save.cpp} \
  local/pxa-apps/mindustry/tests/core_test.cpp \
  -o <本地产物目录>/core-test
<本地产物目录>/core-test
python3 local/pxa-apps/mindustry/tests/simulator.py \
  --simulator build/simulator/generic/pxsys_product_simulator \
  --package <签名展开目录> \
  --publisher-key deps/pxa-system/apps/pxa/.dev-signing/publisher-public.der \
  --output <本地产物目录>/simulator
```

`tests/conveyor_test.cpp` 验证五种连接和镜像选择、计划与邻居变化、方向和堵塞；`tests/conveyor_frame_test.cpp` 验证阴影顺序及四方向、四动画帧和六档缩放。`tests/conveyor_simulator.py --fixture <conveyor_test 生成的存档>` 检查实际截图中的传送带接缝。

`tests/camera_build_test.cpp` 验证视角跟随、停靠半径、暂停、普通施工范围和沙盒规则；运行时传入输出路径可生成远处工厂计划夹具。`tests/camera_simulator.py --fixture <该夹具>` 验证机器人进入范围、逐步扣料施工及重启续建。

`tests/production_simulator.py` 通过实际界面供料，验证冶炼厂同时接收煤与沙，以及单台发电机驱动工厂以不足额供电出兵。`tests/device.py --production` 可在实机执行相同场景；开始前备份已有存档；`--restore-from <备份根目录>` 可在测试结束后恢复并重新进入原有游戏。

`tests/unit_size_test.cpp` 验证四种单位在五档缩放下的原版 1.5 格画布和实际精灵提交；`tests/dense_production_test.cpp` 验证 160 栋半血加工厂与长线建造预览的绘制上限。两者使用 UI 测试的编译参数。

`tests/player_test.cpp <输出存档>` 可生成远矿点的真实 MND8 测试夹具，并输出矿格坐标；`tests/player_simulator.py` 以该夹具验证实际触控采集、满背包、退出重启和回核心存入。`tests/device.py --production --mining` 可增加实机采矿场景。

`tests/player_test.cpp` 验证采矿周期与矿级、背包上限、物品转交、施工优先、MND6 迁移和寻路缓存更新，使用核心测试编译参数。

`tests/production_test.cpp` 验证按原料分配容量、加工周期、比例供电、蓄电能量守恒、多电池分配、真实占地连接、缓存失效和 MND5 迁移，编译源文件与核心测试相同。

`tests/construction_test.cpp` 验证 Alpha 范围/速度、逐步扣料、缺料恢复、未完工停机、铺线队列、拆除返还和施工存档，编译参数与核心测试相同。

钻头机制回归为 `tests/drill_test.cpp`，覆盖混矿优先级、硬度、稳定产速、预热、两种用水量、满仓停机及 MND3/MND4 存档；编译方式与核心测试相同。`tests/drill_simulator.py` 通过真实模拟器界面验证完整图标、气动钻头预览、开采和存档，参数与普通模拟器测试相同。

新增核心测试为 `tests/expansion_test.cpp`，可用相同源文件和编译参数运行。`tests/expansion_simulator.py` 使用相同命令行参数，通过实际触屏操作验证铺管、供水、两类工厂出兵与集结。`tests/fixtures/v0.1.mnd` 是旧版自动化测试世界，用于跨版本读取回归。

`tests/render_test.cpp` 使用模拟 Guest 传输验证字模缓存、裁剪、地形和小地图缓存，以及缩小视图的命令容量：

```sh
g++ -std=c++17 -O1 -g -Wno-attributes -fsanitize=address,undefined \
  -DPXA_POCKET_RESPONSIVE=1 -DPXA_POCKET_SYSTEM_TEXT=1 \
  -I deps/pxa-system/sdk/guest-c/include \
  local/pxa-apps/mindustry/{renderer.cpp,core.cpp,systems.cpp,construction.cpp,production.cpp,power.cpp,player.cpp,save.cpp} \
  local/pxa-apps/mindustry/tests/render_test.cpp \
  -o <本地产物目录>/render-test
<本地产物目录>/render-test
```

`tests/render_compare.py` 依次运行两个启用性能日志的签名包，使用相同种子、视口和操作采样主菜单、世界和缩小视图；参数见 `--help`。该测试比较应用侧提交前的指令生成耗时，旧实现的 Canvas 合成是异步的，不能将比值当作显示吞吐提升。

`tests/ui_test.cpp` 使用与渲染测试相同的编译源文件和参数，验证五种尺寸及安全边距下的控件边界、常驻遮挡面积、真实游戏手势和完整帧提交。模拟器测试覆盖 320×240、296×240、480×320、240×320 和 480×480。

`tests/gesture_test.cpp` 使用与渲染测试相同的编译参数，覆盖手势中心稳定、双指平移、不同松手顺序、界面触点隔离、第三触点、取消、缩放边界与长按选择。`tests/touch_simulator.py` 使用与普通模拟器测试相同的命令行参数，将真实双触点事件送入 PXA/WAMR；覆盖五种尺寸和额外的 305 DPI、安全边距及圆角配置。

`tests/device.py` 从固件工作区运行，以 `--port`、`--package`、`--output` 指定设备、签名包和本地产物目录；需要 PXADB 的字模、截图与帧采样功能。它通过正常界面开始测试沙盒，开始前把已有游戏存档备份到输出目录，再验证双指缩放/平移、缩放边界、长按选择、范围预览、折叠 HUD、科技、小地图与库存，并采集首屏字模时间和已呈现帧间隔。它安装应用包，不刷固件。`--skip-install` 可复用已安装的同一测试包。

测试运行产物、日志与截图放入工作区 `local/artifacts/mindustry/<时间戳>/`，不提交。
