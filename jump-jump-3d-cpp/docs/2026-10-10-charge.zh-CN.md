# 蓄力计时修复与内存复测（2026-10-10）

已恢复 C 原版的蓄力与飞行计时规则，没有调整蓄力上限、起跳速度、重力或落点公式。正常包关闭计时日志，使用 O3。正式 ESP32-S3 包和六种屏幕的模拟器包均重新构建。

## 原因与修复

C 版的 `pxa_clock_tick_steps` 每次将回调间隔四舍五入到 20 ms，最多补两步，丢弃余数。移植时使用的 `FixedStepper` 会累计余数。两者在稳定 20 ms 回调下相同，但 32 ms 回调连续 25 次时，原版推进 50 步、1.0 秒，旧 C++ 只推进 40 步、0.8 秒；因此同样按住时，蓄力和跳距偏小。

应用改用只有一个 64 位时间戳的 `GameClock`，逐次匹配实际 C helper。后台停止时钟并取消蓄力，前台重置时间戳，避免把暂停时间补进游戏。显示仍独立于物理更新，零步回调不丢弃可呈现画面。该时钟是应用的兼容规则，不修改其他游戏的通用 `FixedStepper`。

## 正确性

- 原生测试直接调用未修改的 C helper 和 C 游戏核心；12 种间隔 × 6 种按住长度，共 72 次完整重放，核对蓄力、缩放、释放速度、飞行、落点、状态、评分及暂停恢复，并覆盖重复/倒退时间戳、抖动与两步上限。
- pai-touch 的诊断包记录实际回调时间戳。0.15、0.36、0.70、0.82、1.20、2.0 秒六次注入均逐回调符合 C 规则，释放速度和理论落点也符合原公式，见 [charge-device-parity.json](charge-device-parity.json)。日志会拖慢回调，这组测试只证明计时兼容，不能作为帧率或正常手感基准。
- 正式代码原生与 ASan/UBSan 各 **9/9** 通过。六种签名 AOT 屏幕各通过准备、按住、释放画面检查，见 [font-display-matrix.json](font-display-matrix.json)。

## 降低内存而保留画面

原来的命令、上传和调色板三个数组按使用时段共用 32,788 B，减少 32,768 B 固定暂存。绘制/上传调用同步复制数据后才复用暂存；每次天空换色重新建立全部调色板。实际 Host 光栅输出检查了 8 个配色、3 档字体、准备/蓄力/飞行共 72 帧，命令和像素与独立暂存相同。

三档抗锯齿字图改为签名 PXR 资源，由 Host 按需加载所选的三个字图并直接绑定。Guest 保留字形度量，免除字图在 Guest 和 Host 的重复驻留。九个字图的 texel 与原始字体数组逐字节相同：[资产校验](jump-font-asset-parity.json)。六种屏幕的准备画面与外置字体前 **零像素差异**：[画面校验](jump-font-image-parity.json)。未减少字体大小、覆盖率或抗锯齿层次，也没有新增 UI 帧层。

## 最新真机同场景比较

pai-touch，296×240、160 DPI、全分辨率、三帧缓冲、准备场景、种子 `0x9e3779b9`、最高分 0。C 与 C++ 使用同一次开机的 Host，分别冷启动三轮，预热 5 秒，采集 4 秒。原始结果：[C](device-C-final.json)、[C++](device-CPP-final.json)，截图：[C](screenshots/device-C-final.jpg)、[C++](screenshots/device-CPP-final.jpg)。

| 三轮中位数 | C 原版 | C++ 修复后 |
|---|---:|---:|
| 实际显示 FPS | 27.35 | 28.61 |
| Host 光栅整帧平均 | 21.358 ms | 19.394 ms |
| 整机稳定 SRAM（包括探针） | 286,328 B | 286,240 B |
| 整机稳定 PSRAM（包括探针） | 2,569,716 B | 2,523,268 B |
| 从本轮空闲状态增加的稳定 PSRAM | 1,205,048 B | 1,152,016 B |

显示 FPS 约提高 4.6%，Host 光栅约减少 9.2%；稳定整机 PSRAM 降低 46,448 B。两版字形和天空背景有画质差异，这属于整条绘制路径比较，不是仅比较语言。采集窗口内原版约 2.81 秒的一次 BGM 已播放完毕，不能声称该场景有持续音乐负载。呈现间隔在原始 JSON 中完整保留，不用应用提交计数计算 FPS。

在之前一次 Host 上也实测过 C 35.45 / C++ 36.18 FPS；期间另一任务更新了固件，两批结果不能交叉比较。版本字符串都带 `dirty`，不足以证明两个批次固件相同；本报告以上述同次开机的最新成对测量为验收依据。

AOT 映射确实增加，已计入整机 PSRAM，不能仅凭 Guest 减少宣告总内存降低。资源预算、音效缓存与 Asset 缓存具有包含关系，不重复相加。最新 JSON 保留全部预算分类、空闲基线、初始化峰值与退出后占用。

## 复现

在 workspace 根目录执行：

```sh
PXA_CPP_GAME_TEST_BUILD="$PWD/local/cpp-game-ports-20261010/native-build" bash local/pxa-apps/common/cpp/tests/run.sh -DPXA_C_REFERENCE_BENCH=ON
PXA_APP_DEFINES=J3_TRACE_TIMING=1,J3_FORCE_SCALE_SHIFT=0 bash tools/app.sh build jump-jump-3d-cpp --target esp32s3 --aot-only --source-root local/pxa-apps --output local/cpp-game-ports-20261010/jump-charge-trace
python3 local/pxa-apps/common/cpp/tests/reference/device_jump_timing.py --port /dev/ttyACM0 --output local/cpp-game-ports-20261010/device-jump-charge-parity --allow-audio
bash tools/app.sh build jump-jump-3d-cpp --target esp32s3 --aot-only --source-root local/pxa-apps --output local/cpp-game-ports-20261010/jump-font-device
python3 tools/measure-device-voxel.py --port /dev/ttyACM0 --app pxa-jump-jump-3d-cpp --output local/cpp-game-ports-20261010/device-jump-font-memory-final --warmup 5 --seconds 4 --repeat 3 --local-heap --wake-home --package local/cpp-game-ports-20261010/jump-font-device/pxa-jump-jump-3d-cpp.pxa
```

两个真机基线须在同一固件、同一开机期间采集；正式包关闭 `J3_TRACE_TIMING`。生产包保持自动分辨率控制，以上各次均通过截图与初始化日志确认实际目标为 296×240，未发生降档。当前产物哈希见 [font-package-hashes.json](font-package-hashes.json)。新增字体资源所占闪存增加，换来重复驻留内存减少，未为缩小包体积牺牲性能。
