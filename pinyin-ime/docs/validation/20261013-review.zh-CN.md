# 输入法代码审查与回归（2026-10-13）

本轮审查输入法 Provider、C++ SDK、Host 生命周期、手机键盘和系统设置。只提交输入法及其验证所需的模拟器修复；工作区中独立的音频接口改动和应用目录改名保留原状。

## 修复结果

| 问题与采用原因 | 行为改善 | 内存与验证 |
|---|---|---|
| 英文九键拒绝插入后仍记录连点状态，下一次连点会误删已有文字 | 只有实际插入才允许替换；过滤掉的字母不会先删除已接受字符；外部文本更新清除连点状态 | 复用现有状态，未增加实例字段或缓存。先复现长度上限下 `X` 被删除，再测试上限、字符过滤、外部中文更新及原有大小写/长按 |
| 保持焦点时改变密码属性未更新键盘上下文 | 旧中文组合与回复失效；释放中文 Provider，强制英文并遮蔽当前行；解除密码模式后重新按偏好启用中文 | 复用会话代数和释放确认，无新增队列或词库驻留。13 种配置检查旧回复被拒绝、正文保留、遮罩和卸载 |
| 故障回退后的光标移动仍将状态设为等待中文 | 原生回退不再进入不需要的词库等待状态 | 没有新状态；既有故障/超时与编辑检查 |
| SDK 未匹配 Host 的输入长度和候选页索引边界，错误分类不清晰 | 超大输入与页索引溢出在本地拒绝；区分调用顺序、无效文本及容量不足 | `Frame` 仍借用调用者缓冲且不分配；边界、错误后重试与无 Host 提交检查 |
| 默认输入法和偏好用了两套持久化代码 | 共用有界读取与原子写入；正确处理短读、信号中断和临时文件链接，失败保留原选择 | 去掉选择文件的 stdio 临时缓冲，无默认缓存增长；默认值、所有偏好、畸形记录、链接及失败后原值检查 |
| 模拟器 PNG 写入的错误跳转与清理混在一起；关闭文件失败可能被报告为成功 | 两处共享小型写入函数，清理留在调用方；磁盘写入/关闭失败返回错误 | 复用原有图像缓冲。GCC 16 严格构建及 ASan/UBSan 下正常写入、`/dev/full` 失败、后续恢复检查 |

## 验证口径

从 Git 暂存区导出独立副本，使用同一 WAMR、LVGL 和字体依赖构建，避免以未提交的音频接口支撑当前提交。独立副本的 GCC 16 严格模拟器构建及 89 项 CTest 全部通过（63.03 s）；当前工作区此前的 91 项回归通过，其中包含未纳入本次提交的音频测试及额外 fixture。C++ SDK 原生全套、T9 原生测试、ESP Host 原生测试通过；手机键盘按矩形、圆角、圆屏及不同 DPI 的 13 种配置验证。

AOT 与 Wasm 分别验证正常输入和六类异常包：同长度词库损坏、签名损坏、缺词库、额外文件、词库软链接和外部硬链接。包括候选/拼音选择和翻页、长按、数字/符号、分词、光标、编辑器删除、加载取消、密码、背压、超时、重复卸载与启动。

本轮无新的帧缓冲、深度缓冲、线程或默认大型缓存。键盘实例没有增加字段，SDK 帧编码没有新增动态分配；这属于实现和构建检查，不能代替全机真实峰值测量。上一轮受控真机数据和截图保留于 [手机键盘验证](20261012-phone-keyboard.zh-CN.md)。本轮没有更新设备固件，不把旧真机结果说成这些修复的新测量，也不据此宣称打开速度、FPS 或端到端延迟继续改善。
