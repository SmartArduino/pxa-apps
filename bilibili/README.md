# billy

首页提供热门、推荐、关注动态和关键词搜索，也可输入 BV 号或
`bilibili.com/video/BV...` 链接。详情页提供选集、评论（含楼中楼预览）、
作者作品、相关推荐、画质选择、播放和本地稍后再看。选集支持多 P 与 UGC 合集，
同 BV 的观看记录保留最后观看的分 P，播放进度不会串到其他分 P。
播放期间约每分钟保存一次进度，暂停、退出播放器和播完时也会保存。
“我的”保留最近 6 条本地记录和 6 条本地稍后再看；另可浏览云端历史、
收藏夹及其视频、云端稍后再看、我的关注和关注动态。私有页面需要先登录。
扫码登录使用 B 站网页端接口，需在手机哔哩哔哩确认，二维码约 180 秒失效。
登录状态保存在应用私有 Storage，退出登录会清除本机保存的会话；封面和
媒体请求不携带账号 Cookie。登录信息不会写入应用日志。
这些云端页面只读取账号内容；本地稍后再看按钮操作本机列表。
搜索页保存最近 8 条实际搜索记录，可再次搜索或清空，不预置测试视频。
浏览页面适配竖屏、横屏和方屏；横屏详情并排显示，窄屏详情可滚动。
配色跟随系统主题和主题色，图标使用带透明抗锯齿边缘的原始 PNG。
再次播放可从上次位置继续，观看结束后从头重播；卸载并删除数据会清除记录。
默认请求 360p；480p / 720p 入口按 Host 上限显示，实际返回的尺寸仍会检查。
首次浏览申请网络权限；首次播放申请音频权限，被拒绝时可观看无声画面。
切到后台停止播放。返回详情页可继续浏览，封面和浏览请求在播放期间释放。

应用查询 PXA Video 解码能力，通过 HTTPS 分段读取 MP4 或 DASH 索引和媒体数据。
360p 和 480p 选择站点对应的 AVC 表示，音轨选择 AAC-LC。播放器转换 AVC 长度
前缀到 Annex B，再由设备 Host 解码 H.264 和 AAC-LC。
视频等比适配整块屏幕，自动保留必要黑边；播放时控制层自动隐藏，轻点画面显示。
在播放控制栏点“弹幕”可开启或关闭本分 P 的滚动、反向滚动和顶部弹幕。启动应用时默认关闭，
开启后按视频时间加载对应分段，最多同时显示三行。弹幕下载失败时继续播放视频。
可拖动进度条、前后跳转 10 秒、暂停/继续和重播。播放器右上角可循环选择
0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 倍速；目前通过 PCM 采样转换实现，声音会变调，
播放速度仍受设备解码吞吐量限制。所有时长超过一小时后显示为“时:分:秒”。定位会落在不晚于目标的
最近关键帧，时间可能有少量回退；拖动前处于暂停状态时，定位后仍保持暂停。
支持 Video 0.4 的 Host 将解码器绑定到 Surface，根据视频矩形在原生缓冲区准备画面，Billy 按 PTS 提交。整帧像素留在 Host 中。
支持 `POLL_FRAME` 的 Host 在一次调用内返回异步解码结果和帧信息。较早的 Host 分两次取得结果和帧信息。
Video 0.3 使用映射 Surface，更早的 Host 使用缩放读取和普通 Surface 写入。
单独构建 ESP32-P4 时，应用线性内存固定为 3 MiB。单独构建 ESP32-S31 时，应用线性内存从 1.375 MiB 按需增长，最高为 2.25 MiB，其余空间供 Host 解码和显示使用。
当视频填满屏幕高度、左右合计只差 1–2 像素时，播放器把黑边放入全宽共享 Surface。ESPP4-A 可以直接旋转这块缓冲到面板。边长不超过 480 像素的方屏也可把黑边填入共享 Surface。控制栏隐藏时可由支持的
设备直出面板。弹幕使用画面上方的局部透明图层。
满足分段大小限制的 360p DASH 直出可以使用三缓冲，第三块缓冲占用从播放缓存预算中扣除。
Host 拒绝三缓冲或线性内存不足时，播放器使用双缓冲。
小方屏播放较大码流时，如果两块 RGB565 缓冲区的黑边合计占用至少 256 KiB，播放器只为视频矩形分配缓冲区，按 128 KiB 分页读取大视频分段。控制层继续使用整屏坐标。
PCM 由 Audio 输出。支持长缓冲的 Host 使用缓冲 PCM，其余 Host 使用普通 PCM。
1 倍速优先通过 Audio 0.17 批量提交 AAC-LC，由 Host 异步解码并直接填充 PCM 队列。
旧固件、压缩音频接口不可用和变速播放继续使用同步解码和 PCM 输出。
DASH 音轨按已收到的完整 AAC 包开始播放。分段下载中断时，备用地址从已提交的音频包之后恢复输出。
Host 的异步 AAC 输出遇到错误时，Billy 按当前播放时间重新选择音频样本并切换到同步 PCM，保留已解码的视频参考帧和待显示画面。
设备不提供 PCM 输出时，播放器继续无声播放，并在播放控制栏提示。
无需转码服务器。
不超过 768 KiB 且文件大小有效的普通 MP4 先完整缓冲，再分配解码和显示资源；
播放、定位和重播共用同一缓存。
较大 MP4 使用两个可共享的分段缓存。DASH 按索引合并相邻分段，
先缓冲起播所需的两轨数据，播放时串行补下载。
快用完当前分段时，播放器继续解码并预取下一批分段。音视频分别保留已下载的下一段，并按当前分段的结束时间安排预取，紧急补音轨时优先保证音频。
视频按 256 KiB 合并，两批视频缓存的预取预算为 1152 KiB。遇到较大的分段，会在需要时释放已消费的视频数据，为预取留出空间。
DASH 视频补下载可接续进行中的预取。收到分段索引后，播放器可以一边下载，一边解码数据已到齐的视频样本。
下载大视频分段前，播放器会提前补音轨。遇到短读或临时连接失败时，音轨可用备用 CDN 重试一次，保留当前播放进度。
DASH 画面落后整段缓存时从当前时刻附近的独立解码分段追赶，保留 AAC 播放进度。
封面保留 16 个解码内存条目，使用 32 个固定私有文件缓存编码数据，最多约 4 MiB。
文件头绑定 URL 并只在下载完成后提交；中断下载和冲突条目会重新获取。
封面下载只允许一个进行中请求、至少间隔 1 秒、每分钟最多 20 次；
错误按指数退避，429/403 至少等待 60 秒，数值型 Retry-After 可延长等待；
日期型或无效值保守等待 5 分钟，缓存命中不发起网络请求。
需要带视频后端的固件；不支持时会显示提示。

当前支持非分片 MP4 的 avc1 / mp4a 单描述轨道、stco/co64、stsc、stsz、stts
和 ctts，包括 moov 位于文件尾的布局，索引上限 768 KiB。DASH 支持带 sidx 的
单轨分片 MP4，视频和音频分轨读取。超过 768 KiB 的视频分段按 HTTP 窗口读取，跨窗口的帧从帧首续读。直播、番剧及需要额外鉴权的片源
超出当前播放范围。
接口受站点策略影响；作者作品可能要求账号或额外验证，失败时显示错误，可登录后重试。
匿名搜索失败时可重试或直接输入 BV 号。
站点拒绝请求、视频不可用、链接到期或格式超限时显示错误，可停止并重新播放。

接口行为参考用户指定的
[bilibili-api-collect](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/video/videostream_url.md)。
本应用独立实现请求与解复用，没有复制该文档库代码、示例或素材。
功能入口和 API 行为另参考
[CardBili](https://github.com/journey-ad/M5CardputerZero-CardBili)，应用独立实现；
没有引入它的 Slint/FFmpeg 依赖。二维码使用 Nayuki 的 MIT C 实现，
[许可声明](assets/licenses/qrcodegen.txt) 随应用包分发。
界面的双列视频卡片与简洁导航参考
[Bili You](https://github.com/lucinhu/bili_you) 的布局，图标和界面独立实现。

从工作区构建：

```sh
tools/app.sh build bilibili --board espp4-a --source-root local/pxa-apps --aot-only
```
