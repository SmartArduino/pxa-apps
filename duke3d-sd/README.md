# Duke3D 固定 SD 资源测试包

复用 `../duke3d` 引擎，代码包不携带 GRP。要求固件和 SDK 实现 FS 0.3 `app-media-root`，由 Host 按已验证身份自动绑定 `/PXA/media/<app-key>`，启动不申请文件权限或弹目录选择器。资源文件名为 `duke3d.grp`，使用共享移植说明中的 MG24 GRP 转换格式。私有存档目前仍在内部旧布局。

从 pxa-projects 工作区构建 GameKit 的 ESP32-S31 包：

```sh
tools/app.sh build duke3d-sd --board doit-gamekit --target esp32s31 \
  --source-root local/pxa-apps --output local/storage-fixed-games --aot-only
```

资源由安装或导入侧按身份预置到固定媒体根，Guest 不选择目标路径。本次设备资源通过开发用 PXADB 预置；通用资源导入界面和整应用 SD 安装仍待实现。工作区设计见 `docs/pxa-storage-layout.zh-CN.md`，实际场景、内存和帧率记录见 `docs/validation/2026-10-18-duke3d-sd.zh-CN.md`。

0.1.7 引入按需 NVM 存储，后续 0.1.11 已在 GameKit 完成首次运行和重开并进入屋顶，无回调超时；稳定场景中位数为 13.9fps，20～30fps 目标仍未达到。私有 NOR 按需写入 `nvm-4194304/000` 至 `511` 的小页文件，每页 8,192 B 数据加 16 B 格式头；只有一份临时发布文件。旧 `state.nvm` 保留为只读迁移来源，新页关闭后使用 FS replace 发布，未变化的 NOR 位不重复写入。重开时有界枚举已有页，不逐个探测空页。最大 512 页，新增常驻索引和路径不足 1 KiB，不增加读取缓存，0.1.11 将 continuation 缓冲缩减 128KiB 后，最大线性内存为 3.875MiB，实际使用 3.75MiB；读取缓存仍为 384KiB。

新页覆盖优先于迁移来源；旧程序不识别这些覆盖文件，因此不能直接降级后继续写旧 NVM。迁移来源与新页会暂时并存，安装/运行仍需足够空间；当前未实现来源回收，也未完成掉电耐久性验收。遇到损坏页或枚举错误会停止，不把错误当作空白 NOR。

三个 ASan/UBSan 配置覆盖跨页 AND/擦除、无变化跳过、旧 dense/NVM2 迁移、重开、损坏页及发布失败后保留旧页。真实引擎在 Node 协议宿主中首次进入和重开均到达屋顶，使用 17 页共 139,536 B，迁移源 2,064 B，0.1.7 实际线性内存 4,063,232 B；这些宿主帧数不是设备帧率。后续支持 READ_AT 时，使用指定偏移读取，避免独立 seek 控制请求；不支持时保留原读取路径。

批量保存沿用引擎已有的开始/结束边界，同页字段先在 8KiB 缓冲聚合，切页及最外层结束前发布；结束成功后不再留待写数据。批内读可见新值，非批量调用保持写穿。这不是跨页或全存档的掉电事务。C 栈仍各为 256KiB，缩减的是独立的 continuation 缓冲；所有关卡栈峰值和完整存档恢复尚待验收。

游戏使用 Clock 0.2 合法的 16ms 周期；32ms 是主动让出前的计算预算，与定时周期不同。配置会进行编译及返回值检查。上游同步使用 `common/recrof/tools/upstream.py`，Duke 与 SD 变体共用一份版本锁和引擎源码。

0.1.12 已完成约160秒首次运行和约140秒重开，两次均无回调超时。共同80～140秒窗口的中位数仍为13.9fps；成对 RGB565 写入和原生尺寸控件快速路径没有改善本设备的中位数，不能宣称达到20fps。开启音乐/音效、关闭音乐、关闭两者的短时对照约为13.9/15.9/15.9fps，测试后恢复完整音频。动态等待仅占稳定汇总窗口约12%，仍需分析引擎内部热点。

顶端瞬态系统栏会拦截 MENU 标签的部分触摸，真机在标签下缘 y=28 可打开菜单。当前已验证转向和射击；安全边距下的完整控件布局仍需完善。
