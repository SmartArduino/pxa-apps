# 2026-10-10 SDK portability correction

The first official SDK link produced fourteen actual objects and a WASM module, then the official import validator rejected WASI `clock_time_get`. The preserved module also imported WASI `fd_close`, `fd_seek` and `fd_write`. Its actual reverse call graph connects those imports to generic `sprintf`/stdio locking and to C++ heap `operator new`'s failure-reporting path. The complete pre-change source, object closure, link commands, failed WASM/WAT and original validator output remain in `logs/games/hollowseeker/failed-sdk-wasi-printf-20261010T025840849359Z`.

Two owner-local bounded ASCII functions replace only the title's original `%5d` score and `'%02d"` elapsed-second strings. Score input is the platform's existing unsigned 16-bit `lastScore`; all 65,536 attainable values are compared against the prior defined native integer-promotion semantics, including space padding and every output-buffer byte. Seconds retain `playFrames / 60 % 60`, with all 60 attainable remainders and 32-bit frame endpoints checked. No equivalence is claimed for incompatible AVR varargs types or unexecuted AVR firmware.

At the same original point in `MyArduboy`'s constructor, the same `ArduboyPlaytune(myAudio.enabled)` construction and following `initChannel(PIN_SPEAKER_1)` call now use aligned static object storage and placement-new. The owner Playtune implementation has no instance data and is trivially destructible. Its pointer is used only for its original method calls, does not escape, and is never compared for identity. No extra initialization guard or per-NEW reconstruction was introduced. Its existing software score, priority, callback identity, channels and timing fields remain in the canonical game state. Storage addresses are excluded from that representation.

The frozen shared provider, original raw upstream files and licenses, host import whitelist, maximum memory and original game rules are unchanged. Production source changed, so current native game, sanitizer, fresh-image and encoded-sound checks are rerun before the corrected SDK build. Prior passed native evidence is preserved separately; prior acceptance does not stand in for these new runs.

The first cold PXA execution of that corrected build then exposed two differences in its complete 3,565-byte packet: channel count zero and disabled output callback, versus native values one and enabled. The actual WASM data initializes the shared constructor marker to one, while its remaining dynamic `MyArduboy` constructor has not run; the unchanged shared boot guard consequently skips it. Full failed signed package, expanded files, fourteen objects, source boundary, cold packets and actual constructor/data traces are retained in `logs/games/hollowseeker/failed-headless-cold-20261010T031132812833Z`.

An owner-only `pxaEnsureConstructed()` now runs before the original owner reset/setup. It uses the existing canonically packed audio channel count as its initialization tag: only count zero placement-constructs the same original `MyArduboy` and its exact Playtune constructor/channel sequence. A native image whose global constructor already ran has count one and skips it. NEW preserves that count and skips reconstruction. There is no new mutable guard, pointer-identity comparison, state-loader operation, source-provider edit or canonical-size change. Current game, sanitizer, sound and fresh-image checks are rerun after this correction, with an additional ordinary native NEW lifecycle regression.
