# Hollow Seeker adaptation and source boundary

Game, embedded bitmap/font arrays and embedded score bytes are preserved from OBONO/ArduboyWorks commit `d4b1f041789dcd1d71907654e4025d613b4ab420`. The repository states that its code is MIT licensed; no separate license notice occurs in this game's embedded arrays. Its full root license is retained unchanged. `vendor/original` contains the complete eight-file game directory plus the upstream root README and LICENSE. Only `vendor/platform` is compiled. The exact six changed-file sections are listed in `platform-lock.json` and `platform.patch`; the seventh platform file, `hollow.ino`, is byte-identical to its original.

Playtune 1.0.4 is pinned to `493d3c960a87d1b4716eb85fb297706230c8e937`. The original official repository URL, Arduboy/ArduboyPlaytune, redirects to Ar-zz-duboy/ArduboyPlaytune. Its full ten-file tree and MIT license are retained. The hardware timer implementation is reference source only. The owner-local implementation interprets this game's original note-on, note-off, wait and end commands and retains its software busy/priority state; audio output is silent. Encoded millisecond waits are modeled without claiming AVR frequency-dependent ISR wait quantization.

The separate 15-bit `rand()` stream implements the fixed avr-libc 2.0.0 algorithm from avrdudes/avr-libc commit `8c0baff524181d8a8a57889b352d2d326a1a08bb`. The original `rand.c` and its complete BSD 3-Clause notice are retained. The notice is also reproduced in the implementation and `LICENSE.AVR-rand.BSD-3-Clause`. This state does not alias Arduino `random()`.

AVR-width scalar types, typed constant-pointer reads and EEPROM numeric-address translation replace assumptions about AVR integer sizes and program-memory address width. The original score byte initializer 260 is explicitly converted to byte 4, preserving AVR unsigned-byte conversion. EEPROM records retain their original little-endian field order and checksum; the 1024 bytes are per-Guest RAM and have no persistence beyond a Guest session.

The upstream Logo shifts a 32-bit value by a counter-derived amount outside 0..31. The minimal guard makes those shifts defined and sets the LED signal false outside that range. Independent whole-file UBSan witnesses preserve the original failures at shift 34 and -1; all 98 originally defined counter inputs produce byte-identical outputs with the guard. There is no claim of equivalence for originally undefined inputs. Physical RGB LED output is omitted. Startup blank/flashlight/system-button utilities are omitted because they depend on physical hardware, including an intentional infinite flashlight loop. The game's original software Logo, menu, cave, drawing, death/retry, records and controls remain present.

The complete game state is encoded field by field in 429 bytes. All original mutable statics and arrays, independent RNG, owner faults and software audio fields are included. Immutable song arrays, registered song-address tables, fixed module callbacks and the fixed audio-enabled callback use semantic identities and are not serialized as host pointers. The original `MyArduboy` audio object is a fixed implementation object with no additional mutable heap state. With the platform's 3136 bytes, each full state packet is 3565 bytes.

The native checker and private replay library compile the full adapted game and provider source. The private library exposes ordinary boot, input, time advance and read operations; there is no state loader. These checks establish adapted native C++ behavior, not executed AVR firmware or physical hardware behavior. Actual PXA and desktop acceptance are reported separately and only become passed after their real executions.

The first actual SDK failure and resulting owner-only bounded scalar formatting and aligned placement-new corrections are documented in `NOTICE.sdk-portability.md`. Full original bytes and complete updated six-section platform diff remain available; neither correction changes game rules or the canonical state layout.
