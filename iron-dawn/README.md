# 钢铁黎明 / Iron Dawn

原创 PXA 即时战略游戏。等距工业战场、自动采矿、基地建设、电力调度、混合编队、三章连续剧情和无尽守备。战场采用原创生成的像素图片图集，像素特效使用 MIT 授权的 pixelfx 离线烘焙动画；设备上不运行 JavaScript，不依赖其他游戏资源。

## 玩法

- 点选己方单位；双击同一单位选择全部同型部队。“全军”选择所有作战单位。
- 点小地图下方的“框选”，在战场拖出矩形；可从任意方向拖动，实时预览入选单位和数量。松手后自动恢复指令模式，点地面移动或点敌军集火。框选只包含屏幕内的己方作战单位，不包含建筑与采矿车。点空地结束框选会清空编队；再次点“框选”或按 B 取消时保留原编队。
- 框选未开启时拖动战场仍为平移；小地图始终用于跳转视角。框选期间第二根手指不会抢走选框，切到后台或暂停会取消未完成的框选。
- 点地面下达移动指令，部队途中自动迎敌；点可见敌军集中攻击。拖动战场平移，小地图跳转，“回基地”归位，“缩放”切换三个视野。
- “部队”面板排队生产；“基地”面板选择建筑，再点己方基地周边已探索的空地施工。精炼厂完工附送一辆采矿车。
- 采矿车自动采集有限矿脉并返厂交付。补充电站，避免缺电造成生产与施工减速、己方炮塔停火。兵营生产步兵，工厂生产装甲和采矿车。
- 游骑兵适合对抗步兵，破甲兵适合反装甲；坦克承担正面交战，长弓火炮用远射与溅射压制密集目标。
- 蓝色信标标记战地补给站：作战单位靠近并守住五秒，获得 280 矿石，附近部队修复 30% 基础耐久。敌军靠近会争夺并暂停接收；每站只能领取一次。补给站出现在重新部署的战役地图，已有存档可继续原战局。
- 单位累计击毁 2、5、9 个敌军时晋升一、二、三星，分别提高 12%、24%、36% 火力，并在晋升时修复 20% 基础耐久。注意保护老兵。
- “停止”让选中作战部队就地警戒、自动还击，手柄 X 同样有效。选中兵营或工厂，再点空地设置集结点，新部队会自动前往。
- “维修”修复选中单位或建筑并扣除相应资金；“空袭”消耗 180 矿石，点可见目标施放，冷却 45 秒。“撤单”取消末项生产并全额退款。
- 战斗可暂停，约每 12 秒自动保存，并在暂停、切到后台、回指挥部时保存。重新打开后从“返回战场”恢复。大存档保存在应用私有文件中，使用两份带校验的快照及原子替换。
- 触屏是完整操作方式。方向键辅助平移，A 选择全军，Start 暂停，B 返回。菜单支持上下与 A。

## 战役

1. **灰烬里的电台**：建立赤砂前哨的经济与装甲生产线，摧毁东南敌方指挥中心。
2. **穿越静默之河**：利用渡口跨河，部队靠近中继站 8 秒完成占领，保护平民撤离 90 秒。把防线推进到电台前方，拦截敌军远射。
3. **黎明之前**：先击毁两座聚变电站，让灰塔炮塔停火，再摧毁中枢。利用火炮与空袭瓦解防御。

初次建议选择休闲难度。标准难度需要保护矿线、补充生产和掌握推进时机。战役胜利解锁下一章，可从档案重玩；保存最好用时和完成状态。

## 无尽守备与科研

从指挥部选择“无尽守备”，守住赤砂前哨。渡口随每局种子变化，敌军轮流从三个方向来袭，每五波出现重装部队。击退整波敌军获得矿石，基地附近的车辆和步兵获得部分维修，短暂整备后下一波抵达；每三波出现新的补给机会。指挥中心被毁时结算，保存最高击退波数。重试保留本局地图种子，新开一局更换种子；战役解锁和最好用时独立保存。

从“战术→科研”打开研发面板，大屏也可直接点击指挥栏底部的“科研”。装甲工厂建成后，可选择两级弹药改良（每级增加12%火力）或复合装甲（每级减少10%所受伤害）。首次研发220矿石、16秒，第二级400矿石、24秒，一次只能研发一项；取消全额退款。缺电时进度减慢，工厂被毁时暂停，重建后继续。科研面板保持战局运行，返回指挥部前可先暂停。科技只作用于当前战局，可与老兵火力加成叠加。

存档使用V6格式，兼容并迁移V4/V5战役快照，同时保存科研进度、守备地图、波次和纪录。缓存不写入快照。

## 机动与地形

坦克、火炮和矿车的巡航速度均高于步兵；坦克适合快速增援和侧翼突进，火炮保持较慢的重型机动，矿车载矿后减速。车辆转弯时先调整朝向，履带帧继续按实际位移推进。公路与桥面让车辆加速20%、步兵加速5%；林地、弹坑和废墟会减速。

新部署地图增加贯通基地、渡口和前线的道路、可绕行岩脊及前出矿点。岩脊不可通行，桥面禁止施工以保留渡口；小地图显示道路、桥面和岩脊。步兵在林地、弹坑和废墟中获得25%直击减伤，旁边显示掩护标记；火炮和空袭可压制掩护。选择单位后打开战术面板可查看当前地形状态。

采矿车保留当前矿点直至采空或路线失效，再寻找可达矿脉；最后一小批矿石按实际数量交付。来敌倒计时显示方向，最后十秒在小地图提示入口。后续波次会分兵袭扰矿线和工厂，无尽守备的后期敌军逐步获得老兵和耐久加成。已有存档保留原地形，新地图在重新部署时启用。

环境按 `art/environment-reference-v1.png` 的河谷设计制作：松树林、分面岩脊、芦苇与碎石河岸、金色矿簇、路肩、路面裂缝及带伸缩缝和栏杆的桥梁。地面细节进入缓存，树木按战场深度绘制；单位靠近时树木保持原位。完整参考图只用于设计，运行时只读取离线编码的小型图集。生成提示词与输入记录见 `tools/environment-prompts.json`。

车辆、建筑和景物的接触阴影从图集底部不透明像素推导，步兵脚底阴影跟随步态并把抬脚高度投回地面。阴影独立于精灵注册点和枪炮口锚点，校准阴影时不移动图集或枪口。

## 大屏界面与 DPI

横屏可用空间达到约800×440dp时启用右侧指挥栏，小地图、编队状态、部队与基地页签、生产卡片和队列常驻；战场下方保留全军、框选、停止、维修、缩放与空袭。可用空间较小时采用抽屉与单行指令栏。DPI或系统字号改变会重新排版，并保持战场中心。

界面按 `art/large-ui-reference-v1.png` 制作，按钮、卡片、面板和肖像底座使用原创图片蒙皮。九宫格保留金属倒角、铆钉和高光，中心与边缘按像素平铺；图片离线编码，运行时不解码PNG。Z Labs像素字体使用整数倍字模。高分辨率窗口采用Host的2倍或4倍整数缩放，两份映射帧合计不超过2MiB；触控坐标同步换算。生成提示词见 `tools/ui-skin-prompts.json`。

## 音乐与音效

指挥部使用克制的工业氛围配乐，进入战斗或科研时渐变到装甲推进节奏。两段配乐为16kHz单声道Vorbis循环；十个短音效覆盖界面、无线电指令、步枪、坦克炮、火炮、火箭、爆炸、施工、就绪与科研完成。暂停会停住音乐并停止短音效，继续行动恢复音乐；暂停菜单的“声音”同时控制配乐和音效，静音设置单独保存。

音频在外部ComfyUI中用ACE-Step 1.5和Stable Audio 3 Small SFX生成，游戏不包含模型或推理依赖。Host流式解码音乐并持有预载的短音效，游戏不缓存整段音乐。音效采用独立轨道与短触发间隔，过时声音不排队。`art/audio/`保留处理后的无损母版，`assets/audio/`是运行时资源；模型摘要、提示词、种子和处理参数见 `tools/audio-prompts.json`。

重新制作时，用 `tools/generate_audio.py --url <ComfyUI地址> --output <本地产物目录>`生成候选，再运行 `tools/prepare_audio.py --source <候选目录> --report <本地产物JSON>`。工具使用现有模型，不安装或修改ComfyUI；转换需要NumPy和FFmpeg。生成记录、候选和验证输出放在工作区 `local/artifacts/` 下。

五类单位拥有独立且固定的中文声线：游骑兵清亮机敏、破甲兵低女声、坦克车长厚重低沉、炮兵军官清冷精确、采矿司机温暖干练。37句短回应覆盖点选、框选、全军、移动、攻击、停止和生产就绪；采矿车只有选中、出发和就绪台词。同一时刻只允许一个单位播报，连续选择会节流，过时指令不会延迟堆积；播报时压低配乐，暂停、静音或离开战场会取消待播语音。

`tools/voice-prompts.json`记录角色设计、台词、固定种子和模型摘要。每个角色先用Qwen3-TTS VoiceDesign生成原创参考，所有后续台词复用同一Base模型声音提示，不逐句重新设计音色，也不改变音高。原始参考及处理后的无损母版在`art/audio/voices/`；16kHz单声道S16运行资源按需异步加载，复用独立的无线电轨道，不在设备上运行模型或解码压缩语音。制作时，在已有Qwen3-TTS环境的推理机运行`tools/generate_voices.py --models <现有模型目录> --output <任务产物目录>`，再用`tools/prepare_voices.py --source <生成目录> --report <本地产物JSON>`转换；工具离线运行，不下载模型。

## 构建与运行

在 PXA 工作区根目录：

```sh
tools/app.sh build iron-dawn --target simulator,esp32s3,esp32s31,esp32p4 --source-root local/pxa-apps
tools/simulator.sh product --profile pai-touch \
  --package local/app-output/pai-touch/pxa-iron-dawn \
  --publisher-key local/pxa-apps/.dev-signing/publisher-public.der
```

可选 `--board doit-gamekit-2` 等目标板。设备需要触摸屏、约 4 MiB 应用线性内存预算和 PXA Core 2.1。使用现有 SDK 的 Surface 映射帧缓冲，界面按屏幕尺寸缩放，原生像素输出。实体设备帧率取决于芯片、屏幕及 PSRAM，需在目标硬件上实测。

`tools/generate_fx.mjs` 使用 `tools/pixelfx/` 中固定提交的 MIT 源码生成 `fx_data.hpp`，保留颜色和透明度，压缩后的五组动画约 95 KiB。Node.js 仅用于生成；无需 npm 依赖。上游提交、输入摘要和排除范围见 `tools/pixelfx/upstream.json`。未包含上游 `gallery/fonts` 的 Patch Pixel 字体。

`tools/generate_assets.py` 从 tools/fonts 中固定版本的 Z Labs Pixel 12px CN（OFL 1.1）生成应用所需的字形子集；需要 Pillow。字体完整声明保存在 `assets/NOTICE.txt`。

可复用规则与战役策略测试位于 `tests/`。运行程序、日志与截图统一放在工作区 `local/artifacts/iron-dawn/<时间戳>/`，不提交生成产物。

## 绘制与性能

工业建筑采用玻璃顶棚、通风百叶、外露管线、检修梯和装卸区警戒线区分用途，地表道路采用分块铺装与断续标线。战斗绘制目标为约30帧/秒，菜单动画为10帧/秒；实际速度仍由目标设备和显示传输决定。

字体采用Z Labs Pixel 12px简体中文版，保留原生12像素单色字模，按整数倍率绘制；界面文字在物理屏幕层合成，避免逻辑画布缩放造成二次采样。字模约9 KiB，运行时不重采样、不创建字形缓存；特效以同行连续像素批量混合，屏幕缩放复用预计算列索引。上述缓存不进入存档，不增加运行时素材依赖。

`tests/render_benchmark.cpp` 提供固定场景的渲染CPU耗时和图像摘要，`tests/raster_cache_test.cpp` 校验全部特效帧的绘制一致性。SDK构建时可用 `--define IRON_PROFILE=ON` 将完整应用的呈现帧率、绘制和屏幕合成耗时写入日志；常规构建关闭此选项，界面不绘制性能浮层。

`tests/font_grid_test.cpp` 检查字形整数倍率、原生屏幕像素对齐、延迟文字内容复制和裁剪；全界面使用同一套12像素字模，中文宽12像素、西文宽6像素，标题按整数倍率放大；小屏卡片采用短名称，长提示按完整UTF-8字符省略，剧情正文调整到完整可读的行宽。

单位、建筑、地表、Logo及界面图标的PNG源素材保存在 `art/generated/`，设计参考为 `art/design-reference.png`，生成提示词和输入摘要保存在 `tools/art-prompts.json`。`tools/generate_art.py` 将这些源素材导入为RGB565调色板与不透明行数据，并生成96像素应用图标；不覆盖PNG源素材。运行包使用编译后的图像数据，不加载PNG、不依赖图像解码库。 商城封面原图为 `art/generated/store-cover-v1.png`，由 `store.json` 引用，提示词与输入记录保存在同一美术清单中。

图集包含五类单位的八个朝向与两组姿态、矿车空载/载矿外观、八类建筑、八张地表、十六枚指令图标、标题Logo和应用标识，共114帧。步兵使用八相位的代码骨骼步态，按实际位移推进；固定双手持枪的上半身图片，仅让左右腿交替支撑和摆动。支撑脚的移动与等距投影下的前进距离对应，停下或交火时回到站姿，暂停时不推进动画。车辆履带按位移切换姿态，水面使用帧动画，队色和受击闪光通过调色板处理。人物骨盆、车辆接地点和八朝向枪口标注在 `art/rig.json`；生成器把标注写入图集，切换朝向与载荷时使用共同锚点。

界面使用更大的单位图片卡片、削角金属面板、独立图标、分段生产进度和编队概要，空袭按钮显示剩余冷却时间。小屏保留原生12像素文字与简短卡片名称。布局由 `hud_layout.hpp` 定义。启动时默认请求横屏，窗口旋转后按新尺寸重建画布，保持相机中心与触控坐标一致；宽屏画布按屏幕比例扩展，避免图像拉伸。战斗顶部只显示矿石、电力、计时和暂停。窄屏、横屏与高度不超过480像素的屏幕，默认只保留一排“部队、基地、全军、停止、战术”。点部队、基地或战术展开浮层，再点“收起”或按B关闭；选择建筑后自动收起，以便在战场部署，底栏直接提供“取消”。生产队列数量和进度保留在部队按钮上，维修、科研、空袭、撤单、回基地和缩放放在战术面板。浮层遮挡的区域不会接收地图指令，展开与收起不改变战场相机；较高的屏幕保留完整生产面板。

不透明行编码支持直接写入已裁剪的像素区间；480像素宽且与逻辑画布等大的屏幕直接在映射帧缓冲内绘制，其他屏幕使用预计算索引缩放。地表图层复用像素缓冲，在相机、缩放、水面相位、地形、迷雾、探索范围、矿脉耗尽或章节变化时重新绘制。缓存不进入存档。

`tests/sprite_asset_test.cpp` 检查图集记录、逐像素解码一致性、缩放、裁剪、调色板、动画帧差异与布局边界；`tests/ground_cache_test.cpp` 检查地表缓存及失效条件。源码保留早期几何单位绘制器用于对照，正式战场使用图片图集。

弹丸在规则层保留原来的地面坐标与命中判定；绘制层从发射时的朝向和枪口锚点计算弹道，火光与拖尾共用发射点。火炮的曲线从炮口开始，初始切线顺着炮管；朝背面被身体遮挡的枪口在人物图层后绘制。`tests/animation_test.cpp` 验证交替步态、支撑脚、上半身稳定性、位移驱动和各朝向发射点；`tests/animation_preview.cpp` 导出逐帧检查图，属于原生渲染预览，不能替代真实模拟器截图。

精灵采用192 KiB有界RGB565行缓存，保留原始不透明行用于裁剪和透明区域；小地图只在地形、探索、迷雾或矿脉状态变化时重建，单位和视野标记继续逐帧绘制；步兵的固定相位骨骼姿态按需缓存。`tests/render_cache_test.cpp` 比较缓存前后的缩放、裁剪、队色和动画数据，`tests/expansion_test.cpp` 检查守备路径、波次、科研与旧存档迁移。
