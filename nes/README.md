# NES模拟器

PXA Core 2 应用，基于 Retro-Go 的 Nofrendo 内核。NTSC 以每秒 60 个模拟帧运行；PAL 按原制式运行 50 帧，避免把 PAL 游戏加速。屏幕提交受独立跳帧和双缓冲背压控制。线性内存初始值和上限均为 4 MiB，避免旧固件在增长后保留失效的映射缓冲；需要有足够 PSRAM 的主机。**支持列表不等于所有游戏已验收，60fps 也需要按具体设备和 ROM 测量。**

## 大 ROM

iNES 1.0 文件上限为 6 MiB，仍按内核实际 mapper 范围解析。超过 1 MiB 或整块分配失败时，使用至多 256 KiB ROM 缓存，PRG/CHR 均按需读取；CPU 和 PPU 的活动映射分别锁定。小 ROM 保留驻留路径。SD 及私有 Flash 均通过 SDK 的 FS `read-at` 访问，卡带运行期间保留文件句柄；不需要把整个 ROM 放进 4 MiB 线性内存。

分页模式的 ROM 只读，CHR-RAM 和 nametable RAM 仍可写。即时存档使用 v2 保存机器状态、RAM 和逻辑银行映射；驻留路径继续使用 v1。电池存档的 CRC32 身份及格式不变。`NES ROM` 每个统计窗口都给出卡带 CRC 和目标频率，分页时增加缓存容量、缺页、淘汰及读取耗时；存储读失败后停止模拟并保留已有存档。公共缓存契约见 [`common/rom`](../common/rom/README.md)。

## 构建和运行

在 `pxa-projects` 工作区执行：

```sh
tools/app.sh build nes --target simulator,esp32s3 --aot-only
tools/dev.sh sim nes --board pai-touch --instance nes
```

指定 PAI Touch 时使用实际发现的 USB 串口；先确认设备已解锁。

```sh
python3 tools/pxadb/pxadb.py package install local/app-output/pai-touch/pxa-nes.pxa --port /dev/ttyACM1 --yes
python3 tools/pxadb/pxadb.py package stop pxa-nes --port /dev/ttyACM1
python3 tools/pxadb/pxadb.py package run pxa-nes --port /dev/ttyACM1
```

更新正在运行的应用后需要 stop/run 才会切换到新代码。构建 ESP32-S31 时将目标改为 `esp32s31`，不能安装 ESP32-S3 的 AOT。

0.1.35（release 41）不再附带 ROM，也不显示“内置”来源。启动与刷新时扫描存储和 SD 媒体目录，只显示找到 `.nes` 的来源；两边均为空时显示目录说明。游戏库支持拖动滚动和手柄逐行滚动，不再使用上一页/下一页。暂停菜单也可滚动，新增“即时存档”和“退出模拟器”；退出先等待正在写入的电池存档完成，再使用 Host 的正常返回/停止流程。

0.1.36（release 42）加入签名作者描述并在启动时通过 FS 0.4 查询实际 SD 显示路径，移除界面内写死的 AppKey。此版本要求带 `app-media-path` 特性的 FS 0.4 Host；查询不在游戏帧循环中执行。应用身份、游戏内核与存档格式保持一致。

即时存档位于应用私有目录 `states/`，每次“新增存档”生成独立文件，读取列表项可恢复进度。应用不设置存档数量上限；实际数量受文件系统空间约束。列表仅缓存 32 个文件名，滚动越过缓存后继续枚举，避免为全部存档常驻分配内存。读写、校验和状态复制只在暂停时执行；写入临时文件后原子重命名，不覆盖已有存档。文件包含格式/布局版本、ROM 校验值及内容 CRC，验证通过前不改变当前机器状态。原来的 `nes-<crc>.sav` 电池存档继续使用。恢复状态时保留当前运行环境的绘图选项、音频配置和查找表，避免由存档改变前端配置。

即时存档保存 CPU/PPU/APU、内存、分页、输入锁存和 Mapper 状态，清除声音队列并重建绘图缓存后恢复。当前格式要求相同核心布局，不是通用 SNSS；缺少状态回调的复杂 Mapper 和外挂音源暂不启用保存，避免假保存。已对用户提供的 Mapper 0/1/2/4/7/23/74/241 游戏做保存、重放、重新加载 ROM 后恢复以及损坏文件拒绝测试。存档列出的日期来自 Guest 时钟。

0.1.34（release 40）重做游戏库和暂停菜单：跟随系统 i18n，支持已识别游戏的中英文名称、页码与清晰的手柄选中状态。支持 UI 0.6 `sized-text` 的主机使用系统字体、统一基线和抗锯齿文字，按分辨率与 DPI 排版，字号限定为 12 种以适应主机字体缓存上限。菜单只在状态改变时提交；开始或恢复游戏时移除 Canvas 节点，恢复透明输入根节点，游戏期间没有菜单文字绘制。核心帧计算、显示提交、文件操作和系统菜单保持独立的函数边界，避免菜单扩展把大栈帧和额外局部状态合并进模拟循环。进入系统字体菜单时隐藏 Surface 游戏画面层，恢复游戏时再显示，避免实机直刷的最后一帧挡住菜单；只在状态切换时配置图层。备用小字库修正了“一”等短汉字因逐字顶对齐而偏高的问题。

菜单读取 Host 的安全区、圆形/圆角屏幕几何；游戏视口和触摸按键使用预先计算的安全矩形。圆屏采用内接矩形，圆角屏结合四角半径和安全边距，保留 NES 原始宽高比与黑边，不增加游戏帧内的逐像素形状裁剪。当前应用 Surface 支持 200–800 像素宽、160–480 像素高。旧主机未报告的物理遮挡无法由应用自行推断；无系统字号接口时保留位图菜单。

性能路径：在原有绝对自跳转之外，对实时映射允许的 `LDA/LDX/LDY zp; BEQ/BNE -4` 等待循环合并完整迭代，最后不足一次迭代的部分仍由解释器执行，保留寄存器、周期余数和 IRQ/NMI 边界。PPU 背景绘制在同一名称表区间复用页指针，水平跨表和 Mapper 锁存回调后刷新，CHR 数据继续实时读取。音频队列即将溢出时先重试写入 Host，避免在主机已腾出空间时仍丢旧采样；缓冲大小与正常路径的写入次数不增加。新增 Mapper 241。这些优化保留现有 Host 双核绘制、PCM 输出与 LCD 传输路径，未增加帧缓冲或改变固定 4 MiB 线性内存。

0.1.32（release 38）减少 6502 的空等开销：利用 NMI 发生时已有的 CPU 程序计数器和上一帧实际命中的空等，选择两套直接调用的扫描线循环；避免只检查帧入口漏掉帧中等待，同时不给普通扫描线循环添加探测。历史中断地址只提供提示，每个加速片段仍核对当前实时状态；读取任何指令字节前先检查当前页映射，以支持中断后的银行解除映射。显式保持 WASM LTO 对 PPU 扫描线、APU 混音和 NMI 热函数的内联，避免新增调用点使编译器撤销原有内联；两套帧函数保持独立，限制普通路径的控制流复杂度。在加速路径的 CPU 执行片段入口发现无副作用的绝对 `JMP` 自跳转时，把当前预算内的三周期重复批量计入。待处理的 IRQ 和 DMA 等待仍进入原路径；普通指令循环保持为独立函数。普通总线访问保留已验证的实现。保留最后一条指令的周期余数；扫描线、Mapper、APU 和 IRQ/NMI 的调用边界不变。只对经过实时映射、读处理器和指令字节检查的普通 RAM/ROM 启用，不按游戏名称或固定 ROM 地址启用，也不跳过轮询 I/O 的循环。`NES_REFERENCE_IDLE=1` 可回退原路径，`nes_cpu_idle_{optimized,reference}` 对照周期边界、DMA 等待、跨页、访存副作用、银行切换和中断。此优化不增加帧缓冲，不改变 50/60Hz 制式和模拟时间债务。 绘制调度保留小数间隔，通过轮流跳过不同数量的画面分配预算，避免需求从 2.00 帧轻微变为 2.01 帧时直接把屏幕更新降到每 3 帧一次。CPU/APU 时钟、10% 预算余量、积压反馈和手动绘制间隔继续保留；Surface 背压不会积累一串补画请求。在实际发生背压且预算接近两帧一画时，收紧到稳定的两帧间隔，减少缓冲归还事件尚未处理时的连续重试；更快场景自动退出该限制。反馈仅在一秒内的最低积压仍超过两帧时增加，避免批次入口的短暂峰值触发额外跳帧。历史积压即使不再增长，也会暂时降低绘图频率，让 CPU/APU 实际追赶完成后再恢复，不直接清零时间债务。

实机测试应使用独立的应用 ID 和对应 i18n namespace。自动进入新游戏也可能修改 SRAM，不能用用户的正式应用身份反复做破坏进度的测试。正式包继续保留原 ID 和签名，测试包的数据与正式存档隔离。

0.1.29（交付 release 35，代码与测试 release 33 相同）在支持 GameRender 1.3 的 Host 上使用 `BLIT_INDEXED_RECT`：按源/目标矩形直接采样 INDEX8，原生转换 RGB565 并写入已获取的映射 Surface，256×240 原尺寸不会经过旧接口的 320×240 中间采样网格。手柄隐藏悬浮按键时启用；显示触摸按键或 GameRender 1.0–1.2 不支持新操作时自动使用原有渲染器。安装包要求至少 GameRender 1.0，仍提供 0.x 服务的旧固件需要先更新。Host 可把目标范围分给两个核心，调用返回前完成全部写入；不额外复制源图或调色板。LCD 输出仍使用主机已有的缓冲和 DMA 路径。DOIT GameKit-1 固件把显示准备和 PCM 输出放在 CPU0，与 CPU1 的下一帧模拟重叠；Host 按 32ms 时间预算让出 CPU，避免每条短命令后都休眠。

详细扫描线采样默认关闭（`NES_PROFILE=0`）。启用后会输出 `NES PHASE`，但频繁的时钟导入本身有显著开销，不能将其时间当作无扰动 CPU/PPU 耗时，也不能用该版本验收最终帧率。常规 `NES PERF` / `CORE` / `SCHED` / `RASTER` 保留，按卡带的 PAL/NTSC 目标分别验收。

0.1.27（release 31）在 Korvo 使用与面板相同的 800×480 映射 Surface，游戏原始 256×240 像素居中显示，四周留黑边。Host 不再为它执行 2 倍 CPU 放大，可使用已有的不缩放呈现路径。黑边在缓冲失效时清零，之后仅更新变化的游戏图块和按键；菜单仍以原来的物理大小显示，按键命中位置、UI 密度转换、系统 i18n 与手柄自动隐藏继续保留。小于 NES 原始画面的面板仍使用保持比例的最近邻缩小。

自动绘制频率使用实际绘图/跳帧耗时和模拟积压的变化调整，不再因为积压达到两帧就进入固定约 4fps 的模式。模拟时间债务不清零、不丢 CPU/APU 帧；极端负载下，默认最多约 200ms 就会再次尝试绘制，实际完成仍受内核耗时和 Surface 背压影响。用户指定的绘制间隔仍作为下限。`NES SCHED` 记录主动跳过、缓冲等待、自动间隔、耗时估计及 `sound` 状态。实机脚本新增 `--require-audio`，用每个采样窗口的日志确认声音开启，而不是只读取安装包版本或菜单上的历史状态。

按键缓存记录每个按钮及其文字的实际包围框和覆盖图块。按下 A 时只更新 A 的反馈，不再扫描整条按键带或重绘菜单按钮下面的游戏区域。缓存/完整绘制的独立逐像素对照覆盖六种尺寸、两个输出缓冲和三种源对齐，共 9,360 帧。固定线性内存仍是 4MiB；800×480 双缓冲占用 1,536,000 字节，比此前实际注册的 400×240 双缓冲多 1,152,000 字节，减少了 Guest 内部可用堆空间。3MiB 是 ROM 格式准入上限，实际可加载大小还取决于画布和 Mapper 的 RAM 需求。


0.1.24（release 28）增加 Korvo 800×480 屏幕支持：Guest 绘制 400×240，宿主 Surface 按整数 2 倍显示到面板；游戏内容保持 256:240 比例，居中显示为 512×480，两侧各留 144 像素黑边。UI 触摸事件使用 dp，先乘环境提供的 `density_q16` 转为面板像素，再除以 2 参与命中判断；环境变化时同步更新密度。双缓冲与按键覆盖图的最大宽度扩至 400，固定 4 MiB 线性内存保持不变。PAI Touch 和 GameKit 继续使用原分辨率。此版本保留 0.1.23 的 PPU 内核优化。

0.1.23 的 PPU 背景路径用 4 KiB 调色板查找表一次生成四个像素；仍实时读取 CHR 位平面，避免缓存图块地址导致切换图形银行后取错图。每条扫描线检查背景调色板，变化后重建对应表。精灵用 1,920 字节扫描线成员掩码，按原 OAM 顺序访问可见精灵；OAM 写入、DMA、精灵高度改变和重置均使索引失效。帧中途修改 OAM 时回退原扫描，到下一帧第 0 行才重建索引，避免特殊游戏逐行重建。保持原 Sprite 0、每行精灵上限、透明与优先级判断。Guest 默认带 `-fno-builtin`，小型固定长度拷贝显式使用 `__builtin_memcpy`，覆盖背景查表和 RGB565 像素对写入，避免热点里调用通用字节拷贝。新增静态数据约 6 KiB，不增加整帧缓冲；原绘制路径可用 `NES_REFERENCE_PPU=1` 编译，以便逐帧对照。

原生构建还提供 `nes_ppu_kernel_test` 和 `nes_ppu_trace_{optimized,reference}`。前者穷举位平面、调色板和对齐并检查索引失效；后者接受 `ROM [frames=1200] [draw_interval=1]`，输出每帧 CPU/RAM/PPU/视频/PCM 签名及单独的绘图/跳帧计时。比较 stdout，stderr 的墙钟计时不参与签名。ROM 对照只说明保留原内核行为，不代表原内核通过所有硬件时序测试。

菜单支持一号、二号手柄：首行向上进入顶部存储来源，左右或 L/R 切换，A/Start 确认、B 返回、Y 刷新；方向长按连续移动。GameKit 固件需支持 Canvas 菜单的 controller 订阅路由。

## ROM 放置位置

入口有两种来源（空来源自动隐藏）：

- **FLASH**：应用私有文件系统内的 `roms/` 目录。主机允许的文件管理工具可向此目录复制文件；部分旧固件禁止 PXADB 写私有目录，此时建议使用 SD 卡媒体目录。
- **SD**：主机选定的只读应用媒体根，统一使用 `/PXA/media/<作者>/<应用>/`；例如 `/PXA/media/lucinhu/pxa-nes/`。重名作者可能带短指纹后缀，具体路径由 FS 0.4 查询返回。将 `.nes` 直接放在该目录（无需再建 `roms/` 子目录）。固件不再生成、扫描或迁移旧的 AppKey 长目录。

桌面产品模拟器的媒体目录仍为实例状态根下的 `media/<AppKey>/`，FS 0.4 查询返回模拟器实际位置；flash 私有目录为 `private-files/<publisher>-pxa-nes/roms/`。历史 PAI Touch 测试固件只有 FS 0.2，需要升级 Host 后才能安装 0.1.36；0.1.35 及以前的兼容性以各版本要求为准。

当前只枚举单层目录，每个来源最多 128 个 ROM，单文件上限 3 MiB；iNES trainer 支持加载到 $7000；不支持压缩包、NES 2.0、FDS、NSF、VS/PlayChoice。私有 FS 文件名受主机 64 字节段长限制。文件读取支持 UTF-8；系统文字菜单的字形覆盖取决于主机字库，备用位图菜单仅嵌入中英文 UI 所需的字符。不要打包无分发授权的 ROM。

## 操作、声音和存档

游戏保留完整的 256×240 内容，在主机报告的安全矩形中按原比例居中，必要时最近邻缩小，允许黑边；无额外安全边距的 296×240 矩形画布中，两侧各留 20 像素黑边。左侧是十字方向键，支持单指斜向操作并保留中心死区；右侧斜排 A/B，中间放置 SELECT、START、MENU。按钮以简洁的圆角半透明样式覆盖在游戏画面上，在安全矩形底部再预留触摸手势空间。悬浮按键固定使用自建 ASCII 字形与方向符号，SELECT / START / MENU 不翻译；仅布局变化时生成覆盖图，游戏帧内不调用系统字体或绘制文字。

暂停菜单的 KEYS 按钮循环切换底色不透明度：38% → 25% → 63% → 隐藏。文字和描边比底色更清楚，按住时加深反馈；按钮之间及其余画面保持原始游戏颜色。手动隐藏后触控按键停用，可用系统返回键或手柄 X 打开暂停菜单恢复。触摸支持主机提供的多个指针。

手柄使用 PXA 标准 controller-state 事件，支持两位玩家的方向、A/B、START/SELECT。收到实际按键操作才自动隐藏悬浮按键，连接后的空闲状态不会隐藏；松开仍保持隐藏。再次触摸屏幕会恢复原来选择的透明度，第一下只用于恢复；全部手柄断开后也自动恢复。手动选择的“隐藏”设置仍保留。

0.1.37/r43 起，游戏库和即时存档页的底部按钮也可用手柄聚焦。方向键上下移动，列表末尾继续向下进入底部；底部左右选择按钮，上键返回列表。A 确认，B 返回（游戏库中为退出），Y 刷新游戏库；存档页空列表默认选中“新增存档”，X 快捷新增。方向键按住 350 毫秒后，每 90 毫秒移动一项，仅在菜单运行；切后台、断连或触摸操作后停止重复。第二个手柄保留游戏输入，菜单方向焦点只由第一手柄控制。焦点用高亮显示，确认菜单按钮的输入不会传入游戏。

手柄 X 暂停/继续；暂停菜单用上/下选择、A 确认，B 或 START 继续；ROM 库用左/右切换有游戏的存储来源，上/下选择游戏，A 或 START 加载，无需触摸屏。桌面方向键移动，Z=A、X=B、A=手柄 X、Enter=START、Tab=SELECT；SDL 手柄左摇杆由宿主转换为数字方向。START+SELECT 也可暂停，但 **DOIT GameKit 会把这一组合保留给系统桌面，应该使用 X 暂停**。

实体按键、蓝牙或 USB 输入需要设备固件提供 PXA 手柄事件；本应用不自带蓝牙/USB 驱动。DOIT GameKit 的实体按键有此上报路径，旧版 PAI Touch 固件只有触控路径。

透明混合采用预计算 RGB565 查找表，只在按钮所在的行读取覆盖图，无逐像素除法；每次都从 NES 原始像素合成，避免反复混合导致颜色累积变暗。新版本新增约 104 KiB 静态覆盖图和颜色表，仍使用固定 4 MiB 线性内存。

0.1.18 按源图像的 8×8 像素块检测变化，仅为发生变化的块重新执行调色板转换、等比例缩放和按键合成。每个 Surface 缓冲分别累计失效块，因此两个缓冲交替使用及画面变化后恢复原样时也不会留下旧像素。按键按下、透明度变化、手柄自动隐藏和暂停恢复都会使对应区域失效。历史图像用 61,440 字节，放在预留 Surface 数组的未使用尾部；0.1.24 中 296×240、320×240、320×320 和 400×240 均有足够尾部空间，最大 400×320 画布空间不足时自动完整重绘。检测仍需要读取源图像，卷轴滚动时收益取决于实际变化范围。

Surface 使用 `GUEST_MAPPED | PREFER_DIRECT_SCANOUT`：注册两个 Guest RGB565 缓冲后，提交只发送缓冲索引和帧 ID，不复制整帧到 Host。宿主在满足条件时可绕过 LVGL 合成；PAI Touch 的直刷路径仍需要旋转、面板布局转换及可能的 DMA 暂存。完整帧的提交协议和 LCD 传输没有因局部重绘而变成局部传输，不能把这称为端到端零拷贝。

0.1.19 将脏标记压成每缓冲 30 个 32 位位图，相邻变化块合并为连续行段；已经全部失效的区域不再重复逐块判断。64 位对齐比较保留 4 字节及非对齐回退，控件区成对写入 RGB565，并取消游戏完整重绘前多余的整帧清零。元数据减少 2,528 字节。内核对没有读处理器的实时映射页直接读取；低地址 OAM DMA 批量复制保留目标回绕及原停顿计数，特殊映射和读副作用仍走原总线。原始实现由参考目标保留作差分验证。

暂停菜单可选择显示每 1/2/3/4 个模拟帧提交一次；模拟 CPU、PPU 状态和 APU 继续运行。Clock 0.2 旧主机默认每 4 个模拟帧绘制一次，为模拟速度预留余量；成功协商 8 ms 计时的新主机默认每帧尝试绘制。缓冲忙碌时继续自动跳帧。后台暂停并清除输入，恢复时重新建立计时基准。

单次回调使用 24 ms 计算预算（在完整帧后检查），最多追赶 4 帧，避免复杂 ROM 的一帧计算超过旧 12 ms 预算后始终无法追上计时。模拟时间不丢弃；负载超过设备能力时会在 `debt_frames` 中体现。

0.1.24 及以前在积压两帧以上时最多每 250 ms 尝试绘制一帧；0.1.27 已用上文的耗时预算和积压变化反馈替换此策略。

0.1.22 通过 PXA i18n 读取系统语言，中英文目录在构建时编译；启动配置和系统语言变更事件会刷新菜单与游戏名，无应用独立语言开关或语言配置文件。`i18n/messages.yaml` 为英文源目录，中文目录提供 `zh-CN` 和 `zh` 父级回退，其他语言回退英文。显示间隔和透明度采用具名数字占位符。0.1.34 起悬浮按键改用固定英文，覆盖图仅在初始化或布局变更时重新生成，不逐游戏帧处理字体；4 MiB 固定线性内存保持不变。应用图标的 SVG 源稿和 192×192 PNG 位于 `assets/icon.*`，启动器名称和说明同样使用 i18n 元数据。

声音按钮显示关闭、开启中、已开启或失败，可点击开关及重试。点“继续游戏”后才恢复游戏声音。声音需要主机授予可选的 `audio.playback` 权限。拒绝声音不影响运行。输出为 16 kHz 单声道 S16 PCM，每帧采样数量保留分数余量，避免每秒少 40 个样本。256 ms 的 Guest 环形缓冲保留未写完的数据，并在宿主队列恢复后重试；超出容量时才舍弃最旧采样并计入统计。硬件听感和延迟须另行测量。

电池 RAM 按 ROM 内容 CRC 存到私有目录 `nes-<crc>.sav`，在暂停和进入后台时触发；先写临时文件再原子替换。游戏运行时不定时写 flash，以免旧固件的闪存操作阻塞模拟。退出前先暂停，等待 SAVING 提示消失；硬停止可能丢失尚未落盘的进度。即时存档与电池存档分开管理，可从暂停菜单保存或读取。

## 测量和回归

每五秒通过日志输出 `NES PERF`，版本由包元数据生成；结合独立的 `NES ROM` CRC/目标频率记录、单调时间戳、实际完成的 `frames` 和墙钟 `elapsed_us`。帧率由完成帧数除以真实单调时间计算，不采用定时器事件数。测量器直接订阅这些日志，窗口内不读写 flash；历史 `nes-perf.txt` 不再更新或作为验收来源。

- `sim_x100`：真正执行的模拟帧率 ×100。
- `submit_x100`：成功提交给 Surface 的帧率 ×100，不能当成 LCD 实际完成刷新率。
- `cpu_avg_us`：NES 内核每帧平均墙钟耗时，不含缩放和显示提交；可能包含宿主抢占。
- `NES CORE draw_avg_us` / `skip_avg_us`：分别记录生成视频帧与跳过视频输出的内核调用平均墙钟耗时，避免总平均值掩盖 PPU 绘图成本。
- `scan_avg_us`：每帧 CPU/PPU 扫描线处理时间，可和 `cpu_avg_us` 区分 APU 开销。
- `skipped`：当前窗口未渲染的模拟帧数。
- `debt_frames`：尚未追上的模拟时间；持续增长说明设备算力不足。
- `audio_drop`：音频队列未接收的采样数。
- `paint_avg_us`：每个实际绘制帧的缩放和按键合成平均用时，不包含 Surface 提交调用。
- `paint_px_avg`：每个绘制帧实际写入的 RGB565 像素数，296×240 全屏为 71,040；局部更新会减少此值。
- `keys_alpha`：按键底色不透明度的八分之一单位，默认 3（37.5%），0 为隐藏。

`NES DISPLAY` 另记录 Surface 的累计 `submitted`、`consumed`、`replaced` 和空闲缓冲数。`consumed` 表示宿主使用并释放 Guest 缓冲，旋转复制结束即可发生，仍不代表 LCD DMA 完成。支持 `PERF START display` 的固件可在 `PERF STOP` 返回 `display=1` 后，用 `completed * 1e6 / window_us` 计算面板全帧传输完成频率；它也不等于面板内部扫描频率或光学测量。测量过程中不要截图或读取 flash。



默认使用 FirebrandX Composite Direct 的 64 色调色板。颜色验证可以使用 FCEUX 2.6.6 加载同名 `Composite_Direct_FBX.pal`，用 `gui.gdscreenshot(true)` 保存 256×240 参考帧，再运行 `tests/compare_colors.py` 比较游戏区域。工具比较编码后的 RGB565，兼容实机与桌面 PNG 对 5/6 位通道扩展时相差 1 个 RGB8 单位的情况；静态画面和相同调色板是比较前提。实机顶部 FPS 遮罩可用 `--ignore-top 20` 排除。

全屏验证的 `--area` 为 `0 0 296 240`。可以先隐藏按键采集原始颜色；显示按键时，用重复的 `--ignore-rect X Y W H` 排除控件区域。桌面截图另用 `--corner-radius 58` 排除面板圆角、`--ignore-rect 120 231 56 4` 排除宿主手势提示条。

```sh
python3 local/pxa-apps/nes/tests/validate.py --output local/nes-test --download
python3 local/pxa-apps/nes/tests/validate.py --output local/nes-asan --sanitize
cmake -S local/pxa-apps/nes -B local/nes-controls -DNES_NATIVE_TEST=ON
cmake --build local/nes-controls --target nes_controls_test

local/nes-controls/nes_bus_dma_test local/nes-controls/demo.nes
# 先在已解锁的 PAI Touch 上进入测试 ROM，再执行：

```

跳帧优化对照原始精灵扫描实现，比对 CPU、RAM 和视频 CRC；25 个用例（含 PAL、trainer）的签名必须相同。

`nes_video_test` 将局部重绘和独立的完整重绘逐像素比较，覆盖六种尺寸（含 400×240、800×480 原生像素黑边）、有无缓存、两个缓冲、变化抵消、按键状态和暂停后失效，以及 8/4/1 字节对齐输入，共 9,360 帧。`nes_bus_dma_test` 检查 144 个 DMA 用例及实时 ROM/SRAM 读处理器；对应原生测试可使用 AddressSanitizer / UndefinedBehaviorSanitizer 检查。

回归覆盖 16 组 Blargg 独立指令 ROM、NROM/MMC1/UxROM/CNROM/MMC3/AxROM/GxROM 启动和输入、计时余量、音频采样数、ROM 截断和格式拒绝。Mapper 测试为自行生成的简单程序，不代表完整商业游戏验收。组合版 `official_only.nes` 目前仍未通过，不应把独立测试通过扩展成整个测试库通过。

## 0.1.21 中文界面与映射帧保留

菜单及悬浮按键使用约 4.4 KiB 的 Noto Sans CJK SC 点阵子集，授权与来源见 `licenses/ui-font-OFL.txt`、`ui_font_data.inc`。字库离线生成；菜单按需绘制，按键文字只在覆盖图初始化时绘制。游戏帧仍通过原查找表合成，没有逐帧 UTF-8 排版、字体加载或新帧缓冲。未知汉字显示方框；当前字库覆盖菜单、马里奥及重装机兵的友好名称，不是完整 CJK 字库。可通过 `python3 tests/make_ui_font.py --font /path/to/NotoSansCJK-Regular.ttc --index 2` 重新生成。

新的变化检测候选默认不启用，需编译定义 `NES_EXPERIMENTAL_TILE_SCAN`。候选按 8 行区域维护尚需检查的图块，已经对两个输出缓冲累计失效的块不重复比较；历史像素仍更新，避免变化抵消或换缓冲后残影。电脑原生微基准出现收益与回退且受并发负载影响，不能证明 ESP32-S3 或 LCD FPS 提升；0.1.21 交付使用已验证的 0.1.19 检测路径，保留候选供后续同机对照。

实机音量条白屏涉及宿主：旧 ESP 后端在消费映射帧后立即将其归还应用，单独重绘系统浮层时可能没有可用的游戏底图。固件修正保留当前映射帧，替换帧开始消费时才归还旧缓冲，让应用可并行绘制下一帧；不增加像素拷贝或帧缓存，但减少了空闲缓冲数量，实际吞吐变化须实测。只更新 `.pxa` 不会修复旧固件。宿主回归涵盖无新 Guest 提交的重复浮层重绘、两缓冲连续替换及旧帧归还顺序。

历史测试包 `local/nes-work/metal-play-20261020/package/pxa-nes.pxa`（0.1.19 / release 21）曾包含用户提供的重装机兵和马里奥。0.1.35 起发布包与源目录均不附带游戏，连诊断 ROM 也不随包安装；已有游戏保存在应用私有 `roms/` 或 SD 媒体目录。0.1.21 / release 23 的旧候选包及固件位于 `local/nes-work/opt3-20261020`，仅供历史验证记录参考。

当前前端和内核仍使用 C Guest SDK。C++ 前端可以保留 C NES 内核并使用相同的 GuestMapped Surface；切换语言本身不会消除 PPU 绘制、旋转或面板传输成本，性能需同路径同场景实测。
