# Game-render 扫描线优化与真机验收（2026-10-15）

本轮采用不增加工作内存的扫描线优化。Watcher 相同存档、相机、画质和视距的 Voxel
固定画面初轮和回测分别约提高 **3.2% / 2.0%**，四轮 v4 的 FPS 均值增益为 **2.57%**。
初轮 Host 光栅平均耗时降低 **4.35%**，回测仍有改善，但收益存在波动。
收益有限，仍未达到 30 FPS；Jump 保持约 33 FPS 静止、30 FPS 跳跃。
未改变分辨率、树叶透明孔洞、深度遮挡、透视修正、游戏逻辑、蓄力公式或音频。
完整测量见 [measurements.json](game-render-20261015/measurements.json)，
[代码和固件来源](game-render-20261015/provenance.json)。

## 相同负载与测量方式

Watcher：ESP32-S3，MAC `8c:bf:ea:09:af:6c`，412×412 RGB565、圆屏、284 DPI、40 MHz QSPI。
使用稳定 USB by-id 路径和 2,000,000 baud；每次先校验芯片身份和已安装 manifest SHA256。
不按 `/dev/ttyACM` 编号判断设备。每个场景重启应用，预热后测量 4 秒，重复两轮；截图在计时窗口之外。
FPS 来自不同帧的**面板 DMA 完成间隔**，并非提交 FPS，也没有测量 LCD 光学扫描速率。
保留整窗口 FPS 和活跃帧间隔 FPS，避免把结果页停止绘制误认为低光栅性能。

Voxel 为正式 0.12.4/release 17 AOT 包，SHA256
`f4abaf8c522c836d48daa8c2b9430c2963788197cc29ed28ead8039a7a8504d6`。
首次随机新游戏混入时钟，不能跨启动比较，早期随机场景只作为功能检查。
最终每次加载同一 Slot 1：种子 `3646175235`、世界 hash `2893106422`、
相机 `(32.5,17.0008506775,32.5)`、yaw/pitch 0、固定视距 32、q0、
原生 412×412、正常物理和音效、`VOXEL_CHEAP_PATHS=0`。
[98,492 B 存档](game-render-20261015/fixed-save.bin)和[元数据](game-render-20261015/fixed-save.json)保留为复现夹具。
固定画面命令 23,752 B、覆盖像素 250,037，前后相同。

Jump 为同一正式 0.1.5 AOT 包，SHA256
`da5dc9757979f2a164db7ff94b8ec4a6c95388ae69bedde7743e898fc58376cb`，
静止预热 2 秒，注入蓄力请求 0.68 秒；实际设备按下至松开的时间还包含 UART/SYNC 等待。
动画轨迹和音频临时资源可能因此略有差异，不能将跳跃小幅差异全归于内核。

冻结原版 raster 源码，以相同编译参数替换候选固件私有 archive 中唯一的 raster 对象，
其他对象和链接选项一致；避免同时进行的工作区修改污染 A/B。
先后完成原内核、v2、v3、v4、冷启动原内核回测、v4 固定视角复测。
下表使用最后一次原内核冷启动回测与 v4，均在重启固件后先跑六轮 Voxel，再跑四轮 Jump。
[固件 hash、静态 section](game-render-20261015/firmware.json)与原始分轮报告附在同目录。

## 实测性能与延迟

| Voxel 场景 | 原内核 DMA FPS | v4 DMA FPS | Host 光栅 ms |
| --- | ---: | ---: | ---: |
| idle | 9.930 | 10.247 | 70.680 → 67.603 |
| turn | 9.108 | 9.446 | 75.885 → 72.249 |
| walk | 8.655 | 8.900 | 79.840 → 76.454 |

`idle` 是严格相同的负载。转向、行走虽然复用起点和注入流程，帧率影响输入采样和物理步进，
最终视角、面数会变化，只作为操作体验观察，不能作为等工作量加速率。
后续 v4 固定视角复测见 [span-v4-recheck-voxel.json](game-render-20261015/span-v4-recheck-voxel.json)。

| Jump 场景 | 原内核 DMA FPS | v4 DMA FPS | Host 光栅 ms |
| --- | ---: | ---: | ---: |
| idle | 33.541 | 33.630 | 19.900 → 19.796 |
| charge | 30.216 | 30.317 | 21.206 → 21.048 |

分项实测覆盖 Host 光栅墙钟时间、独立 DMA 完成间隔、输入采样至 Guest 回调、关联提交和 DMA 完成。
逐轮延迟与样本数保存在原始 JSON。低帧率 Voxel 仍有明显操作延迟；这些短测的 P95 波动
不足以支持“延迟全面降低”的结论。软件关联延迟不包含物理触控控制器和光学响应。
本轮没有新增 Guest 更新、几何生成、命令编码各自的真机计时点；
也没有将 DMA 间隔减去光栅耗时冒充这些阶段或排队时间。

Pai-touch ACM3 和 Korvo USB0 已核对芯片身份并测量现有 Jump：
前者 0.1.3、296×240，静止约 37.49 FPS、跳跃约 34.60 FPS；
后者 0.1.4、800×480，静止约 36.97 FPS、跳跃约 34.69 FPS。
两者未被本轮刷写；不同版本、屏幕和工作量不能用于宣称新内核跨板收益。
Korvo 新内核仅完成实际工具链编译和 IRAM 符号尺寸检查，仍需完整固件真机 A/B。

## 采用的优化与取舍

| 改动 | 原因与收益 | 内存与验证 |
| --- | --- | --- |
| 分离不透明 / cutout 深度循环 | 材质条件在扫描线级选择，不透明可见像素不再逐像素判断透明索引 | 无分配；透明索引 0 不写颜色或深度，保留叶片孔洞 |
| 扫描线预缩放 V 与步长 | 将乘纹理宽度、可变移位移出像素循环，像素内用常量移位和掩码取行 | 无查找表；无符号环绕等价，覆盖 1～256 的二次幂纹理 |
| 端点证明深度范围，冷分支独立 | 常见扫描线只做深度比较；少见越界路径使用 64 位插值，避免整数溢出 | 冷函数不挤占可选 IRAM 热函数；极值 oracle/UBSan 通过 |
| 带深度纯色专用扫描线 | 纯色面无需纹理坐标、调色板访存或每像素范围钳制 | 不增缓存；颜色与深度逐像素对照通过 |
| 数值边界修正 | 使用无符号步进处理最后像素后的未使用增量；越界深度不再有有符号累加溢出 | 6,000 个独立 oracle 用例、哨兵、空 span、相等深度、极值步长通过 |
| 8 MiB 应用文件配额 | Watcher/Korvo 的 64 KiB 默认配额不足以保存 98 KiB 世界；Watcher 已真实保存、重复加载 | 仅磁盘逻辑配额，不预分配 RAM；Korvo 配置已改，尚未刷写验证 |

最初 v1 扩大了 S31 热函数 IRAM（314 → 466 B），不满足内存约束，未采用。
v2 抽出冷分支后为 306 B，但 Watcher 固定负载增益较小；v3 简化索引，v4 再将 V 预缩放。
最终 S31 热函数 **312 B**，小于原来的 314 B；这是编译尺寸结果，不能当作 S31 实测加速。

本轮没有新增 SIMD / 汇编光栅内核。既有 S3 送屏字节交换 SIMD 保留，不能重复计为本轮收益。
带深度纹理路径包含条件深度写入和离散纹理 / 调色板读取，先采用能共享到不同芯片、
可逐像素验证且有实测收益的 C 内核。新的向量深度掩码、汇编或更大缓存仍需独立 A/B；不作为已实现能力。

## 内存与画面

单位 B。稳态取各匹配场景窗口中的最坏当前占用；峰值使用 `MEMORY START/STOP`
本次窗口 minima，启动窗口与游戏窗口分开。历史累计 budget peak 仅保留作诊断。
首次冷启动会有额外一次性资源和映射临时量，不能与已经初始化的热启动直接比较。
最后一次 v4 冷启动复测的 Voxel SRAM / PSRAM 真峰值为 **516,240 / 4,780,180 B**，
对应冷启动原版为 **516,240 / 4,780,324 B**；均包含首次临时开销。

整机 heap 含系统 UI、音频及后台资源，少量波动和音频临时对象不归为 raster 节省。
整轮启动与游戏观测到的最高峰值前后未增加，但不能据此保证每个短操作窗口均更低。
v4 的一次 Voxel 行走窗口峰值比冷启动回测原版多 260 B SRAM / 4,680 B PSRAM；
一次 Jump 碰撞多加载 18,912 B 音频资源，导致该轮当前占用和游戏窗口峰值更高。
同一 PXA 音频分项从 138,264 → 157,176 B，与光栅内核无分配无关；旧原版
`control-jump` 的相同音频状态也已出现，完整数据保留，不能把不同音频状态当作等内存负载。
这些波动没有被从表中删除，也不宣称本轮减少了整机内存。
内核本身没有增加静态数据、动态分配、Surface、深度缓冲、队列或 Guest 内存。
Watcher 静态 IRAM text **121,275 B**、DRAM data **33,064 B**、DRAM bss **17,472 B** 均相同；
flash text 2,569,308 → 2,569,980 B（+672 B），64 KiB 映射页边界和静态 PSRAM bss 不变。
代码存储略增，运行时映射容量没有增加。

Voxel 双 RGB565 Surface **678,976 B**、R16 depth **339,488 B**、同步借用 mailbox **0 B**；
Guest 线性内存 **393,216 B**、AOT 映射 **655,360 B**（文件 request 627,076 B）；

mailbox **49,152 B**，Guest 线性内存 **131,072 B**、AOT 映射 **524,288 B**

这些项目已包含在整机占用里，不能再次相加。所有固定容量前后相同。

## 验证与复现

[validation.json](game-render-20261015/validation.json)记录原生、模拟器和设备验证。
原生 core 最终 4/4、Jump/SDK 12/12、Voxel ASan 套件（32 种子、3062 棵有根树、
区块预算、零帧分配、有限背包 / 合成 / 工具 / 材质音效 / UV / DPI）通过；
Watcher LCD IO / compositor ASan 通过；模拟器实际 AOT 两游戏进入并操作，最终 raster 回归通过。
真机有重复启动、固定视角、行走与转向、菜单和后台切换、挖掘 / 编辑后重建与重新加载检查。
PXADB 错误身份和错误 manifest 的负向检查均在实际 Korvo 上验证，未发应用 / 输入命令。

复现时先构建两版仅 raster 对象不同的固件，核对设备身份、备份现有应用分区，保留数据分区。
校验上述应用包 SHA256。用空存档槽创建一次世界，关闭自动视距并固定 32，
之后两版固件始终加载同一存档；若使用附件夹具，必须先备份该应用的整个私有数据，
仅在专用测试数据目录或空槽恢复，不能直接覆盖已有世界。
在 workspace 根目录运行（替换 PORT、PACKAGE、OUT）：

```sh
PXADB_BAUD=2000000 python3 tools/measure-device-gameplay.py \
  --port PORT --expected-serial 8c:bf:ea:09:af:6c \
  --app pxa-voxel-craft --package PACKAGE --output OUT \
  --repeat 2 --warmup 6 --seconds 4 --size 412 412 \
  --prepare-tap 206 258 --start 206 165 --scenes idle turn walk
```

Jump 同工具使用 `--app pxa-jump-jump-3d --warmup 2 --scenes idle charge --charge-seconds .68`，
不传 `--prepare-tap/--start`。每次场景重新启动，不能连续行走后再把下一场当作固定视角。
本轮新建了原本为空的 Slot 1 测试存档，原有应用与数据保留；自动视距临时设置在测试后恢复。
冻结固件、完整串口日志和构建产物保留在 workspace `local/game-render-opt-20261014/`。
本报告没有将旧 C 游戏、不同版本或不同地图当作语言性能对照，也未证明所有芯片和场景都加速。
