## 优化选择及性能

首先试验透视区块的固定长度常量除法，但没有采用：
三轮基线 10.213 FPS / 67.666 ms，
常量除法 10.220 FPS / 67.759 ms，
差异处于波动范围，光栅也没有改善。固定世界中 8/24 像素区块只占约 26.2%，
不能仅凭“常量除法更便宜”判断整个游戏更快。

使用同一存档的原生几何和 Host 深度统计，6,382 行中 831 行完全被遮挡，约 13.0%；
检查了 16,797 个深度位置，平均每行约 2.63 次比较。其余行一发现可见像素就停止预检。
这份统计来自原生固定几何，不冒充设备上全部帧或所有场景的遮挡比例。

| 手段 | 原因及收益 | 内存与正确性 |
| --- | --- | --- |
| 整行深度预检 | 全部像素都被已有深度挡住时，省去 U/Z、V/Z 插值、区块透视除法和纹理步进 | 直接读取已有 R16 depth；无覆盖位图、层次深度缓存或新分配 |
| 保守范围证明 | 只有整行线性深度处于 1～65535 才提前拒绝，避免与区块钳制/越界处理产生差异 | 不确定就走原路径；空行、正负极值步长、相等深度由独立 oracle 验证 |
| 保留行边缘推进 | 跳过像素处理后仍按原方式推进左右边缘及后续行 | 不影响裁剪、材质 UV、相邻行或区块边界；保留 Z-buffer |

先测基线、常量除法、遮挡候选，再恢复原版测三轮，最后恢复候选测三轮。

| 固定场景 | DMA FPS | Host 光栅 ms |
| --- | ---: | ---: |
| 起始基线，三轮 | 10.213 | 67.666 |
| 原版回测，三轮 | 10.195 | 67.906 |
| 遮挡候选首测，三轮 | 10.423 | 65.911 |
| 遮挡候选复测，三轮 | 10.481 | 65.513 |

Jump 的原生场景不用 R16 深度，候选不会进入此预检；仍作为完整固件回归。

| Jump 场景 | 原版 FPS | 最后候选 FPS | 光栅 ms：原 → 候选 |
| --- | ---: | ---: | ---: |
| 静止 | 33.481 | 33.241 | 19.927 → 19.806 |
| 蓄力/跳跃 | 30.128 | 30.390 | 21.078 → 21.041 |

Jump 早期候选跳跃约 29.79 FPS，保留在 `row-jump.json`；按相同 UART 请求蓄力
并不等于按下至松开的实际设备时长完全一致，轨迹/音效资源可能不同。
不能挑选最高一次跳跃数值，也不宣称 Jump 或全部场景加速。
移动/转向是功能与体验检查，轨迹、面数随采样变化，只列原始结果，不用于严格加速比。
输入关联的 Guest/提交/DMA 延迟在原始 JSON 中；不包含物理触控与光学响应，
没有足够证据宣称 P95 延迟全面降低。本轮未增加 Guest 更新、几何、编码的单独设备计时。

## 验证及复现

原生 raster/span/assets/game-render 4/4、最终模拟器 raster 回归通过。
O3 ASan/UBSan 覆盖原有 6,000 扫描线与新增 3,000 遮挡 oracle，
包括空长度、极值步长、相等/混合深度、必须保守回退的越界跨度。
模拟器重新构建完整产品 Host，实际运行同来源 AOT 的 Voxel 和 Jump，
进入游戏、调整视角、按下攻击和蓄力/跳跃，保留截图；不把桌面 FPS 当作设备收益。
最终设备验证记录见 [functional-final.json](game-render-occlusion-20261015/functional-final.json)。

额外同顺序冷启动对照（均刷写后等待 15 秒）：
原版 SRAM/PSRAM 峰值 **516,240 / 4,780,188 B**，
候选 **516,240 / 4,296,288 B**。
这种启动临时量差异没有独立归因，不能宣称本内核节省了约 473 KiB。
全部轮次中，候选观测到的最高启动 PSRAM 为 4,780,264 B，原版为 4,780,188 B，
绝对值相差 76 B；稳定占用也有十几字节波动。固定内存结构与分配不增长，
但本轮不保证每个窗口的整机绝对峰值都更低。

相同刷写后等待 15 秒的额外冷启动内存对照见 `control-cold-voxel.json` 与
`row-cold-voxel.json`。启动过程的临时量和结束时的固定容量分别记录，
没有删掉早期更高的启动窗口。

本轮没有新增 SIMD/汇编。S3 既有送屏 SIMD 保留；这个优化减少 CPU 做的工作，
可在不同芯片复用。S31 新内核仅完成编译和尺寸检查，没有刷入设备做同负载 A/B；
pai-touch 与 Korvo 的上一轮不同版本基线不能用于宣称本次跨板收益。
候选最终刷在 Watcher，原有应用和数据保留，临时自动视距设置已恢复，应用和探针已停止。
一次启动前段触控读取报错随后正常启动，计时窗口内未观察到显示错误；
未独立定位该板级初始化问题，也没有将软件注入测试冒充实体触控稳定性验证。

复现使用上一轮同一存档夹具和相同包，构建仅 raster 对象不同的固件；
不要覆盖现有世界。空槽固定视距 32 后，用以下命令（替换 PORT、PACKAGE、OUT）：

```sh
PXADB_BAUD=2000000 python3 tools/measure-device-gameplay.py \
  --port PORT --expected-serial 8c:bf:ea:09:af:6c \
  --app pxa-voxel-craft --package PACKAGE --output OUT \
  --repeat 3 --warmup 6 --seconds 4 --size 412 412 \
  --prepare-tap 206 258 --start 206 165 --scenes idle
```

Jump 用 `--app pxa-jump-jump-3d --repeat 2 --warmup 2 --scenes idle charge --charge-seconds .68`，
去掉 `--prepare-tap/--start`。完整固件、串口日志、独立对照构建、未采用候选和源快照在
workspace `local/game-render-opt2-20261015/`。
没有用降低画质、扩大缓存或不同游戏包换取更高 FPS。
