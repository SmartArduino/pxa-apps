# 0.2.1：替换默认书源与网站接入验证

旧的四个默认项（经典直读、GITenberg、古腾堡中文小说、古腾堡世界文学）已移除。
默认改为 [努努书坊](https://www.nunubook.com/) 的真实站内搜索；书名、作者和正文均来自网站，应用不再把四部内置经典当作默认搜索范围。
这次只默认接入这个经过完整验证的站点，没有把镜像域名包装成多个独立书源。

## 数据与交互

- 状态文件升级到版本 4。版本 1–3 按旧书源的类型及已知 URL 识别默认项，移除后补入新规则；自定义 URL / 查询筛选保留。
  书架、阅读位置、搜索历史、设置、完整与部分正文缓存均保留。迁移不重命名缓存，不重新下载旧书。
- 所有书源都可移除；空列表可搜索提示、跳到添加页面，重启不会擅自恢复默认项。
- 默认仍按需阅读，不创建正文 `.part` / `.txt`。可以明确下载离线、清缓存；新站点没有改变这套策略。
- 新默认项使用与自定义来源相同的声明式规则，见 [nunu.json](../source-examples/nunu.json)。没有增加网站脚本运行时、内置书库或独立解析插件。

## 可复用的规则能力

`search.method: POST` 和 `search.body` 支持表单搜索，关键词替换前做 URL 编码。
下一组链接继续使用 GET。HTTP 请求复用 SDK 的标准 Net 接口，头字段遵循 SDK 的小写约定。

`toc.paged` 从详情页取得接口标识，按声明的 JSON 字段读取目录。按需阅读先取得当前章需要的目录页，
翻到后续章或后续目录组时再请求；不提前拉取整个目录。目录接口的 HTML 预览可能只有十条，不作为全书目录。
离线下载先收齐目录并验证计数，再逐章下载。

每页整体校验后才追加到有效前缀。总数变化、重复 URL、缺页或最终计数不一致会拒绝该页，可重试；
目录页面读取失败或取消时恢复到可用的上一组。没有把部分目录或失败下载标记成完整离线书。
具体字段、上限与例子见[书源规则](source-rules.zh-CN.md)。

扫描器同时修复了真实网页中的多余属性引号问题，保留合法属性值中的 `>`；仍是有界扫描，不构建 DOM。

## 真实网站验证

联网原生检查直接编译应用所用的解析头文件，不维护第二套 Python 解析逻辑：

| 查询 | 站点返回且客户端解析的条目 |
| --- | ---: |
| 三体 | 4 |
| 长夜难明 | 1 |
| 紫金陈 | 14 |

《长夜难明》接口声明 69 条目录，分 7 页，实际收齐 69 个不同 URL；检查了首项、索引 11 及末项的正文。
正文解码后分别为 282、6545、6071 字节，UTF-8 有效。记录只保存 URL、大小、计时和 SHA-256，不把小说正文打包进应用或测试仓库。

系统模拟器从没有状态文件的新安装启动，完成真实搜索、首屏阅读、越过目录预览的跳章、遍历到最后一组目录、
保存进度、移除最后一个书源以及空书源重启。默认按需流程没有正文文件。

联调时，先拉完七页目录的实现曾等待约 12.3 秒才出现正文；改为按需目录后，开发样本约 4.0–4.5 秒。
打开首章的请求从“详情 + 七页目录 + 正文”减少为“详情 + 一页目录 + 正文”，其余目录不在后台预取。
这是两种实现的外网观测，网络波动、服务端缓存和桌面调度都会影响计时，不能当作稳定的设备延迟基准。

## 回归与资源

- Clang C++26、ASan / UBSan：状态版本 1–3 迁移、自定义书源保留、空列表重启数据、POST 规则、带多余引号的 HTML、
  分页 JSON、重复 / 变动 / 缺页后重试、有界解析及真实长篇的分页与索引检查通过。
- 296×240 / 160 DPI 模拟器：分页目录跨章请求注入 503 后回滚重试、TXT 窗口边界、历史边界、重启、离线下载、
  清缓存、设置、自动翻页、错误 UTF-8 通过。
- 480×480 / 320 DPI 圆屏：搜索输入、HTML 规则导入、分章阅读、离线下载、清缓存及设置回归通过。
- 未插桩正式包回放已有正文：37 个页面的正文截图与原参考一致，缓存内容和保存进度正确。
- 构建正式包包含 Linux 模拟器、ESP32-S3、ESP32-S31 三种 AOT。没有操作真实设备或商店服务器。

固定资源未扩容：8 KiB TXT 窗口、3600 字节 Canvas 命令区、16400 字节协程池、64 KiB 线性 C 栈、2 MiB 线性内存上限。
本轮新启动的模拟器进程中，Guest 线性内存初始 2 页（128 KiB），观测最高 3 页（192 KiB）；
协程槽位峰值 8，分配失败 0。分页游标只保留小标识及计数，目录条目按需增长，不预分配 1024 项；正文只保留当前章。
这些是本次进程的实际线性页数观测，不是逐次 `malloc` 峰值，也不是设备 SRAM / PSRAM 数据。
新规则解析能力会增加映射代码体积，正式包和各架构 AOT 的大小列在 JSON 中；不能据此声称所有内存类别均下降。

## 可复现

在工作区根目录执行：

```sh
SANITIZE=1 bash local/pxa-apps/novel-reader/tests/test.sh
python3 local/pxa-apps/novel-reader/tests/build_playtest.py \
  --target simulator --output local/reader-source-check/build
python3 local/pxa-apps/novel-reader/tests/session_probe.py \
  --package local/reader-source-check/build/artifacts/pxa-novel-reader.pxa \
  --output local/reader-source-check/session --paged --stress
python3 local/pxa-apps/novel-reader/tests/website_probe.py \
  --package local/reader-source-check/build/artifacts/pxa-novel-reader.pxa \
  --output local/reader-source-check/live
```

默认使用独立的 `build/simulator/reader-validation` 完整系统模拟器，可用 `--binary` 指定同版本完整系统模拟器。
所有会话使用 QA 应用身份及临时数据目录，不覆盖真实书架；外网不可访问算失败，不用本地夹具替代成功结果。

## 已知边界

目前只内置一个经验证的网站规则。搜索结果可能含站点自身的影视条目，不保证所有命中项都有小说目录；客户端读取不到目录会明确提示。
站点目录的“收齐”指其接口声明的条目，并不保证出版文本完整。例如本次书目自身的章节编号有跳号，应用没有改造或补造这些编号。
仍最多 32 条搜索结果、1024 章、每页目录 96 KiB、单章 HTML 64 KiB、单本下载 8 MiB；超长书及超大章节可能超限。
不运行 JavaScript、不处理 GBK、登录、验证码、付费章节或任意分页正文。网站改版或访问失败需要调整对应 JSON 规则。
