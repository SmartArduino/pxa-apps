# 图片资源

游戏图片的 PNG 原稿保存在 `resources/`，`resources.json` 在打包时将它们无损转换为 PXR1 BGRA8888。生成文件进入包的 `assets/`，不会成为 AOT 或 Guest 线性内存中的像素数组。启动器图标继续使用包图标入口。

应用使用 Assets 2.1 和 UI 0.6。`images.c` 保存路径及资源句柄；绘制代码使用 `plane_image_id_t` 和 `plane_image()`，后者提交 Canvas IMAGE_HANDLE。Host 异步读取最终像素对象，LVGL 借用同一份像素。绘制调用不查找路径、不读取 PNG，也不在 Guest 中解码图片。安装时验证包；启动和加载图片时不重复 SHA 校验。

`main.c` 的 `scene_images()` 声明当前页面需要的图片：首页为主图和四个导航图标，其他菜单只保留当前显示的图片；战斗准备所选飞机、所选关卡首领、敌人、拾取物及 HUD/对话框。不能以全应用常驻来掩盖场景切换问题。

调用顺序为：

1. `plane_images_select(mask)` 关闭不再使用的 Guest 句柄，并取消已不需要的加载。
2. 新场景资源未齐时，先提交不含图片的加载画面，释放上一帧对图片的引用。
3. `plane_images_pump()` 提交至多一个异步 LOAD，已有请求未结束时不重复提交。
4. 现有事件分发调用 `plane_images_on_event()`。全部就绪后绘制菜单或启动战斗。

加载失败释放已加载的场景句柄，显示重试按钮，不自动循环申请内存。重试由用户明确触发。取消成功与晚到的成功结果分别处理：不再需要的晚到句柄必须关闭。后台取消当前请求、暂停后续加载；完成事件仍正常回收，前台恢复后继续准备。退出关闭持有的句柄，Host 在消费者释放引用后回收对象。

## 验证

项目根目录的 `tools/test-pxa-resources.sh` 包含控制器的 ASan/UBSan 测试和真实 AOT 模拟运行，覆盖菜单切换、战斗入口、后台恢复、低预算切换和加载中退出。

`tools/compare-plane-images.py` 接收捕获程序、迁移前包、当前包、发布者公钥及输出目录，对比首页和五次菜单截图，并检查游戏画面继续变化、后台暂停和恢复。迁移前包必须来自独立保存的基线，不能重新用当前源码构建后当作旧版。

这些检查不替代同工作负载的帧时间基准。共享资源预算也不包含整个 LVGL 堆、旧 PNG 解码器、SDL、工作线程栈或所有 Host 元数据；旧路径预算主要记录压缩 PNG，新路径记录展开像素，不能直接用两列数字宣布总内存下降。BGRA 保留原图透明度与颜色，但会增加安装后的资源文件大小；存储读取成本与最终驻留成本需要分别测量。
