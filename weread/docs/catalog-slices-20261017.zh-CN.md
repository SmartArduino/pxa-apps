# 目录分段实验与边界修复

2026-10-17。本轮实际比较当前生产 Guest 与目录分段候选。**分段候选未采用；最终安装的是原生产实现加目录整数溢出检查。** 模拟器通过不等于真机性能和内存达标。

## 目的与实现

生产版本在大型目录投影完成后，存在约 192 ms 的同步模型构造。实验使用借用 JSON 数组游标和不发布的目录构造状态，在目录行之间检查 8 ms 时间预算、交还事件循环；完成并验证后才替换目录。取消、后段错误和超限都保留旧目录。没有新增目录索引、JSON 树、整书缓存或宿主接口。

同时尝试按连续章节 UID 合并 URL 赋值、单次选择行字段、共用 JSON 字段扫描器及减少中间任务帧。最初实现跨过第 22 个代码映射页，因此没有部署；收敛后的测试候选保持 21 页，仍使用完整 LTO、O3 和原有编译安全检查。

8 ms 只是在行之间检查的合作式预算。初始元数据扫描、构造函数及单个复杂 JSON 值没有被证明满足该上界，不能据此宣称输入延迟小于 8 ms。

## 同固件真机对照

设备为 pai-touch，身份由 MAC 核对。两次普通软件冷启动，未写 Host 或字体。Host 为本任务既有 PNG 生产镜像 `d8789493…`，字体为 `121cb206…`。旧包 AOT `6f9ae53f…`，候选 `16369dfb…`。

这是单对比较，而且候选在重启后经过安装及文件哈希核对，基线则直接启动。安装顺序可能影响物理堆布局，因此不能把物理堆差值全部归因于目录实现；本轮仍没有足够证据满足内存不增长门槛，也没有证明整体提速，故未采用。后续性能判断需要预先固定启动顺序及交替重复协议。

两次均打开《C++ Primer Plus》的同一个可获取版权信息章节：HTML 241,046 B、投影数据 43,366 B、显示文本 901 B、目录窗口 300 项；加载期间相同 10 次触摸探测，再进行 12 次本地往返翻页。这是大型目录、短正文的负载，**不能代表已购后续全文已经可读，也不能代表长篇正文或漫画性能**。

每个阶段独立执行 `MEMORY START`，确认 `minimum_scope=local`，读取 `MEMORY STOP` 的该窗口统计后恢复 boot 口径。没有用退出后的历史最低空闲量当作当次峰值。WAMR/Guest 峰值和代码映射由实际运行日志核对，未用文件偏移推算“真实映射页数”。

PXA 应用资源统计中的 frame/scratch/mailbox 与整个系统显示缓冲不是同一个口径；没有新增 Guest 帧缓冲、深度缓冲或图像缓存。Host、字体和显示路径保持原样，物理堆统计仍包含其原有占用。

两版首次阅读截图和 12 次翻页后正文区域一致，跨版本正文区域也逐像素一致。实际显示完成计数在翻页窗口均为 19，但窗口包含人为等待；不将计数除以窗口长度当作饱和 FPS。该 Canvas 路径的 present/visible 输入计数为零，未得到可信的触摸至实际显示端到端延迟。

**决定：不采用该候选。** 分段行处理没有消除剩余长回合，模型阶段经过时间反而增长，且不符合内存不增长要求。已恢复生产包；失败候选仅保留在独立实验快照及证据中，不进入产品运行源码。后续应独立计时未切分的元数据、目录初始化与资源读取，再选择方案；这些瓶颈位置目前属于待验证推断。

## 本轮保留的修复

1. 目录窗口 `offset + skip` 和 `begin + item_count` 的 32 位溢出现在会拒绝响应并保留旧目录。旧实现可能回绕到较小页码并错误发布目录。这只增加整数检查，不新增容器、索引或缓存。
2. 模拟器内存统计文件由诊断进程原地重写。测试恰好读到空文件/半个 JSON 时，过去会误判失败；现在只重试这两种临时读取状态，完整 JSON 的字段或断言错误仍会直接失败。成功等待返回同一份完整快照，避免检查后再读时再次遇到重写。
3. 保留单字段/多字段查询的转义键、重复键、空字符串和嵌套对象对照检查。没有把未证明的共用扫描器性能收益写入生产结论。

这些修复与实验性能数据分开：上表针对已回退的分段候选，不能作为边界修复版本的性能收益。定向复现中，旧实现把 `begin=UINT32_MAX` 的一项窗口错误发布为 `end=0`；修复版拒绝响应并保留旧窗口。

边界修复的原生 ASan/UBSan、S3 构建及 AOT/Wasm 各 64 项集成检查均通过，已安装真机。新 AOT 为 1,450,384 B，比原生产包增加 80 B；实际代码映射仍为 1,376,256 B（21 页），相同版权章节负载的 Guest 线性内存峰值仍为 589,824 B，WAMR 原生峰值仍为 220,332 B。没有引入分段构造状态、缓存或额外协程。

安装后正常阅读、联网后重开阅读均通过，每次覆盖同一 901 B 正文、300 项目录与 12 次本地翻页；另有 3 次完整停止/重开书架通过。这些是功能和资源检查，不是新的平衡性能对照，不以加载或翻页计时宣称提速，也不能由 Guest/WAMR 指标推导所有系统物理堆峰值都不增长。

冷启动额外检查出现一次失败：系统启动约 8.4 秒时 DNS 解析失败，TLS 无法连接，等待 50 秒仍未出现书架就绪记录。该次没有进入目录处理，不能计作通过，也尚不能归因于新目录检查。停止后资源释放，联网后的重开恢复正常。记录中还存在 5 段日志丢弃，且未在失败期间截图，因此不能由缺少应用错误日志断言通知一定漏传或错误提示未显示。失败原始记录保留，仍需核查设备冷启动连接错误的通知、画面与恢复；不能把模拟器错误路径通过当作此故障已修复。安装前另一次在锁屏状态收到 `input_unavailable`，尚未归档或写包；确认实屏并正常解锁后才重试安装。

19:39 前补做一次同包、同固件的普通冷启动观察，没有安装或修改任何配置：启动后第 3 秒和第 8 秒截图、书架 READY 均正常，实屏封面可见，未复现 DNS 失败，因此未执行多余的刷新或重复尝试。该次全部 29 个安装文件与 3 个私有文件的集合及 SHA 均与重新接管时一致。保留失败与成功两轮记录；单次成功不能证明 ESP 冷启动失败时的错误提示和手动重试已通过，不能据此宣布问题修复。

## 验证与范围

- 分段最终候选：实际 PXA AOT/Wasm 各 64 项，共 128 项，完整运行返回成功，包含登录续期、详情、核心流程、四屏封面与插图、错误、限额、取消和退出释放。
- 原生 ASan/UBSan：长目录、分批推进、零时间预算进展、取消保留、晚期失败、游标格式和溢出边界通过。300 组有效目录及前后页结果与旧实现一致。
- 桌面同一 43,227 B 数据的五对交替模型测量有改善，原生模型动态分配次数及峰值不变；但数据集和平台不同，不拿这些结果覆盖真机回退结论。
- 生产目录溢出修复与额外 JSON 键检查的原生 ASan/UBSan 已通过；测试统计文件短读/缺失可重试、字段错误仍失败的定向检查通过。
- 最终边界修复：AOT/Wasm 各 64 项、总计 128 项完整集成通过，包括真实 PXA 网络、字体、图片与界面路径；四种屏幕配置、续期、详情、取消和释放均覆盖。与分段候选的 128 项检查分别保存。
- 网络异常补充：`tests/network.py` 在同一最终 Guest 的 AOT/Wasm 分别验证连接拒绝、响应头前断开、正文截断、响应头前取消，共 8 项通过；前 3 类出现错误后手动刷新可恢复书架，全部保留私有认证字节且退出释放资源。连接拒绝使用已绑定但未监听的端口，其他断连使用实际本地 TCP 服务，不以 HTTP 错误状态冒充传输失败。该检查覆盖桌面后端，仍不能代替 ESP DNS/TLS 冷启动验证。
- 分段实验回退时已核对全部 29 个旧安装文件、阅读位置、设置、其他应用私有文件和字体；该阶段官方正常更新的会话保留了最新字节。
- 最终边界修复安装后，7 个新阅读器包文件与签名目录逐项匹配，其他 22 个原安装文件保持原样；全部 3 个私有文件的集合与 SHA 均与本次接管前一致，自己的 session/state 字节完全相同。Host、字体、Wi-Fi 和输入法选择未修改，无 App 运行、监控停止、输入取消、文件系统锁定，最后桌面截图和端口无占用已核对，设备已明确交回浏览器任务。
