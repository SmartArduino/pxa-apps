# 书内插图与 PNG 验证（进行中）

本轮实现原生正文中的静态插图，不替换原网站内容、不执行网页脚本。模拟器与 pai-touch 已显示真实账号的授权插图；大章节加载仍有明显输入延迟，正在继续拆分 Guest 解析。不能把电脑测量当成芯片性能。

## 实现与取舍

HTML 图片保留原文位置、替代文字、宽高比与 em 宽度。`data-ratio` 表示高/宽，排版时转换为宽/高；未声明尺寸时可在解码后读取原图比例。每页最多 64 个文本/图片片段，元数据合计不超过 64 KiB。图片过高时收进当前可用区域，纯文字关闭图片后采用紧凑占位。旧进度仍按 UTF-8 字节保存，加载时迁移新增图片占位符对应的偏移。

当前页共享 65,536 解码像素，非每张各占一份预算。逐张 HTTP 下载并将响应体直接移交现有 Host Assets 解码服务；没有 Guest 编码图片、Guest 像素或临时图片文件。翻页、后台和关闭图片会取消任务并释放资源；失效完成不得回写新页面，失败可以点按重试。PNG 保留透明度；JPEG 与 GIF 显示静态图，GIF 动画尚未实现。缩小采用既有就近采样，细节受目标像素预算限制。

真实图片服务会从 `res.weread.qq.com` 重定向到腾讯云 CDN。现在最多发出四个请求，每次都检查 HTTPS 与完整域名边界，保留原始签名查询串；拒绝外站、降级、用户名密码 URL 及循环超限。图片请求不发送账号 Cookie，也不把响应的 CDN Cookie 转发到下一请求。正式构建不允许测试用 localhost。

## Host PNG

实际授权图片为 1280×1778，共 2,275,840 源像素，超出旧版 1M 上限。PNG 源边长仍不超过 4096，面积工作上限改为 4,194,304；输出仍不超过 65,536 像素。只保存行缓冲、解压状态和缩小后的图，不展开原图。

扫描线环形索引用条件回绕取代逐通道求余；8 位颜色跳过重复量化，低位深与 16 位路径保留原缩放。忽略不含输出采样点的源 tile；Adam7 遇到重叠 tile 时重置采样游标，包含极小尺寸各 pass 重访同一行的情形。

可选的 target 输入预算让 PNG 每次 owner-loop poll 最多处理 64 B 编码输入，签名探测也最多 64 B。其他 codec 保留默认上限 4096 B。没有新增线程、永久图片缓存、wire 字段或 codec 描述符成员。解码器利用原结构尾部填充保存提示值，x86 / ESP32-S3 分别仍为 168 / 116 B；PNG 会话仍为 584 / 568 B。输入字节预算不能保证 CPU 毫秒期限，finish 与多帧 next 仍是同步调用。

## 已测结果

原生 decoder 检查保留 PNG/JPEG、透明、色板、灰度、Adam7、截断、分配失败及 3500 次畸形输入。另覆盖 1280×1778 普通/隔行图、源面积上限与越界、1–9 宽高的 81 种微小 Adam7 图、非整比例缩小、1/2/4/16 位灰度，逐像素检查通道和 alpha。测试包含 ASan/UBSan；结构和动态计费峰值分别核对。

合成集成测试在 296×240、480×480 高 DPI、240×240 圆形、480×800 四屏运行真实 PXA AOT 与 Wasm：PNG/JPEG/GIF 可见且比例正确；20 张可见图片共用预算；关闭释放、503 重试、下载中翻页取消、原始签名重定向、拒绝危险跳转与循环上限通过。保留旧正文/搜索/大目录预算拒绝的 12 项 AOT 与 12 项 Wasm 流程。

共六批、每种算法三批，交替顺序运行；每批预热后八次，固定 CPU、GCC 16.2 / O3、同一私有授权源图、同一 32,768 输出像素限额。旧算法仅放宽源面积上限后比较，否则旧版直接拒绝该图；约 1.70 倍是这份 Linux 工作负载的 CPU 结果，不是 ESP32、FPS 或触摸延迟结论。原始数值见 [批次](images-20261017/final-benchmark.json)。

功能增加需要计入完整应用成本：ESP32 AOT 从正文版 1,237,816 B 增至 1,374,016 B（+136,200 B）。真实账号的大目录搜索及插图流程，模拟器 Guest 线性内存峰值 1,441,792 B；此前纯正文流程为 1,376,256 B，工作负载不同，不能据此宣称性能或总内存不增。20 图合成页 image 计费为 255,660 B，关闭后归零；Guest 线性内存稳定/峰值均为 196,608 B。Wasm 解释器另有模块缓冲，计数存在包含关系，未相加成物理总 RAM。

账号、授权源图、正文截图、签名 URL 与会话只存本地私有验证目录，不放入报告。尚未完成动态 GIF、漫画缩放/专用浏览、PDF、离线缓存、跨端进度与笔记等能力，不能将本轮插图功能称为完整微信读书客户端。

## pai-touch 实测与剩余瓶颈

实际读回生产镜像后，在独立链接目录核对六个加载段，再只替换四个 PNG / 解码相关对象。保留原 JPEG、显示、输入法和字体。Host 文件增加 224 B，静态 SRAM / PSRAM / IRAM / 只读数据与映射页不增加；当前镜像摘要见 [结构化真机记录](images-20261017/device-stepped.json)。

第一版插图包能显示图片，但进入大目录时 Guest 同步扫描触发看门狗并出现“应用无响应”。调用栈定位到数据投影，发生在 PNG 解码之前。随后用借用游标和分步目录投影，每 16 行归还事件循环；真实 1280×1778 插图再次显示，测试捕获中没有看门狗或无响应对话框。当前 ESP32 AOT 为 1,387,728 B，比第一版插图包增加 13,712 B；实际代码映射两版均为 1,310,720 B。真机插图实例包含后续锁屏/后台重载及取消，退出时 Guest 线性峰值为 1,179,648 B；不能将后两次另一书籍的 917,504 B 或日志订阅中的旧历史实例当作该实例峰值。普通正文重开为 393,216 B。电脑真实插图流程峰值仍为 1,441,792 B，工作负载分别记录，未混作前后总内存对比。

固定普通正文的 12 次交替翻页，Guest 输入处理 P95 为 7 ms，旧正文基线为 8 ms；本轮最大 8.76 ms，样本 81 / 83。present / visible 延迟样本为零，不能据此声称物理触摸延迟。三次重启都保留登录并打开图书，其中只有第一次是同一普通正文，其余两次受服务端书架重排影响，打开了另一书籍，不能作为三次相同场景比较。

加载真实大章节期间，10 个 Guest 输入样本的 P95 / 最大值仍为 **1.169 s**。同步的第一轮字面量准备尚未拆分，此版本不能称为加载流畅。下一候选将准备过程、长字符串和索引排序也逐段处理，尚未在真机验证，不将候选当成已取得的收益。

图片就绪时 image 计费 22,019 B，temporary 已归零。`MEMORY START/STOP` 的本次加载窗口 SRAM 最小空闲 43,791 B、PSRAM 最小空闲 3,670,884 B；稳定空闲分别为 48,615 / 4,517,780 B。PXA budget 的历史高水位没有在窗口开始清零，因此不能将其报告成这次加载的真实峰值。关闭/返回期间没有迟到的正文或图片完成回写；结束后其他包和其他私有数据逐项核验，真实账号会话保留，监控停止、系统文件锁定、无应用运行。

## 复现

固定构建输入后先构建测试包（与 README 的 fixture 宏一致），再顺序运行，不能并行占用同一端口：

```sh
python3 local/pxa-apps/weread/tests/images.py \
  --simulator <已构建的模拟器或内存观察器> \
  --package <fixture包目录>/pxa-weread \
  --publisher-key local/pxa-apps/.dev-signing/publisher-public.der \
  --ime-package local/app-output/pai-touch/pxa-pinyin-ime \
  --output local/weread-validation/images
```

20 图预算用例读取 `tests/build_memory_probe.py` 生成的只读观察器报告，需使用该观察器。正式包不含 fixture 端口。原生 decoder 的合成图由 `libpxa/tests/test_image_decode.py` 生成；无需真实账号。
