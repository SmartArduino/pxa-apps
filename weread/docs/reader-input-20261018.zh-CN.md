# 大目录阅读：有界输入与共享解析预算

2026-10-18。代码已进入开发工作树，**本轮尚未安装到真机正常包**。设备继续保留已采用的 `b2b44db1…` Guest；本轮没有访问串口、更新 Host、字体或账号文件。

后续索引与真机结果见 [索引复核](reader-index-20261018.zh-CN.md)；本文的 160 项与二进制摘要仍对应原有界输入候选。

## 已确认的原因

完整私有响应为 950096 B，正文容器内部为 115612 B，Nuxt 数据约 781098 B，包含 8548 个序列化别名、27 项字段初始化和 2538 项目录。正文规范化后为 9133 B。这些数值来自同一完整响应；先前响应头的 950098 B 和未完成的部分采集分别保留，不能混作同一字节样本。

旧 HTTP 上限 786432 B 在解析前拒绝页面；只筛掉外围 HTML 仍无法容纳正文与序列化数据之和；只扩大 HTTP 上限又会遇到固定 8192 个别名的限制。没有把服务端序列化对象当作 JavaScript 执行，也没有改写授权结果或重新尝试已确认不可用的已购书后续章节。

## 实现选择

| 改动 | 原因和收益 | 内存影响 | 验证 |
|---|---|---|---|
| 有界拥有字节输入，解析器借用视图 | 保持一份响应；可原地扩容；分配失败返回 `resource_limit`，避免关闭异常的 Guest 因字符串分配失败直接 trap | 空对象不分配；已知长度只申请所需容量；未知长度按需增长 | 已知/未知长度、257 B 分片、取消释放、移动、超限与重试 |
| 大缓冲的单次增长额最多 64 KiB，失败时尝试精确所需容量 | 首轮 1.5 倍增长仍在未知长度页面耗尽线性堆，保留该失败；限制额外容量后同页通过 | 没有扩大 2 MiB Guest 上限或添加默认大缓存 | 相同 950096 B 合成页面与完整私有响应回放 |
| 输入、别名索引、字段索引和投影输出共享预算 | 用实际保留容量替代固定 8192 个别名、4096 项字段限制；解析器重新使用时先清理不再需要的容量 | 逻辑工作预算仍为 1310720 B；阅读输入上限 1302528 B，为最小输出保留空间；不等同于整个 Guest 或分配器峰值保证 | 9000 别名、预算拒绝、取消后复用、重复字段与非法字面量 |
| 直接规范化借用的正文 HTML | 避免先把约 113 KiB HTML 复制到阅读模型，再生成纯文本；仅成功后提交新模型 | 减少中间副本；旧页在失败时保留 | 截图一致、本地翻页无联网、授权/错误回退 |
| 一次仅保留最多 300 项目录窗口 | 不常驻整本目录；窗口切换仍使用原阅读入口重新投影 | 容量有界；保留源目录长度与官方章节编号 | 2538 项逐窗遍历至末尾；实际 UI 前后窗口往返 |

HTTP、输入、索引与投影预算分别检查。预算允许解析数据，并不保证设备当前空闲堆一定足够；当前仍有模型、标准容器和 SDK 自身分配，不能宣称应用的所有 OOM 都已可恢复。

## 同负载方案对照

以下三个隔离候选使用相同书签界面、同一冻结模拟器、296×240 / 160 DPI / 圆角 58、同一合成正文、8548 别名和 2538 项目录。前后页截图一致，成功后翻页不重新联网。线性内存不会随 `free` 缩小，因此这里的当前值也是本次已增长到的高水位。

| 输入方案 | 已知长度线性峰值 | 未知长度线性峰值 | 结论 |
|---|---:|---:|---|
| 整页字符串，仅扩大输入和索引预算 | 1310720 B | Guest trap；失败保留 | 不采用 |
| 分开持有正文与 Nuxt 的流式筛选 | 1703936 B | 1703936 B | 成功，但比更简单的整页有界方案多占内存，不采用 |
| 有界字节、限制增长额、直接正文视图 | 1310720 B | 1572864 B | 两类均通过，继续验证 |

这些是模拟器 Guest 线性内存，不是 ESP32 的 PSRAM/SRAM 数据。WAMR 的独立稳定/峰值、源码与二进制范围见 [结构化记录](reader-input-20261018.json)；这些计数存在重叠，不能简单相加。

随后又把同一种拥有字节输入统一到登录、书架、阅读和官方 Skill 只读请求，避免复制两套 HTTP 协程。在已采用笔记版本上独立构建的 S3 候选，AOT 为 1458888 B，相对原包增加 4448 B；text 段 1370116→1374192 B，按当前映射规则仍为 21 个 64 KiB 页。它没有书签候选的界面变化，不能拿它和带书签版本直接比较默认成本。整机稳定与首次/重开峰值仍待真机配对测量。

同一小页面的桌面 AOT 对照已完成，前后截图一致、已知与未知长度均通过：线性峰值同为 196608 B；WAMR 稳定计数 56308→56467 B（+159 B），本进程峰值 528845→531064 B（+2219 B）。WAMR 峰值包含首次模块加载，不是纯阅读窗口，也不是 ESP32 物理堆。**因此严格的所有计数不增长门槛仍未通过，不能把代码映射页不变表述为整体内存不增长；本轮没有留机。**

本轮最终验证共 **160 项集成检查**：笔记基线派生 AOT 的基础/网络/续期/插图/笔记/详情/封面 86 项、大页面及私有回放 5 项；开发源码 AOT 的大页面/回放/小页面/限额/书签 27 项；Wasm 的大页面/回放/小页面/限额/网络/续期 24 项；补充 AOT 小页面 2 项和开发源码 Wasm 书签 16 项。另有 7 个原生 ASan/UBSan 测试程序、单独新增的 2538 项目录末尾遍历 sanitizer 检查，以及 C++26 HTTP 数值诊断分支语法检查。每组构建和计数分别记录，不合并为单个二进制的覆盖率。

测试的等待时间包含脚本点按和轮询间隔，**没有当作加载延迟、实际显示 FPS 或触摸延迟**。完整私有页面的本地回放验证了解析和渲染，不替代真实网络下载、有效账号续期或真机验收。

## 复现与范围

`tests/large_reader.py` 现场生成合成数据，没有复制书籍、账号或二维码。`--small` 提供同一小页面的基线成本对照，`--catalog` 检查第二窗口和返回；原生 `hydration_test.cpp` 遍历全部 2538 个目录项，核对每个 UID 和入口。`reader_input_test.cpp` 检查拥有关系、分片增长、容量拒绝与释放。
