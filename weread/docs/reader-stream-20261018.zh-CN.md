# 大页面阅读：已定位的限制与流式候选

2026-10-18。本文保留早期筛选器实验与失败。该原型已被[有界响应输入](reader-input-20261018.zh-CN.md)替代并移出当前源码；**未采用到 pai-touch 的正常包，也没有通过真实书签流程**。

## 真实失败原因

在同一 pai-touch、Host `234edd19…`、字体和同一账号/书目下，原已采用包与书签候选均返回 `limit_exceeded (-16)`，不是书签新引入的错误。数字诊断先确认错误发生在等待响应头阶段；独立的响应头实验确认服务端 `Content-Length` 为 **950098 B**，超过应用的 **786432 B** 响应预算。

响应头实验仅放宽传输声明上限，仍在分配或读取正文之前拒绝超出原预算的响应。因此它是诊断，不是通过扩大缓存实现的阅读支持，也没有修改正常构建的限额。

## 流式候选

`WEREAD_STREAM_READER=1` 启用按块 HTML 筛选，保留服务端正文容器和 Nuxt 序列化数据，丢弃其他页面内容。固定标签缓冲识别引号、注释和脚本/样式等原始文本；被保留的 Nuxt 仍交给原有受限字面量解析器，不执行 JavaScript。筛选器只在阅读请求期间分配，返回后销毁，不在书架模型中预置缓存。

三项独立预算为：传输 8 MiB、保留数据 786432 B、正文容器内部 196608 B。传输上限不代表分配该容量；保留数据按需增长，并保持原有上限。未知长度响应同样受传输和保留预算检查。重复目标数据、截断和不支持的格式失败时保留原阅读状态。

原生 ASan/UBSan 检查覆盖所有双分块边界、单字节与随机切片、原始文本/注释中的伪标签、精确正文边界、超限及重复数据。首个流式构建的 AOT/Wasm 各 **61 项**集成检查通过：基础 19、书签 16、插图 18、大页面/限额/重试 8。约 956 kB 的合成页面仅保留 5757 B，Guest 线性内存峰值小于 512 KiB。这个人为构造的收益不能替代真实页面验证。

后续只增加数值失败原因的版本又完成 8 项边界检查及原生 sanitizer 检查；这些结果按构建分开记录，不声称所有旧检查都在最新二进制重跑。

## 真实页面仍未通过

真实同书流式尝试仍失败。后续数字诊断明确为**保留数据总预算**，不是正文容器预算：已交给筛选器 839680 B、已保留 786023 B 时触发下一次追加的限额检查，尚未进入正文解析。计数表示下载后交给筛选器的块，最后一块可能只处理了一部分。

因此，仅去掉页面外围 HTML 不够。不能把合成大页面通过称作真实图书可读，也不能直接把保留预算提高至数 MiB。下一步需要确认序列化数据中哪些内容占据空间，再设计有界的按需解析；目录、正文和授权状态都必须正确保留。

## 补充结构检查

独立私有诊断包将响应按 1 KiB 写入自身临时文件，硬上限 1 MiB；该代码只存在于私有检出，不在正常应用中。首轮包含文件写入的采集在 20 秒超时，保留 581632 B 的部分响应，不能当作正常阅读耗时或完整页面采集通过。

部分响应已经包含完整正文容器（115612 B）和完整函数形参列表（8548 项）。正文低于当前 196608 B 上限；形参数量还超过现解析器的 8192 项限制。因此单独调整 HTTP 大小无法解决全部问题。已采集部分只观察到 10 处 Unicode 转义，但尾段尚未取得，不能据此判断整页的转义压缩收益。完整参数值和目录成本仍需完整响应核查；此处不根据部分样本声称已完成投影。

清理时发现测试控制器错误地调用了受保护私有目录的调试端删除接口，被 Host 正确拒绝。恢复改用同应用签名身份的 SDK `fs.remove`，仅删除本轮明确创建、采集前不存在的固定临时文件；不修改 Host 路径保护，也不清空其他私有数据。原失败及恢复证据分别保留。

## 完整采集补充

后续独立诊断以 60 秒采集期限完成 950096 B 响应，约 31.3 秒包含临时文件写入，不能视为正常阅读耗时。全文含正文 115612 B、Nuxt 781098 B、8548 个别名、27 项初始化、2538 项目录和 19 处 Unicode 转义。完整采集、同身份 SDK 临时文件清理、恢复 29 个原安装文件和 3 个私有文件均逐项核对成功。源页面只在私有工作区保留。

完整结构确认后，没有提高旧筛选器的默认预算来宣称修复；后续实现与模拟器回放范围另见[有界输入记录](reader-input-20261018.zh-CN.md)。
