# 书架与搜索封面

书架和搜索结果使用官方返回的真实封面地址；取得列表后即可绘制文字与占位，封面在后台依次下载、解码。标题与作者左对齐，封面按比例显示，布局遵循同一 DPI 与屏幕安全区。

## 原因、收益和内存

- 原先只有“书”字占位。现在能根据封面识别图书，不需要额外打开详情。
- 只请求当前可见条目，翻页取消旧下载。大书架不增加常驻封面数量，暂不预取或持久化封面。
- 和正文插图使用**同一个** `PageImages` 实例、HTTP 流、Host 解码与取消机制；共用 65,536 像素总预算，不新增第二份图片缓存。进入章节加载前释放封面，正文大 HTML 的解析阶段不会同时持有封面像素。
- 请求在栈上临时描述，每次重绘不复制封面 URL 或新建临时容器。只有可见条目变化时才更新缓存项；Host 保存像素，Guest 不下载完整编码文件或像素缓冲。
- 书架现在会持有可见封面的像素，不能声称这一界面和无封面版本占用相同。实测内存见下表。ESP32-S3 AOT 从前一设备版的 1,338,340 B 变为 1,408,220 B，包含本轮目录、登录和封面功能。
- 官方旧 HTTP 封面地址仅对准确匹配的腾讯封面域名升级为 HTTPS；其他地址仍需通过可信图片域名校验。JSON URL 不做 HTML 实体替换，签名查询字节不变。图片请求不发送账号 Cookie。

## 已通过的检查

最终 AOT 与解释 Wasm 各有 43 项，共 86 项：登录/阅读/目录及权限流程 19 项、正文插图 18 项、封面专项 6 项。覆盖四种屏幕、只加载可见条目、翻页、搜索复用索引但 URL 不同、在途取消、损坏图片回退、原始查询字节、退出后的 Host 资源清零。离开封面界面时还直接检查活跃进程的图片资源归零。

只读观察器在退出前的最后一次采样可能仍显示正在展示的封面，不把该采样误当成退出后快照；退出检查使用 Host 完成清理后的剩余资源计数。

真实账号网络检查中，模拟器显示了同一书架的 5 张可见封面，另一次正常进入授权正文并显示插图，两次退出后资源清零。pai-touch 已显示真实封面、完成同一章节的加载及本地翻页；建模优化的阶段对照见下文；持久提示页也已在最终设备包验证。合成画面见 [小屏](covers-20261017/compact.png)、[高 DPI](covers-20261017/hidpi.png)、[圆屏](covers-20261017/round.png)、[竖屏](covers-20261017/portrait.png)，[机器可读摘要](covers-20261017/summary.json)。

本轮没有新增 Host、字体或 ABI 改动。实际购买授权差异另见 [目录与权限](catalog-and-access-20261017.zh-CN.md)，封面可见不代表正文一定获得授权。

## 真机阶段结果（同一 Host）

仅比较同一图书、同一章的 241,046 B HTML、901 B 正文。以下均为单次受控运行，不能替代重复样本分布。

| 项目 | 无封面旧版 | 封面 v6 | 去除相邻重复链接 v7 |
| --- | ---: | ---: | ---: |
| 解析开始到可读（含首次字形映射资源读取） | 5,082 ms | 3,812 ms | 3,400 ms |
| 加载期 Guest 输入排队最长值 | 2,065.519 ms | 519.553 ms | 375.658 ms |
| 本实例 Guest 线性内存真实峰值 | 589,824 B | 589,824 B | 589,824 B |
| AOT 映射 | 1,310,720 B | 1,376,256 B | 1,376,256 B |
| 稳定 SRAM 空闲 | 48,615 B | 48,615 B | 48,615 B |
| 稳定 PSRAM 空闲 | 4,742,140 B | 4,669,548 B | 4,668,196 B |
| 本次监测 SRAM 最小空闲 | 44,479 B | 44,427 B | 44,479 B |
| 本次监测 PSRAM 最小空闲 | 4,199,472 B | 4,129,148 B | 4,126,724 B |

功能增加跨过一个 64 KiB 代码映射边界，另有运行元数据开销；整个应用的稳定 PSRAM 和峰值占用并未保持旧版水平。封面离开界面即释放，不与正文解析阶段重叠，但不能用这一点掩盖代码映射增长。

加载期使用相同的 10 次界面外探测触摸；这些值衡量 Guest 收到事件的排队情况。Host 的 present/visible 延迟计数为零，因此**未测得手指到实际 LCD 像素的延迟**。12 次本地翻页的 Guest P95 为旧版 6 ms、v6 9 ms、v7 7 ms，样本数及页脚权限文字不同，不据此声称固定画面的渲染性能提升。

v7 的投影阶段 1,952 ms、模型阶段 325 ms、正文及首次字形映射资源读取 1,123 ms。后一项包含异步 I/O，并非纯正文处理 CPU 时间。继续优化重复 JSON 扫描，不能将当前 0.38 秒的最长输入排队称作流畅。

原始运行数值见 [v6](covers-20261017/device-v6.json) 与 [v7](covers-20261017/device-v7.json)。全局资源预算峰值是开机以来历史值，未冒充本次运行峰值。设备升级只替换本应用的签名包，其他安装文件及全部私有文件在升级前后逐项 SHA 核对一致；未更新 Host、字体或 Wi-Fi 设置。

## 一次扫描字段的进一步测量

v8 将顶层所需 JSON 字段一次提取为借用视图，既不保留对象树，也不增加字段缓存。原生 ASan/UBSan 与 78 项模拟器检查通过；相同数据上，每 8 次模型构建的分配次数由 7,680 减为 6,920，属于 Linux 原生计数，不能当作 S3 帧率。

S3 一次对照中模型阶段从 v7 的 325 ms 降为 285 ms，但本次整体解析为 3,967 ms，高于 v7 的 3,400 ms；准备/投影为 2,294 ms，正文及首次字形映射 I/O 为 1,387 ms。因此仅报告模型阶段观测收益，不宣称整体加载加速。Guest 线性峰值仍为 589,824 B，映射仍为 1,376,256 B。

此时已遍历过长目录，Host 字体缓存被进一步预热：稳定 PSRAM 空闲 4,446,496 B，本次最小空闲 3,903,852 B。这些是有效占用观测，但不能全归因于 v8 改动，也不能同前面表格当作相同缓存状态比较。详见 [v8 数值与限制](covers-20261017/device-v8.json)。


## 持久阅读提示

授权与内容获取错误改用独立提示页，使用原有状态文字和固定容量排版结果，不建立新页面缓存。点击“返回”或系统返回后回到原目录/书架/正文；加载失败不会替换已读内容。四种屏幕的 AOT/Wasm 检查均验证提示持续显示、返回后像素保留和限免可读。合成截图：[小屏](covers-20261017/access-compact.png)、[高 DPI](covers-20261017/access-hidpi.png)、[圆屏](covers-20261017/access-round.png)、[竖屏](covers-20261017/access-portrait.png)。

最终签名设备版 AOT 为 1,420,224 B，加入了提示页和单次字段扫描；保留 O3。未为缩减包体而降低优化等级。


## 最终留机版本

最终 v9（1,420,224 B AOT，O3）已安装在 pai-touch。相同 241,046 B HTML / 901 B 正文的一次受控测量为：准备/投影 1,958 ms、建模 286 ms、正文和首次字形资源读取 1,391 ms，共 3,636 ms。加载时同样 10 次界面外探测触摸的 Guest 最长排队为 296.606 ms；12 次本地翻页 Guest P95 为 8 ms、最长 8.880 ms，81 个事件样本。仍未测量实际 LCD 可见延迟，也不把单次样本当作稳定的性能保证。

本次相同单章实例的真实 Guest 线性峰值 589,824 B；另一个包含再次加载及未授权章节尝试的实例真实峰值 **655,360 B**，单独记录，不用较小的单章数值替代。代码映射 1,376,256 B，与 v6/v7/v8 相同。稳定 SRAM 空闲 48,615 B，PSRAM 空闲 4,446,408 B；本轮启动至章节可读的局部最小空闲为 SRAM 44,391 B、PSRAM 3,903,864 B。Host 字体缓存已被长目录预热，不能同旧版未遍历目录的整体堆值直接比较。

实际后续章返回内容错误时，持久提示页持续显示；点返回再系统返回，原 901 B 正文区域与加载前像素一致。三次重开均恢复现有账号，不需要重新扫码。未获得服务端拒绝的后续正文，没有绕过授权或把购买提示当作已实现全文。

升级前后，其他安装包和全部私有文件逐项 SHA 相同；正常阅读产生的位置保存是预期行为。两种临时安装顺序触发空间保护，均恢复原 v8 包；最终只在私有安装脚本中先传签名、再按原顺序传文件，避免最后一个小文件的保守预留阻拦。Host 的签名、正常 deploy 和 128 KiB 余量检查都保留；没有删除其他应用、刷新 Host 或写入私有状态来绕过安装检查。最终安装后报告可用空间 143,360 B。共享 CLI 未改动。

完整数值及限制见 [最终真机记录](covers-20261017/device-final.json)。依然存在约 0.30 秒的建模/输入长回合，后续可将目录构造拆成可中断任务；另一个待验证方向是将首次字形映射读取从 1 KiB 调到 SDK 允许的 4,064 B，减少异步往返，复用现有目标缓冲。这两项尚未实现或宣称收益。


## 首次字形读取优化（v10）

首次字形映射固定 41,984 B，原先每次读取 1,024 B，产生 41 次异步资源往返。现按 SDK 已允许的 4,064 B 上限直接写入原有目标向量，按文件大小计算为 11 次；不增加 Guest 缓冲、缓存或 Host 接口。修正了非购买类内容错误的诊断分类。AOT 只增 80 B，最终为 **1,420,304 B**，O3 不变；AOT/Wasm 各 43 项、共 86 项检查重新通过。

在同一 d878 Host 上，每个版本均正常软件重启，再读取相同 241,046 B 页面、901 B 正文并执行同一组探测/翻页。两次正文区域像素逐点相同。一次成对测量：

| 阶段 | v9 / 1 KiB | v10 / 4,064 B |
| --- | ---: | ---: |
| 准备及投影 | 1,922 ms | 1,944 ms |
| 模型构造 | 289 ms | 281 ms |
| 正文与首次字形资源读取 | 1,407 ms | 350 ms |
| 解析到可读合计 | 3,619 ms | 2,576 ms |
| 加载期 Guest 最长排队 | 335.701 ms | 328.339 ms |
| 当前实例 Guest 线性峰值 | 589,824 B | 589,824 B |
| AOT 映射 | 1,376,256 B | 1,376,256 B |
| WAMR 原生分配峰值 | 248,638 B | 248,638 B |
| 同次启动的资源外部峰值 | 125,930 B | 125,930 B |
| 同次启动的临时外部峰值 | 98,512 B | 98,512 B |

该对照总加载少 1,043 ms，约 28.8%，主要收益来自首次资源往返减少。它没有解决同步建模的约 0.3 秒长回合，亦不是实际 LCD 延迟测量。

Host 单次资源读取响应临时缓冲多至 3,040 B，但本次整段资源峰值未升。整堆测量还存在微小波动：启动前 SRAM/PSRAM 空闲分别差 8 B/856 B；从各自启动前空闲量到窗口最小空闲计算，v10 比 v9 多 24 B/52 B，归因未确定，**不宣称整个堆逐字节相同**。所有原始空闲数与限制保留在 [冷启动配对记录](covers-20261017/device-map-read.json)。两次正常重启也使之前被完整目录预热的字体缓存归零，旧的热缓存堆值不能混入这个对照。

最终核对当前包 7 文件、其他包 22 文件及其他应用私有数据、当前账号和偏好、字体均通过；Host 与设备设置未改，最终停止应用、清理监测并锁定文件系统。设备已交回浏览器验证任务。本轮没有把新的官方 Skill Key 写入设备或程序包。
