# 完整主栈、个人笔记与真机资源对照

2026-10-17，23:10。已采用配套 Host 和微信读书应用，pai-touch 已回到桌面并释放。这里只说明本轮已测功能；客户端仍有未实现项，见 README。

## 改了什么，为什么

| 修改 | 原因与收益 | 内存变化 | 验证 |
|---|---|---|---|
| WAMR 完整主栈策略 | ESP-IDF 启用 pthread 后，主线程只有声明栈的约五分之一；改为完整主栈、子线程创建时按需分配 | 无默认新缓存；静态 SRAM/PSRAM/IRAM 不增，固件少 160 B | 解释器/AOT 历史控制与修复共八项、pthread 配置 libpxa 四十项、真机八次流程通过 |
| 应用栈 64→16 KiB，协程池 8×2048→8×1536 B | 使用实际可用栈而非被隐式分割的栈；保留 O3/full LTO 和越界检查 | 默认 Guest 线性内存 128→64 KiB；同新 Host 的物理 PSRAM 稳定/窗口峰值约少 64 KiB | 同一曾失败 AOT、真实书架/封面/详情/划线/想法与重复启动通过；诊断观测不能当作所有输入的最坏栈证明 |
| 按需个人划线、想法 | 复用既有官方 Key，只读访问个人数据；精确游标、有界解析，切换取消旧请求 | 无默认全量笔记缓存；WAMR 加载子计数增加，下面单列 | 真实数据与六种布局、精确整数、坏数据、取消和失败保留原页检查通过 |
| JSON、笔记查找和图标编码 | 减少重复扫描、临时字符串与空 TEXT 命令 | 桌面查找临时分配 200,000→0；图标每个少 28 B | 五对桌面交替测量，结果校验相同；不是 S3 帧率证据 |

本轮没有修改图片解码、显示调度、输入法、网络协议或 SDK ABI；独立链接保留已验证生产 PNG/IME 对象，不夹带共享目录的其他候选。运行时修复的共同入口是 PXA System 的 `cmake/PxaWamrRuntime.cmake`。内部结构布局受开关影响，必须整体重编 WAMR target，不能只替换单个线程对象。

## 根因与适配要求

旧 Host 的 WAMR 开启 lib-pthread 和线程管理器，默认保留四个子线程栈。
`wasm_cluster_create` 把模块声明栈分成五份再向下对齐：16,384 B→3,264 B，65,536 B→13,104 B。
清零 `RuntimeInitArgs.max_thread_num` 不会取消默认保留。生产 ELF 的默认线程数已读取核对；桌面通常未开启相同线程配置，所以仅靠原来的模拟器栈水位无法发现差异。

统一启用上游 `WASM_ENABLE_HEAP_AUX_STACK_ALLOCATION=1` 后，主线程保留完整声明栈，子线程仅在创建时分配、结束后释放。没有通过禁用线程、扩大导入白名单或关闭边界检查解决问题。专门线程 fixture 验证创建前零次栈分配，三次创建/加入后分配和释放各三次。

**当前应用默认 16 KiB 栈，必须配套此修复后的 ESP32 Host。** ABI 版本和相同的工具版本字符串不能区分旧策略；当前没有部署端的能力协商保护，不能直接向旧 Host 发布这个包。旧应用在新 Host 上的流程已纳入对照，不需要整体迁移其他应用。其他设备及不同 WAMR 配置仍需验证。

## 固定实验与失败保留

设备为 pai-touch，字体保持原文件，真实同账号、每次同一页 20 条书架元数据，等待前两张封面完成后再稳定一秒。启动内存窗口不截图、不启用绘制 PERF；结束后分别采集四对“设置/返回”的输入与显示数据。冷启使用普通软件重启，重开完整停止后重新启动。

采样前登记顺序：旧 Host/旧 Guest 冷启及重开各一次，新 Host/旧 Guest 各一次，新 Host/新 Guest 各两次。共八次，不额外补样本寻找通过。先完整读回原 Host，独立构建的旧策略六个加载段与生产镜像逐字节匹配（appdesc 除外），新镜像刷写后完整读回核对。

第一次准备时在启动尚未接管输入的阶段调用 `INPUT CANCEL`，返回 `input_unavailable`，尚未刷候选也没有样本。保留该准备失败和恢复记录，等待正常启动后继续已登记流程。此前旧 Host 下的两次 16 KiB 溢出、被中止样本及 48 KiB 诊断详情超时仍是失败；新实验不把它们改成成功。新协议预先按实际物理区域与 Guest/映射判断，另列模块内部计数；不追认旧协议“每个内部子计数都不得增长”的门槛。

## 全部八次结果

单位：时间为秒，内存为 B；稳定值及峰值均为**整个物理堆的已用量**，不是仅应用增量。这里是固定流程的观测样本，不是置信区间或正式最坏上界。

| 顺序 | Host/Guest | 启动 | 书架与封面就绪 | SRAM 稳定 | SRAM 窗口峰值 | PSRAM 稳定 | PSRAM 窗口峰值 |
|---:|---|---|---:|---:|---:|---:|---:|
| 0 | 旧/旧 | 冷 | 8.479 | 272132 | 277948 | 2984296 | 3740508 |
| 1 | 旧/旧 | 重开 | 5.850 | 272096 | 276232 | 2993508 | 3778348 |
| 2 | 新/旧 | 冷 | 6.530 | 272248 | 276808 | 2979928 | 3737356 |
| 3 | 新/旧 | 重开 | 5.229 | 272248 | 276348 | 2989168 | 3774052 |
| 4 | 新/新 | 冷 | 6.026 | 272132 | 276820 | 2914584 | 3671624 |
| 5 | 新/新 | 重开 | 5.383 | 272096 | 276232 | 2924084 | 3708912 |
| 6 | 新/新 | 冷 | 5.688 | 272096 | 276820 | 2914928 | 3671668 |
| 7 | 新/新 | 重开 | 5.189 | 272096 | 276232 | 2923848 | 3708784 |

八次均完成书架和封面。第 0 次发生一次正常原生会话续期，第 1、4 次没有续期；网络、TLS/文件系统首次初始化和服务响应也不是固定 CPU 工作量，因此不能把 8.479→6.026 秒称为确定的启动 CPU 加速。

采用组合相对原生产组合，按冷启/重开分别取新样本最差值：

| 指标 | 冷启差值 | 重开差值 |
|---|---:|---:|
| SRAM 稳定 | 0 | 0 |
| SRAM 本次峰值 | −1128 | 0 |
| PSRAM 稳定 | −69368 | −69424 |
| PSRAM 本次峰值 | −68840 | −69436 |

更接近单独 Guest 改动的对照是在**同一个新 Host** 上比较旧/新 Guest：PSRAM 稳定值冷启少 65,000 B、重开少 65,084 B；窗口峰值分别少 65,688 B、65,140 B。两个对照相差约 4 KiB，包含启动基线波动，不能全算成应用优化收益。Host 单独运行旧 Guest 时有 SRAM 稳定值 +116/+152 B 的观测，也完整保留，不声称每个组合每项都下降。

窗口峰值取 `MEMORY START/STOP` 的 `heap-local` 本次最小空闲值；普通 `MEMORY` 的启动以来历史最小空闲另存，不参与本次峰值。第 0 次 SRAM 稳定增量相对空闲为 8,552 B，第 1 次仅为 1,192 B；新组合冷启 8,516–8,552 B、重开 1,192–1,196 B。这些包含首次服务初始化差异，不能把首次初始化费用算成每次启动都新增的应用内存。

## 流畅性、画面与功能

四对设置/返回共八次串口注入点击，Host 采样到 Guest 处理的 P95 仍为 7–8 ms。旧组合最大 10.552 ms，新组合最差 13.211 ms；加权平均约 3.458→3.443 ms，差异太小，不认为已证明触摸加速。该计数不包含手指触摸采样前和最终可见显示，原生 UI 的 present/visible 延迟样本为零，**端到端可见延迟尚未测得**。

显示窗口约 3.32–3.41 秒，完成帧数依次 12、14、13、15、15、12、15、13。静态界面仅在点击或异步图片完成时更新，这组由操作速率决定的帧数不能称作渲染吞吐 FPS。

随后真实只读验证简介、个人划线、个人想法、正文局部分页、返回简介和书架。真实画面已人工检查：页签、正文、分页按钮对齐，没有崩溃或栈溢出；完整 11 张截图保存在私有证据中，包含账号书目/笔记，不公开。合成六屏截图见 [笔记记录](notes-20261017.zh-CN.md)。没有新建或修改笔记、没有请求此前受限的后续付费章节，也没有重新扫码。

配套最终安装烟测 5.630 秒完成同一书架和两张封面；它只证明安装结果可启动，不进入固定八次性能数据。根源码重新构建的 AOT 与实测冻结包 SHA256 一致。

## 复现和交接

1. 使用固定版本源码、WASI SDK 和 wamrc，以 C++26、O3、full LTO 构建；保持模块定义、字体与画面设置一致。专门回归命令见 PXA System 的 `libpxa/adapters/tests/wamr_aux_stack/README.md`，分别运行新策略和历史控制。
2. 普通 AOT/Wasm 七套集成测试共 172 项，AOT 栈诊断 86 项，原生 ASan/UBSan 十项；诊断包不混入普通包的资源/性能数据。原生辅助栈八项和 pthread libpxa 四十项另计。
3. 真机先备份并读取精确 Host，而非只看版本文字；登记上述八次顺序、固定就绪条件、内存窗口与失败停止规则。保存原包、私有数据和字体摘要。真实账号测试需已有合法会话，不能用合成凭据替代。
4. 如测试失败先保留原始串口、异常前画面和错误，再恢复包与 Host；原生同账号正常续期需验证并保留，不为恢复哈希而回滚有效登录。安装守卫保留 128 KiB 空间余量，空间口径异常只做普通重启，不清用户数据。
