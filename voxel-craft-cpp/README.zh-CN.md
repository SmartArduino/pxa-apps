# Voxel Craft C++

使用独立 PXA C++26 SDK 的体素沙盒。纹理和调色板在初始化时逐个加载、绑定并释放临时句柄，Renderer 持有绑定引用；稳定帧仅提交复用的 DrawList。

启动进入标题页，可新游戏、加载三个存档槽或打开设置。右上角按钮打开暂停菜单，
提供继续、保存、设置及返回标题；存在未保存的改动时确认放弃，覆盖存档也需要确认。
菜单、背包及存档操作暂停物理和挖掘，并清除全部按住状态。
标题、游戏和背包都隐藏系统状态栏，窗口就绪及恢复前台时重新申请；保留系统导航手势。
Host 的调试 FPS 浮层独立于状态栏，由设备开发设置控制。

游戏左半屏从触摸起点拖动移动，不显示遮挡视野的摇杆；右半屏拖动调整视角。
右侧三个按钮依次为攻击/操作、放置、跳跃。短按工作台打开操作页，长按
0.30 秒进入持续挖掘。不同材料有不同徒手耗时，例如树叶 0.45 秒、泥土 0.65 秒、
原木/木板/工作台 1.60 秒、石头 3.20 秒；切换目标、松手、菜单或后台会复位进度。
准星下方显示进度，非透明方块还显示受深度遮挡的裂纹。也可长按拆除工作台；取消触摸不触发交互。
当前世界没有动物实体，尚未实现动物攻击和保险箱。
飞行默认关闭，设置开启后额外显示上、下按钮；地面跳跃只在落地时触发。
反转上下默认关闭，视角灵敏度默认中；自动跳跃默认开启，可在设置关闭。
自动跳跃只在落地且行走受阻时检查单格障碍和上方空间，高墙、低天花板和空中均不触发。
底部九个快捷槽最右侧为背包。新游戏背包为空，挖掉方块后收集一件，放置成功消耗一件；
背包满时保留目标方块，放置失败不扣数量。背包有 27 个储物格和 9 个快捷格，普通材料每格最多 64 件，工具不堆叠。
点击来源格再点击目标格移动、合并或交换；点已选格取消选择。

背包上方是随身 2×2 合成格，短按世界中的工作台打开 3×3 合成格。点击物品格，
再点击合成格放入一件材料；可从同一堆重复填格，选择另一堆可换材料。未选物品时
点击合成格撤回材料。点产物格完成一次合成；产物放不下时不扣材料，关闭页面不丢材料。
配方包括原木 → 四块木板、2×2 木板 → 工作台、竖排两块木板 → 四根木棍；
3×3 工作台可用木板或石头/圆石配两根木棍合成镐、斧、铲。镐为顶排三块材料加中列两根木棍，
斧为顶排两块材料加第二排一块材料和两根木棍（接受镜像），铲为竖排一块材料和两根木棍。
配方允许在格中平移。工具匹配材料时，木工具加速 2 倍、石工具加速 4 倍；
镐适合石质方块，斧适合木质方块，铲适合土、沙、雪、砾石。用错工具按徒手速度。
成功挖掘扣一次耐久，木工具 60 次、石工具 132 次；取消或背包满不扣，耗尽后消失。
快捷栏和背包显示耐久条，切换工具重置挖掘进度。尚无铁/钻石工具、熔炉、容器和装备栏。

挖掘、破坏、放置和合成使用树叶/植物、泥土、砂砾、雪、木、石、玻璃、羊毛八类短音效。
Guest 按需生成带起音和衰减的接触噪声与共振，向 Host 的既有混音器提交一个 PCM 包；
每次最多 320 个 16 kHz 单声道采样，使用 640 B 栈暂存，不加载 PCM 资源或建立音频缓存。
音频播放是可选权限，拒绝或撤销后游戏仍可运行；授权先于世界 Surface 和深度缓冲的分配。
多指按 pointer_id 独立管理，后台取消持续动作。

控件和命中范围共用按需计算的布局，读取逻辑分辨率、DPI、字体比例、安全边距及
四角半径。文字使用 10/14/18 像素的 Sarasa Gothic SC（更纱黑体 SC，中国大陆字形）灰度覆盖图集，启动时只加载
适合当前屏幕的一档，通过固定八字批处理和 Host 的逐 texel alpha 混合抗锯齿。
不链接运行时字体引擎，不建立动态字形缓存；字体许可证见 resources/fonts/。
菜单只在状态改变时重新编码及提交，不在标题页持续投影或光栅化世界。

每槽保存全部 98304 个方块、种子、相机、垂直速度、飞行状态及全部 36 个物品格的类型、数量和工具耐久，设置独立持久化。
两个文件交替写入，读回校验后才原子更新有效版本索引；写入失败保留旧版本。
加载和校验借用暂停后的区块缓存作为暂存，校验失败不改变当前世界，完成后重建区块。
不额外分配 96 KiB 的世界副本。v3 存档独立校验背包和耐久，兼容 v1 世界/相机与 v2 有限背包；
旧版无限材料快捷栏迁移为每个旧槽一件，旧水槽清空（目前没有水桶）。三个槽各保留两个版本最多占磁盘 590952 B；
pai-touch 私有文件逻辑限额须为 1 MiB，此限额不预分配内存或磁盘空间。

渲染从眼睛位置投影，保持 Q4 坐标和 Q8 深度。近面与视锥裁剪保留 UV；四边形和裁剪三角形共享深度，叶片透明 texel 不写遮挡深度。所有 45 个方块材质与 HUD 使用正确资源；绿色仙人掌没有树冠。

默认保留完整透视纹理。显式启用 `VOXEL_CHEAP_PATHS=1` 后，面按投影大小和深度变化选择绘制路径：不透明面宽或高小于 4 像素时用
对应材质/光照的平均 RGB565 色；纹理误差不超过半个 texel 时用仿射 UV；
其余保留透视 UV。树叶等 cutout 始终保留纹理和透明孔洞。四边形使用
扫描线深度路径，裁剪后的多边形用有界退化四边形扇形，所有路径共用深度缓冲。
目前 pai-touch 树林斜视的近似路径没有实测收益，默认关闭，不能宣称比完整纹理更快。
颜色表由实际资源生成，`tools/generate_lod_colors.py --check` 检查同步。
完整画面和 HUD 请求直接扫描输出；输入 Canvas 没有可见 UI 内容。
Host 遇到系统覆盖层时仍保留合成回退，不绕过遮挡或 UI 检查。

区块可见性与精确裁剪共用视空间远面，避免径向距离误剔除边缘的树冠和树干。
地图先完成地形再生成植被，草丛不能替换树干底部。保留 8 格区块，
每块固定 192 个 quad；32 个回归种子的最大值为 173，World 从 688896 降至
393984 字节。本版将仅在 Guest 内部使用的 MeshQuad 缓存记录从 8 B
压到 4 B（保留所有字段范围及 192 条容量），World 进一步降至 246528 B；
默认八格区块的缓存节省 147456 B。复杂编辑超容量时分页复用同一缓存，避免漏面。视距根据实际
帧间隔与 Host 光栅化成本调整，且裁剪远面同步使用该视距，低质量仍保留深度。
模拟步长保持 16 ms，最大更新次数显式设为 8，使约 10 FPS 时移动和重力
仍按实际时间推进；后台恢复重置模拟时钟。

构建：

```sh
bash tools/app.sh build voxel-craft-cpp --target all
bash local/pxa-apps/voxel-craft-cpp/tests/test.sh
```

主机测试检查多指输入、后台复位、32 个地图种子的树干/树冠、所有区块的可见面、超容量分页与编辑重建，
以及绘制路径边界、相同可见面数、树叶 cutout、DrawList 容量和零帧内堆分配。
`SANITIZE=1 bash local/pxa-apps/voxel-craft-cpp/tests/test.sh` 加跑 ASan/UBSan。
`PXA_APP_DEFINES=VOXEL_PROFILE=1` 可启用 Guest 绘图计时；默认不增加帧内 WASI 计时调用。

可重复的绘制对照用 `PXA_APP_DEFINES=VOXEL_BENCH_DISTANCE=24` 固定出生相机、
地图种子、视距和光照；`VOXEL_CHEAP_PATHS=0` 可关闭三档绘制。测量包关闭运动与
自动视距调整，正式包不定义 `VOXEL_BENCH_DISTANCE`，保留正常触摸和运动。

严格 C/C++ 对照使用 `VOXEL_BENCH_SCENE=1`（正视）或 `2`（斜视），C 版另加
`VOXEL_AUTOPLAY=1`。公共 fixture 在 `../common/voxel_benchmark.h`，固定相同的
98304 个方块、相机、FOV、24 格远面、中性光照和完整纹理，关闭 HUD/近似绘制/
自适应与模拟。编译定义用逗号分隔。`tests/benchmark_test.cpp` 对照全部方块和
缓存容量；C 原版 Z 面 UV 交换已修复后才允许参与画质一致的对照。
在固定场景另加 `VOXEL_CHEAP_PATHS=1,VOXEL_BENCH_CHEAP=1` 可对照绘制近似的画面与收益；
该结果应独立标注，不能与完整纹理结果混作语言性能比较。
固定场景另加 `VOXEL_BENCH_HUD=1` 可只打开正常游戏 HUD，对照按钮、物品栏和
准星的实际显示成本；地图、相机、画质、模拟和自动视距仍固定。

`VOXEL_PROFILE=1` 将几何准备与编码放在同一命令缓冲的两个阶段，只在边界
计时，120 帧后输出均值。它仍有观察者成本，最终显示 FPS 必须使用不含该宏
的包；Guest 提交墙钟时间包含 Host 抢占，不等于纯编码 CPU 时间。

2026-10-08 pai-touch（当时为 `/dev/ttyACM2`） 三轮显示帧率约 7.42 FPS，Host 光栅化约 59.5 ms；会随场景、视距和操作变化。数据与限制见 workspace `local/host-interface-20261008/REPORT.zh-CN.md`，不能当作与 C 版等价画面的语言性能比较。

2026-10-09 等画质对照（296×240、固定相机和 24 格视空间远面、完整透视纹理、相同材质）：
S1 的 LCD 完成 FPS 为旧 C++ 10.439 → 本版 13.901，C 为 12.587；
S2 为旧 C++ 8.914 → 本版 12.107，C 为 12.526。各三次独立采样，
性能提高约 33%/36%，S2 比 C 低约 3.3%。生产 Guest 线性内存 13→9 页，
World 减少 294912 B，既有帧/深度/命令缓冲不增加。完整计量、真实峰值、
截图、诊断的观察者影响及限制见本仓库的 [3D 优化验收报告](docs/performance/pxa-3d-20261009.zh-CN.md)；
原始报告和可复现包在 `local/pxa-3d-goal-20261009/`。

界面、输入、存档、投影、网格构建及 SDK 实现统一使用 `-O3`，不为减小代码体积
降低编译优化级别。Host 对标准、动态载入 AOT 安全地提前释放重复的源文件；
代码映射、稳定 RAM 与本次启动/保存峰值分别记录，不把文件大小等同于运行占用。
此回收需要 Host 的 WAMR 初始数据所有权修复，不能仅把 loader 标志打开。
0.10.0 的交互、大陆黑体、DPI、存档、峰值及固定场景验证见
[O3、HUD 与交互验收报告](docs/performance/voxel-craft-cpp-ui-20261009.zh-CN.md)。
所有报告和测量汇总见 [性能与验收记录索引](docs/performance/README.zh-CN.md)。

HUD 在世界之后直接编码到同一 DrawList、画进同一游戏 Surface，并一起提交。
标题、暂停、设置等页面也复用这个 Surface；没有额外全屏 UI 图层或合成缓冲。
Canvas 是 input-only，只负责触摸。按钮、图标及字体本身仍有编码和光栅化开销，
系统浮层出现时 Host 仍允许回退到合成路径。
HUD 和背包图标采用现有的仿射 2D 扫描线，按光照行 0 取色，保留透明 texel，
不读写世界深度。同一 O3 树林 fixture 的三轮 LCD FPS 从原 HUD 的 11.001
提高到 11.529，Host 光栅化从 43.620 降到 39.427 ms；关闭 HUD 为 11.975 FPS。
两个定点插值器在精确 texel 边界有少量相邻样本舍入差异，截图与原生深度哨兵
已检查。没有改动世界的叶孔、深度、画质或视距，也没有增加缓存或缓冲。

绘制前查询累计完成与废弃数，仅在没有尚未完成的绘制列表时构造下一帧。
这保留 LCD 传输与下一帧构造的重叠，避免 Guest 过量提交造成外部内存竞争、
重复光栅化与废弃帧；暂停菜单可直接提交以响应操作。固定步长模拟和输入继续，
HUD FPS 与自适应视距包含跳过的 tick 时间。SDK 的可选 `game_pacing.hpp` 提供
无状态的计数判断；查询失败保留原有绘制行为。真机验收记录实际 LCD 完成 FPS。
