# ESP-Mosaico DPI 与菜单布局修复

## 原因与修改

ESP-Mosaico 板级配置和模拟器 profile 都是 480×480、305 DPI、四边
12 px 安全边距、58 px 圆角。旧真机 Host 在构造 UI adapter 时把
`density_q16` 固定为 65536；板级 profile 发布得更晚，启动 Guest 前又没有
刷新这个值。应用得到的是 1 倍密度，选择 10 px 字库。模拟器此前直接提供
正确密度，因此只跑模拟器不能发现这条真机传递路径的问题。

Host 现在在 Guest 启动前和显示 profile 更新时，从 LVGL display 刷新真实
密度、尺寸和几何信息，并同步到 UI service、adapter 和启动配置。
启动时直接预置 UI service 的密度；组件在 STARTING 阶段不能接收环境
事件，原生回归专门验证了这个边界。运行中的 profile 改变才发送更新事件。
profile observer 同步 LVGL DPI，沿用已有的更新队列，没有新增全局
profile 缓存、帧缓冲或 UI 图层。C++ 版标题页在方屏和竖屏中居中；紧凑
横屏保留原来的排列位置。字体沿用已有的 Sarasa Gothic SC 大陆黑体灰度
图集，生产包仍包含 10/14/18 三档，只加载一档；编译仍使用 O3。

Canvas 触摸事件的坐标是 dp，原生 Surface 的绘制坐标是像素。
C++ 游戏继续使用 SDK 的 `canvas_to_surface_coordinate`。
旧 C 版 voxel-craft、Pixel Dungeon 补上同样的坐标换算，兼容辅助代码放在
应用公共目录 `common/pxa_canvas_pixels.h`，不新增 C SDK 接口。
后续功能与 SDK 维护以 C++ 为主。

同时修复共享 LVGL adapter 的另一处密度错误：`vw`/`vh` 原先把已经是
像素的视口尺寸再乘一次 DPI。现在直接用像素视口计算比例，避免高 DPI
控件越界；没有增加缓存或分配。

## 内存与性能边界

此次 Host 传递和标题布局修复没有新增常驻对象或堆分配。C 兼容应用各有
一个 4 B 的密度值。帧缓冲、深度缓冲和命令队列配置均沿用原值，静态
菜单继续只在变化时重绘。

字库像素从 12100 B 的 10 px 图集切换到 39204 B 的 18 px 图集，增加
27104 B（26.47 KiB）。这是修正字号的实际成本，不能报告为总内存不增长。
目前没有新增或同时加载第二套字库。真机稳定内存、代码映射及本轮峰值的
前后核对尚未完成，不以字库尺寸推断总堆变化。

本次不构造 C/C++ 语言 FPS 对比；标题、菜单和 HUD 变大也不是相同工作
负载。3D 世界几何、材质、视距和深度遮挡实现没有在这次布局修改中改动。

## 验证与当前状态

- 原生 ASan/UBSan 游戏回归通过：输入、存档、背包、合成、工具、音效、
  世界编辑、区块网格、渲染、C/C++ 固定场景一致性。
- ESP Host ASan/UBSan 回归通过。
- 真实 LVGL adapter 原生与 ASan/UBSan 回归通过；50vw/50vh 在
  160、240、305、480 DPI 下均为 320×240 视口的 160×120 px，释放后
  allocator 当前占用归零。
- 布局测试覆盖 296×240、480×480、412×412、240×296、800×480、128×128，
  验证安全边距、圆角、按钮位置、非整数 DPI 及 C/C++ 坐标换算一致性。
- 480×480/305 DPI 模拟器完成标题→设置→返回→加载列表→返回→新游戏→
  游戏菜单→继续→背包→返回→游戏菜单的点击和截图检查。
  最终复测使用无音频权限的隔离包，仅免去首次授权弹窗；生产音频能力
  不变。新游戏步骤检查真实 `VOXEL-STATE` 日志，不以点击推断已经进游戏。
- 296×240/160 DPI 模拟器通过相同流程，首个按钮仍在 148,95，使用 10 px
  字库；小屏布局没有被方屏标题居中规则改变。
- ESP32-S3、ESP32-S31 的 C++ 0.12.1 AOT 包及 ESP-Mosaico 应用固件构建
  通过；Guest 初始线性内存仍是 6 页（393216 B）。
- 原真机已有 7 个应用。操作前备份了可访问的 22 个私有数据/权限文件，
  共 69855 B，操作后 SHA-256 均一致；未修改存档、设备偏好或应用安装状态。

**真机部署待完成。** 当前 ESP-Mosaico TinyUSB CDC 不支持自动进入下载
模式；USB 和外接 UART 的自动连接都没有进入 ROM。需要手动按住 BOOT
重新上电，然后核对 S31 MAC `1c:29:04:d0:ad:04`，备份当前应用分区并仅
执行 `app-flash`。还需检查真机截图、实际触摸、重复启动、前后台及运行
峰值，再安装正式包和必要兼容更新。当前没有声称已在真机修复。

## 复现

对应代码提交：PXA Host `c5bdd6a`，共享 LVGL adapter `8b24e02`，
C++ 维护方向 `d600bc2`，旧应用兼容 `0d4cba6`，C++ 菜单 `b25a4bf`。

在 pxa-projects 工作目录运行：

```sh
SANITIZE=1 bash local/pxa-apps/voxel-craft-cpp/tests/test.sh
PXA_TEST_SANITIZERS=1 bash firmware/components/pxa/tests/test_host.sh
bash tools/simulator.sh product build --profile pai-touch
cmake -S deps/pxa-system/libpxa -B build/dpi-lvgl \
  -DPXA_BUILD_TESTS=ON -DPXA_BUILD_ADAPTERS=ON \
  -DPXA_LVGL_SOURCE_DIR="$PWD/build/simulator/pai-touch/_deps/lvgl_source-src" \
  -DCMAKE_C_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer -g'
cmake --build build/dpi-lvgl --target pxa_lvgl_ui_test --parallel 4
ASAN_OPTIONS=detect_leaks=1 build/dpi-lvgl/pxa_lvgl_ui_test
python3 local/pxa-apps/voxel-craft-cpp/tests/build_playtest.py \
  --target esp32s31 --identity pxa-voxel-craft-cpp-ui5 --no-audio --output local/dpi-fixture
```

安装隔离测试包并解锁设备后，运行：

```sh
python3 local/pxa-apps/voxel-craft-cpp/tests/device_dpi.py \
  --port /dev/ttyACM1 --output local/dpi-device \
  --width 480 --height 480 --dpi 305 --safe 12
```

该测试只允许独立的 `pxa-voxel-craft-cpp-ui*` 身份；不覆盖生产存档。
模拟器可使用独立 PXADB service 的 Unix socket，并通过 `--log` 指定
外部模拟器日志。原始日志、测量状态及构建哈希见本报告附件。
