# 2026-10-13 原版跳跃、玩法与特效

本轮以用户指定的 [yaoshanliang/weapp-jump](https://github.com/yaoshanliang/weapp-jump/tree/8102017c5357ae18a0df2eece2e09771e8648b66) 为参照。独立检出位于 workspace 的 `local/references/weapp-jump-20261013`；检查时远程 HEAD 为 `8102017c5357ae18a0df2eece2e09771e8648b66`。此前 C 移植版的时间量化行为作为旧版基线保留。

## 参数与拖沓原因

| 项目 | 原版 game.js | 本版（世界单位为原版的 1/10） |
|---|---|---|
| 重力 | 720 | 72 |
| 垂直初速度 | min(135 + 15 × 蓄力秒数, 180) | min(13.5 + 1.5 × 蓄力秒数, 18) |
| 水平速度 | min(70 × 蓄力秒数, 150) | min(7 × 蓄力秒数, 15) |
| 翻转 | 140 ms 半周 + 180 ms 半周 | 同样为 320 ms，不再随飞行时间伸缩或回绕 |
| 快速跳奖励 | 松手距上次成功不足 800 ms | 在松手时捕获 |
| 特殊平台停留 | 2 s | 2 s，一次发奖 |

原版参数位于 `game.js:10436`，实际时间蓄力位于 `16597`，解析式飞行积分位于 `12350`，翻转时长位于 `12415`，落点解算位于 `16464`，短跳返回位于 `16256`，评分乘数位于 `14353`。

旧版每个时钟回调四舍五入成 20 ms，最多推进 40 ms。在低帧率下，墙上时间过去 100 ms，游戏只推进 40 ms。与此同时，飞行使用半隐式 Euler，预测落点使用另一套解析公式，翻转角度在一周后回绕，最后又把角色移动到预测终点。这些行为会造成速度随回调频率变化、临近落地再次翻转和落点瞬移。

现在按单调时间推进；DOWN/UP 时间戳决定蓄力，MOVE 不提交额外帧。解析式轨迹与落点使用相同的压缩后起始高度，落地跨越时消费剩余时间。重复/倒序时钟不推进物理，后台时间通过重置时钟排除，迟到的 UP 不把队列延迟计入蓄力。音频时间也保持单调。原版 `>100 ms` 时丢弃更新的行为未沿用，以免低帧率再次慢动作。

固定种子、首跳相同 700 ms 蓄力的原生事件重放：

| 时钟间隔 | 旧版实际飞行时间 | 新版实际飞行时间 |
|---|---:|---:|
| 20 ms | 380 ms | 400 ms |
| 32 ms | 320 ms | 416 ms |
| 80 ms | 800 ms | 400 ms |
| 100 ms | 1000 ms | 400 ms |

新版该跳的解析落地时间为 395.514 ms；表中时间是首次观察到落地状态的回调时刻，最多多一个回调间隔。重力、起跳速度和目标平台距离保持相同。20/32 ms 的旧版偏快也被纠正；没有一律缩短所有跳跃。

`tools/reference/extract_upstream.cjs` 直接执行上游 `_jump` 方法生成 [28 个黄金位置](upstream-motion.json)。原生测试验证 12 种回调间隔的蓄力、轨迹和落地；本版落点不复制原版每步 `toFixed(2)` 的舍入误差。

## 补齐的玩法与反馈

- 短跳落回当前平台可以继续，分数和连击保持；擦过平台边缘仍会翻倒。
- 快速跳在松手时判定，普通快速跳也计分；快速中心跳的乘数按原版接着递增，例如 +4、+6，而非退回 +4。最高单跳乘数仍为 32。
- 蓄力白/绿粒子、落地散射、飞行拖尾、落地形变与最多四层相隔 200 ms 的波纹。波纹固定在各自落地点。
- 音乐盒唱片旋转与音符、商店开关门、井盖水花与涟漪、魔方顶面分组转动。离开特殊平台停止对应持续音效；只有音乐盒续播旋律。
- 高连击音阶封顶，修复每八次回到最低音的问题；修正直落/翻倒音效选择。游戏事件先产生音效请求，再提交音频，消除额外等待一个游戏时钟的情况。
- 取消触摸或切后台恢复角色、平台高度；第二根手指无法终止第一根手指的蓄力。

[跳跃/蓄力截图](upstream-motion/flight-comparison.png)、[特殊平台截图](upstream-motion/special-blocks.png)、[屏幕矩阵](upstream-motion/display-matrix.png)。

视觉取舍：粒子与音符用程序生成的少量四边形，拖尾重建最近 100 ms 的轨迹；特殊平台沿用现有几何外观。波纹复用已有白色纹理的固定混合，并逐渐减小线宽，没有新增连续 alpha 渐变纹理。它们保留反馈的节奏和含义，未逐像素复刻 WebGL。尚未移植上游全部品牌贴图与装饰平台、微信分享/好友排行、观战与网络对战。

仅保留实际使用的三个平台槽位，腾出的状态空间容纳解析轨迹和特效参数。粒子、拖尾无持久容器，热路径不新增动态分配。144 个最坏特效组合通过真实 Host 校验与光栅器，最终最大命令 12656 / 16384 B。

新增逻辑和特效会增加 AOT 代码，整体内存并非零增长。最终 ESP32-S31 AOT 文件增加 25600 B；READY 的 PSRAM 剩余从旧版 10513540 B 变为最终冷启动复测的 10489296 B，稳定占用增加 24244 B。最终包另一运行的增加值为 16044 B。同期 Host 资源计数相同，推断部分差值来自代码装载，但不能将整机波动全部归因于代码。

本次开机累计 PSRAM 最低剩余：旧版 READY 为 8152308 B，新版冷启动 READY 为 8104316 B（整机峰值增加 47992 B）；操作后新版为 8080948 B。新版操作多触发了中心连击，音频资产 external 达到 210064 B，旧版为 182544 B；操作后缓存属于不同播放负载。另一次更新后的运行曾记录累计最低剩余 6722416 B，冷启动复测未复现；该值涵盖开机以来所有操作，尚不能归因于游戏。它与首次初始化的资源峰值分开保留，见 [各次运行的完整内存记录](upstream-motion/device-memory.json)。代码体积与最终包哈希见 [包哈希](upstream-motion/package-hashes.json)。

## 验证与复现

最终代码为 C++26、O3；构建通过 x86_64、ESP32-S3、ESP32-S31 AOT，生产包不启用计时日志。

- [9 项当前检查和 1 项可选 C 渲染参照检查](upstream-motion/native-tests.txt)通过，包括核心玩法、原版黄金位置、实际输入处理、多指、取消/前后台、音效请求、过期时钟、共享缓冲、特效预算、SDK 和回压。
- [ASan/UBSan 的 4 项相关检查](upstream-motion/sanitized-tests.txt)通过。
- [六种实际 SDK 模拟器屏幕配置](upstream-motion/display-matrix.json)通过：296×240/160 DPI 圆角、480×480/305 DPI 圆角、176×176 圆屏、320×480/240 DPI、800×480、480×800/320 DPI。
- 独立计时诊断包已验证真实 AOT 起跳与落地；一条记录的预测飞行 396626 µs，落地回调距 UP 为 401151 µs。控制命令所写的 700 ms 手势并不等于真实 DOWN/UP 间隔，该次实际蓄力为 737094 µs；测试以事件时间戳为准。桌面调度也出现过长帧，因此诊断日志不当作显示延迟上界或真机 FPS 证据。
- 旧 `pixel_reference_equivalence` 的 C/新 SDK 逐像素比较在改动前、改动后都失败，失败位置相同；本轮未修改 Pixel Dungeon。其核心/当前光栅检查通过。

从 workspace 根目录运行：

```sh
PXA_CPP_GAME_TEST_BUILD="$PWD/local/jump-reference-native" \
  bash local/pxa-apps/common/cpp/tests/run.sh \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++

node local/pxa-apps/jump-jump-3d/tools/reference/extract_upstream.cjs \
  local/references/weapp-jump-20261013/game.js > /tmp/upstream-motion.json

bash tools/app.sh build jump-jump-3d --target simulator,esp32s3,esp32s31 \
  --aot-only --source-root local/pxa-apps --output local/jump-release

# 已安装测试包时，在 Korvo 上重放；会停止并重新启动该游戏。
python3 local/pxa-apps/jump-jump-3d/tools/reference/device_measure.py \
  local/jump-device-repeat
```

默认原生检查不启用旧 C 逐像素比较。真实手指的主观手感仍需使用者体验；本轮自动化确认了计时、轨迹、计分、画面和实际显示吞吐。
